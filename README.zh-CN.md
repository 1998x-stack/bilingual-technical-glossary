## 项目定位

本仓库不只是“英文词—中文词”的平面表格，而是可持续维护的**技术术语知识基础设施**：同一份结构化数据可以发布为专题 Markdown、供程序使用的 JSON/CSV、可打印的 PDF，以及可视化检索网站。

## GitHub Pages 展示

主题为专业技术知识库、研究数据门户的 UI，支持：

- **中英混合全文搜索：**英文、中文、缩写、专题和解释；
- **主题选择：**26 个学科、398 个专题；
- **覆盖可视化：**按学科展示真实术语数量及学习路线；
- **资料下载：**每个主题的 PDF、Markdown，以及搜索结果 CSV；
- **交互体验：**移动端布局、明暗主题、键盘快捷键、分享检索链接。

静态资源位于 `docs/`，无需后端、数据库或付费 API。当前 GitHub Pages 发布工作流已有成功执行记录；后续修改 `docs/**` 将自动触发部署。首次迁移到新仓库或 Pages 被关闭时，管理员需在 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**，再运行已有 `.github/workflows/pages.yml`。详见 [部署说明](docs/PAGES_SETUP.md)。

微积分新增 361 条术语（16 个专题），并保留 `notation` 字段；源 Markdown 存放在 [`sources/calculus.md`](sources/calculus.md)。

## 更新与质量控制

修改术语前，请先查看 [贡献指南中的学科权威源对应表](CONTRIBUTING.md) 及 [维护者架构手册](docs/MAINTAINERS_GUIDE.md)。不同学科可能以 TSV、HTML、原始 Markdown 或 JSON 作为编辑入口；**不能默认所有词条都直接改 `data/terms.json`**。

普通变更先执行不会生成 PDF 的只读检查：

```bash
python3 scripts/verify.py
python3 scripts/build_wiki_index.py --check
python3 scripts/verify_wiki.py
python3 scripts/verify_docs.py
python3 scripts/sync_agent_skills.py --check
python3 -m unittest discover -s tests -v
```

**注意：**总构建命令 `python3 scripts/build.py` 会重建多个学科的输出并调用 PDF 渲染器，仅在确认权威源与预期文件差异后运行。多本 PDF 属于独立编排原件，不应因只修改 JSON 就假装完成 PDF 内容更新。PDF 变更必须人工核查中文字体、分页和可检索性。

本项目用于研究、学习和工程阅读；不是任何标准组织发布的官方术语规范。仓库尚未选择开放许可，直到明确发布 License 之前请保留作者权利。

## 统一术语详情页

目前 AI Infrastructure 已发布 **80 篇完整概念解析**（142 个术语中），未扩展的 62 个术语仍提供简明定义。专业同行审稿独立记录在 [审稿台账](wiki/reviews/README.md)，不得将自动验证冒充专家签核。

读者从原有的 [术语检索 Explorer](https://1998x-stack.github.io/bilingual-technical-glossary/#explorer) 进入，无须单独访问 Wiki 栏目。例如选择 [强化学习](https://1998x-stack.github.io/bilingual-technical-glossary/?category=reinforcement-learning#explorer)，点击任一英文或中文名即可打开该术语详情。已有专业解析的词条直接展示完整 Wiki 内容；其他词条仅展示经过整理的简明定义，不虚构尚未编写的长文。每 20 条一批的排期仅用于内部生产，不出现在公开阅读界面。

## P0 / P1 / P2 工程质量治理

- **P0 发布安全：**专题 PDF 和索引同步 Action 不再直接 `git push main`；只上传待人工审查的 PDF/补丁 Artifact。正式合并必须通过 PR，Pages 发布前执行数据和文档门禁。
- **P1 专业审稿：**80 篇已发布 AI Infra 文章已建立 [审稿证据台账](wiki/reviews/README.md)，初始均为 `pending`，只有真实评审人核对权威资料、公式和例题、记录文件 SHA 与来源定位后才能标记 `verified`。自动测试通过不等于专家签核。
- **P2 浏览器测试：**新增 [Chromium E2E](e2e/README.md)，涵盖桌面与手机、检索、术语跳转、键盘与语义导航、深色模式、Markdown 表格/代码和公式文本的安全可读性，CI 保存截图。

仓库管理员仍需在 GitHub Rulesets 中开启 `main` 必须经 PR/人工审核/必要检查的保护；真正的屏幕阅读器体验与完整数学排版还需专项验收。
