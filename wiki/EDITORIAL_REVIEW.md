# 深度 Wiki · 内部编辑审查清单

> **仅用于作者、评审人与 Agent。** 不是公开术语详情的章节，不应复制到发布的 Wiki 正文。读者从统一 Explorer 进入详情，不能看到“Batch”、PR 状态、编辑清单或生产统计。

## 1. 批次准备（内部）

- [ ] 当前 `main` 与未合并 PR 已核对；从该领域的真实权威源确定连续编号与原稿数量
- [ ] 内部批次最多 20 条（最后一批可不足 20），不存在重复编号、错配译名与跳号
- [ ] 已为每个概念列出至少一个可核验的一手资料、对应版本和相关术语
- [ ] 明确哪些项目仅为计划，哪些已经完成文章审稿；不可预先宣称发布

## 2. 每篇正文验收

- [ ] 英文、中文、缩写、词义边界与权威源一致；厂商实现不当作通用标准
- [ ] 形象类比正确，明确其局限
- [ ] 技术机制有实际数据流/算法/内存模型/数学条件；必要时附原创图或示例
- [ ] 工程案例说明场景、权衡、限制、故障排查或性能测量口径
- [ ] 与至少一个易混概念作准确对比，相关术语可从站内检索
- [ ] 至少两道中等难度面试问答；答案包含推理、约束与取舍
- [ ] 至少两道中等难度考试题与解析；量纲、算术、假设已复核
- [ ] 至少一项可追溯的权威资料；年份、版本、链接和引用主张相符
- [ ] 教学假设与真实设备实测明确分开；不凭空编造指标
- [ ] 不复制未经授权的来源长文或直接粘贴专有图片

## 3. 发布文件检查

- [ ] 正文文件**只**包含面向读者的定义、原理、案例、问答与参考资料；不含批次、生产进度、编辑 checklist
- [ ] `wiki/<domain>/*.md` 与 `docs/wiki/<domain>/*.md` 字节一致
- [ ] manifest 正确，仅真实已完成的文章标记可发布；未完成的术语仍显示简明定义
- [ ] `python3 scripts/build_wiki_index.py --write` 后 `--check` 无差异
- [ ] 所有内部相对链接可解析；公共详情没有跳往内部批次计划或编辑清单的链接
- [ ] `python3 scripts/verify_wiki.py` 与整库测试成功，PR 合并后 Pages 工作流成功
- [ ] 人工浏览器抽检：目录、表格、公式、代码、手机布局、深色模式与返回检索

## 4. 状态和质量声明

- **planned：**只存在内部选题清单，不能算 Wiki 完成。
- **drafted：**正文已写入候审分支，不代表事实已经审校或 Pages 已上线。
- **merged / published：**已合并 `main` 且部署成功的具体文章，可计为线上可读。
- **technical review：**术语与答案经过领域专家复核才可宣称学术质量已验证；自动测试主要覆盖结构、一致性和可访问文件。

本清单由 [Wiki 路线图](README.md) 与 [贡献指南](../CONTRIBUTING.md) 引用。编辑路径可分批，公开阅读体验永远是**学科 → 术语 → 专业知识详情**。

## 5. 独立签核和内容哈希

每篇已发布文章的专业验证记录见 [Review ledger](reviews/README.md) 及 `reviews/ai-infrastructure.json`。审稿人应提交明确的技术主张与权威文档版本/章节对应关系，逐题重算；签核带正文 SHA-256，变动后自动失效。**已发布文章的未签核状态必须保持 pending；当前 142 篇均需要逐篇专业复核**，不能将 CI 通过宣称为学术同行评审通过。执行 `python3 scripts/verify_wiki_reviews.py --check --report` 可收集宽泛引用、缺少引用、尚未审核等风险。
