# Pod（容器组）

> 学科：AI Infrastructure · 专题：调度与容器 · 技术边界按 Kubernetes、OCI 与运行时官方规范核对

## 1. 核心定义

Pod 是 Kubernetes 中最小的可调度与部署单元，封装一个或多个紧密协作的容器，以及共享网络命名空间、存储卷和部分运行配置。Pod 作为整体被调度到一个 Node；其容器共享 Pod IP 与端口空间，可通过 localhost 通信，但每个容器仍有独立文件系统视图和进程空间（除非显式共享）。

## 2. 形象理解

Pod 像一辆共同出行的小型工作车：车上可以有主驾驶和辅助人员，他们共享同一辆车、路线和行李舱；整辆车被安排到一个站点，而不是把乘客拆到不同站点。

## 3. 技术原理与核心内容

PodSpec 包含 containers/initContainers、volumes、restartPolicy、securityContext、resources、affinity 等。每个 Pod 获得自己的 IP；同 Pod 容器共享 network namespace、端口空间和 localhost。共享 volume 可用于 sidecar 日志、模型下载缓存或 Unix socket。init container 在应用容器启动前完成准备；sidecar 与主容器可协作提供代理、日志或凭证刷新。Pod 的 IP 和本地 writable layer 不是持久身份；Deployment 创建的 Pod 被替换后通常得到新 UID/IP。

## 4. 工程实践与设计权衡

在线推理可将模型 server 与轻量代理/日志 sidecar 放在同一 Pod，但必须考虑 sidecar CPU/内存请求、启动顺序、探针与退出协同。训练任务中不要把多个需要独立故障恢复的 worker 随意塞入同 Pod；若需要共同调度多 Pod，使用 Job/Workload 与 gang admission。数据集和 checkpoint 放 PVC 或对象存储，不依赖容器可写层。

## 5. 易混概念与边界

Pod 不等于 Container：一个 Pod 可以包含多个容器。Deployment 管理一组可替换的 Pod，Service 为 Pod 集合提供稳定访问入口；Pod 是调度/共享资源边界，不是长期稳定的机器或持久存储边界。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 sidecar 和主容器放在同一个 Pod，而不是两个独立 Pod？** 答：当它们必须共享 localhost、生命周期/部署单元或卷时，同 Pod 能直接共享网络命名空间和 volume；若需独立扩缩容或故障隔离，分开部署更合适。

2. **问：两个容器在同一个 Pod 中监听相同 TCP 端口会怎样？** 答：它们共享 network namespace 和端口空间，通常会发生端口绑定冲突；应使用不同端口或分离 Pod。

## 7. 中等难度考试题（含解析）

1. **题：一个 Pod 有 2 个容器，requests.memory 分别 3Gi 和 1Gi，忽略 Pod overhead，调度时总内存 request 是多少？** 解：`3+1=**4Gi**`；节点调度按 Pod 总资源需求考虑，而不是把容器放在不同节点。

2. **题：一个 Pod 内有 3 个容器共享网络 namespace，它们是否有 3 个独立 Pod IP？** 解：没有；该 Pod 通常只有 **1 个 Pod IP**，三个容器共享网络命名空间与端口空间。
