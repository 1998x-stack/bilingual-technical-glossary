# Hot Reload（热重载）

> 学科：AI Infrastructure · 专题：推理与服务 · 具体实现应核对官方接口及版本

## 1. 核心定义

热重载（Hot Reload）是在不中断整个服务进程或尽量不中断在线请求的条件下，加载新的模型版本、权重或配置，并让新请求逐步转向新实例。它与严格的零中断发布并不等价，能否保留在途请求、KV cache 和旧模型可用性由具体运行时与发布策略决定。

## 2. 形象理解

书店不关门就把旧版教材换成新版，但正在看旧版的顾客应有机会看完，切换后新顾客才能拿到新版本。若直接在原书上撕下章节替换，顾客可能读到新旧混杂的内容。

## 3. 技术原理与核心内容

Triton 的模型管理有 NONE、POLL、EXPLICIT 等模式：EXPLICIT 允许经 API 加载/卸载指定模型，POLL 根据仓库变化刷新，但官方提醒直接监听正在写入的 repository 可能观察到部分状态，生产环境不推荐无同步的 POLL。正确发布通常先完整写好版本目录、验证权重与配置、预热新实例、原子切流、保留回滚对象。热加载新模型还可能同时持有新旧权重导致瞬时显存峰值；不能默认 KV cache 与 tokenizer/位置编码在两个版本间兼容。

## 4. 工程实践与设计权衡

在模型上线前对比新旧版本 checksum、配置、tokenizer 和输入/输出 schema，设置 canary 5%→25%→100% 并跟踪 readiness、5xx、TTFT/ITL、显存和错误率。明确预热时延、模型下载失败和部分副本未就绪的回滚策略，测量流式在途请求是否能够安全完成。严禁在无回滚能力的情况下原地覆盖正在使用的权重。

## 5. 易混概念与边界

热重载强调不重启整个运行时的更新；滚动更新可以通过并行副本替换实现近零停机但可能重启单个容器；蓝绿发布通过双环境流量切换，属于部署方案而非单进程 API。

## 6. 中等难度面试题（含参考答案）

1. **问：为何生产环境不宜直接依赖检测文件目录变化的随意 POLL？** 答：写入新模型文件期间可能被轮询到不完整状态，导致加载失败或不一致。Triton 文档建议谨慎使用，通常更适合明确版本化上传与受控 EXPLICIT load。

2. **问：热重载为什么可能出现显存突然翻倍？** 答：新旧权重及实例可能在流量切换期同时驻留，外加预热与 KV cache；需预留容量或分批跨实例切换。

## 7. 中等难度考试题（含解析）

1. **题：旧模型占 14 GiB，新模型占 16 GiB，短暂同时驻留，不计其它 buffer，最低需要多少显存？** 解：至少 `14+16=**30 GiB**`，还未加 KV cache 和运行时空间。

2. **题：计划 10,000 请求中 5% 灰度到新版本，理想随机分流的期望请求数？** 解：`10,000×0.05=**500**` 个；这是期望，不保证恰好 500。
