# Speculative Decoding（推测解码）

> 学科：AI Infrastructure · 专题：推理与服务 · 以维护者文档及具体引擎版本为准

## 1. 核心定义

推测解码（Speculative Decoding）先利用便宜的草稿模型、n-gram 或其它预测机制提出多个候选 token，再由目标模型批量验证，力图减少目标模型逐 token 串行调用次数。原始**精确推测采样**在满足其接受/拒绝与校正规则时，可以保持目标模型输出概率分布；某些工程近似并无这项保证。

## 2. 形象理解

助手先起草 4 句，主编一次审核；猜得准就能连续通过，猜错则丢弃余下错误前缀，甚至需要重新采样。草稿成本、审核成本与命中率共同决定收益，不能把提议 4 句当成四倍加速。

## 3. 技术原理与核心内容

每轮 draft 提议 K 个 token，target 计算这些位置的条件概率；按正确接受概率得到连续被接受前缀，拒绝时用残余分布校正采样，以实现目标分布的精确性。涉及 KV Cache 提交/回退、流式输出 chunk、随机采样和停止条件；EAGLE 等路径与基础双模型版本的接受率、实现假设不同。验证批次占用 GPU 和网络，特别是在高并发时可能增加竞争。

## 4. 工程实践与设计权衡

评估时分别报告 draft 生成开销、target 一次验证耗时、mean accepted length、输出 TPS、TPOT/ITL 长尾和效果质量。高命中率不保证高吞吐：草稿模型过大、目标模型并行验证成本高时可能收益为负。对采样分布做统计验证，不能以固定随机种子文本完全一致作为数学等价证明。

## 5. 易混概念与边界

Speculative decoding 不等同 beam search（多路径搜索）或 prefix cache（复用已有输入）。它可能使一次 SSE 事件包含多个 token，从而令事件 ITL 与每 token TPOT 差别明显。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么高并发服务开启推测解码不一定更快？** 答：草稿推理与目标验证都消耗计算资源，而连续批处理本已利用高 batch；接受长度低时额外工作不值得。应测实际每个已输出 token 的端到端成本。

2. **问：如何声称推测采样未改变目标模型分布？** 答：只能在正确接受概率与拒绝后校正采样、合法的采样截断/停止条件下证明。直接采纳全部 draft token 并不保持目标分布。

## 7. 中等难度考试题（含解析）

1. **题：100 次验证累计接受 270 个 draft tokens，平均接受长度？** 解：`270/100=**2.7**` 个/轮；不等于平均最终输出总数，因轮末还可能采样额外 token。

2. **题：原始逐 token decode=20ms，某推测轮总耗时 50ms 且最终生成 4 token；理想相对加速？** 解：每 token 等效 `50/4=12.5ms`，比原 `20/12.5=**1.6×**`；未计首 token 和跨请求调度。
