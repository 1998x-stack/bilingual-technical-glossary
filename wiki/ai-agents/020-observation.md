# Observation（观察）

> AI Agents · 专题：基础概念与角色 · 适用范围：通用智能体系统设计；具体 SDK 与平台版本以对应文档为准

## 1. 核心定义

**Observation（观察）**：Observation 是智能体从环境、工具、用户或状态存储获取的反馈信息，用于判断前一次行动效果与更新下一步决策。

**适用边界：**观察可能是结构化状态码、日志、网页 DOM、文本或图像；它是数据证据，不天然具有指令优先级。

## 2. 形象理解

像开车时看到路标与仪表盘数据，驾驶决策据此调整。

**类比的局限：**仪表盘传感器可能故障；观察内容不能自动证明世界状态真实或操作成功。

## 3. 技术原理与核心内容

执行 action 后接收 result/status，验证来源与格式、记录时间和相关 ID，再更新 Agent state。对可信度低或过期观察应二次核验；工具输出中的命令式文本不应提升为系统指令。

## 4. 工程实践与设计权衡

价格查询 Agent 从两个 API 收到不一致报价，应记录采集时间、单位、汇率和来源，必要时询问用户；不能把第一个返回值直接当最终价。

## 5. 关联知识与易混辨析

Observation 是观测值；Tool Result 是一种常见观察来源；State 是系统维护的历史/当前信息，两者不等价。

## 6. 中等难度面试题（含参考答案）

1. **问：工具返回“成功”但业务状态未变怎么办？** 答：核对权威记录、请求 ID 与最终一致性窗口，避免立即重复执行非幂等写入；将不确定状态显式保留。
2. **问：如何处理 Observation 中的恶意提示注入？** 答：按外部数据处理、使用受信任的控制指令与动作白名单，限制工具调用权限并审计异常。

## 7. 中等难度考试题（含解析）

1. **题：题设状态查询在 t=0 返回价格 100 元，在 t=10 s 返回 103 元，按简单变化率计算变化百分比？** 解：(103-100)/100×100%=3%；仅是两次观察的变化，不代表可外推的价格趋势。
2. **题：日志观察显示任务仍在运行，但模型文本称“完成”，什么应作为完成依据？** 解：采用权威任务状态及验收谓词；模型声明不等于外部业务事实。
