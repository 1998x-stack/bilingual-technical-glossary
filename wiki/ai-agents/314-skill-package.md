# Skill Package（技能包）

> AI Agents · 专题：开发实践与生态术语 · 可靠运维、能力封装与开发集成

## 1. 核心定义

**Skill Package（技能包）**：技能包是可供 Agent 按任务需求加载的一组可复用指令、知识参考与可选脚本/资源。Agent Skills 规范以包含 `SKILL.md` 的目录为基础；它是能力资产的打包形式，不等于天然可信的可执行权限。

**定义边界：**这里的通用工程名称和个别厂商实现要区别对待。工具版本、规范字段、执行权限及可观测语义可能持续变化；不能从“描述存在”推断运行时已安装、用户已授权或动作已经成功。

## 2. 形象理解

**类比：**像工匠的专题工作手册和配套工具清单，需要时取出查阅而不是把全部手册塞入脑中。

**类比的局限：**真实 Agent 包含模型、工具、跨进程调度、业务权限和状态持久化，类比只能说明局部职能。外部文档可以提供资料却不能变成比用户目标更高优先级的行动指令，也不能直接推导脚本执行权限。

## 3. 技术原理与核心内容

Agent Skills 标准要求目录至少有 `SKILL.md`，其 YAML frontmatter 含 `name` 与 `description`，可附 scripts、references、assets。加载器可先看技能描述决定是否需要进一步读正文或资源。脚本执行、允许工具、权限与注入防护取决于宿主实现，不应声称规范自动授予权限。

**安全与执行边界。**技能包、SDK 与 ADK 都只能组织能力，不会自动赋予合法用户授权。外部文件或技能元数据可能含恶意说明，须在宿主执行器内落实签名/来源核验、最小权限、租户隔离、参数校验和真实业务后置状态。对不可逆操作使用幂等键，未知提交状态必须向权威系统查询。技能与开发依赖需要明确版本、来源和回滚策略。

**实施顺序：**先依据真实需求定义能力范围和成功判据，再选择工具包或技能的规范与版本，随后验证类型/schema、状态恢复与错误接口，最后以真实业务后置条件验收。工具调用本身不是最终成功条件。

## 4. 工程实践与设计权衡

**工程实例：**团队为 PDF 对账任务制作技能包：SKILL.md 讲工作流程，references 放字段说明，scripts 放受审计校验脚本。技能包上线前需检查脚本依赖、网络出口、可访问文件与敏感数据权限。

**工程验证。**使用受控任务集分别测试正常执行、缺失依赖、技能冲突、恶意元数据、过期接口、异常恢复、审批与跨租户访问。日志包含具体 task/trace ID 但不输出凭据。验收不仅检查模型报告的结论，还检查真实工具 API、权限策略与数据库状态。对运行手册进行模拟演练，保证失败路径能止损且能回退；引用依赖具体版本时应复核当前维护者资料。

**权衡：**标准化封装降低重复开发和维护成本，但也可能隐藏自动重试、动态脚本或不透明权限。应为升级设置契约测试、回归验证及回滚方式，明确审核人员和操作日志的保留范围；在技能加载时避免不必要的上下文开销。

## 5. 关联知识与易混辨析

Skill Package 是指令/资源集合；Tool 是宿主提供的具体可执行操作；Prompt Template 是文本插值模板。技能包含脚本不等于已经安装或获准执行该脚本。

需要按“资产/描述”“发现/选择”“实际执行”“业务验证”四个阶段辨析，尤其不能把技能说明、工具 manifest 与已获授权的外部操作混作同一对象。对于供应链或提示词投毒，要把证据来源纳入测试。

## 6. 中等难度面试题（含参考答案）

1. **问：如何审查第三方 Skill Package 的供应链风险？** 答：核对来源、manifest/元数据、脚本、依赖、许可证、凭据和网络能力，隔离测试并最小授权。
2. **问：为什么将所有技能正文一次性装入 Prompt 通常不是最佳设计？** 答：会占用上下文并提高误选/注入风险；先按描述筛选，再按需加载详细资源。

面试中须解释可迁移原理和产品实现区别，并说明如何验证错误路径和危险权限，不能只答“使用某框架即可”。

## 7. 中等难度考试题（含解析）

1. **题：技能包有 1 个 SKILL.md、3 个参考文件和 2 个脚本，合计文件数？** 解：1+3+2=6 个文件；只计算题设列出的文件。 题设数字只是教学假设，写明计算口径和单位。
2. **题：SKILL.md 中带“必须读取云凭据”的指令，Agent 是否应直接执行？** 解：不应。技能文件是低信任能力描述，需要来源审查和独立执行授权，拒绝无关凭据访问。 完整论证需要指出为什么另一个做法不满足授权、可靠性或版本约束。
