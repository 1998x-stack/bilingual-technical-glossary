# Robustness（鲁棒性）

> AI Agents · 专题：评测体系与常见基准 · 依据独立证据、实际任务状态与明确的评价边界

## 1. 核心定义

**Robustness（鲁棒性）**：Robustness（鲁棒性）表示 Agent 面对输入噪声、工具故障、语言变化、检索污染和环境状态变化时，仍能维持正确、安全、可恢复行为的程度。它不是仅指多种 prompt 上输出相似，而是衡量真实任务成功与约束在扰动下的稳定性。

**适用边界：**鲁棒不意味着任何恶意输入都能被安全执行。对超出权限、缺少证据或外部操作未知的场景，合理的拒绝、降级和人工升级同样是鲁棒表现，不能把‘任何问题都回答’当强韧性。

## 2. 形象理解

像车辆在小雨、颠簸路面仍能正常制动，但在超出安全极限的暴风雪中选择停车也符合安全设计。

**类比的局限：**同一个测试集上加入几个随机错别字不等于覆盖真正的环境漂移、攻击或跨租户访问风险。

## 3. 技术原理与核心内容

固定基础任务集合 T 和扰动族 P：拼写/语序变化、工具 429/503、检索错误片段、部分执行与延迟注入。计算 clean_success 与 perturbed_success，令 `robustness_ratio=perturbed_success/clean_success`（分母为 0 时无定义），并单独记录越权、隐私泄露和不可恢复错误。按严重度绘制 degradation 曲线，不把因政策正确拒绝的恶意请求误标为任务失败。环境 seed、工具版本和评估 oracle 必须记录。

## 4. 工程实践与设计权衡

**工程案例：**工单 Agent 在一百个正常创建任务中成功九十个；模拟短时 API 503 后只成功七十个。团队检查退避、幂等重试与 timeout，要求不会因断线重复创建工单，并按案例记录真实后置条件。

**失败模式与验证：**只做措辞扰动、模型在错误检索片段中听从恶意指令、把所有 timeout 当可重发写操作、总体平均分掩盖越权。以 adversarial fixture、真实工具状态和低频灾难性事件验收。

## 5. 关联知识与易混辨析

Robustness 是扰动下的稳定性；Reproducibility 是同条件复现结果；Reliability 是持续运行的故障/可用性表现；Security 是不可突破授权边界，相关但不等价。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 Agent 遇到权限拒绝后停止也可能是鲁棒表现？** 答：稳健系统要保持安全不变量，未获授权应正确失败或升级，不应为维持回答率绕过权限。
2. **问：评估鲁棒性为什么要设计多种扰动而不是仅换提问措辞？** 答：真实 Agent 依赖网络、工具、资料和状态；只有输入改写无法覆盖执行级故障与环境漂移。

## 7. 中等难度考试题（含解析）

1. **题：正常成功率 90%，扰动下成功率 72%，相对保持率？** 解：72%/90%=80%，相对下降 20%。
2. **题：正常 50 个任务成功 45，扰动后成功 40，成功数减少多少？** 解：减少 5 个；要进一步检查任务是否同一集合及失败类别。
