# Hierarchical Planning（分层规划）

> 适用领域：AI Agents · 专题：任务规划与决策 · 相关理论与具体产品能力应依据所引来源和版本区分

## 1. 核心定义

**Hierarchical Planning（分层规划）**：Hierarchical Planning（分层规划）用多个抽象层表示目标：从高层任务逐级细化为可执行的低层动作。经典 HTN 用任务分解方法和领域知识约束细化；现代 Agent 也可用目标树/层级工作流组织。

**适用边界：**HTN 是有明确任务网络与细化规则的一类规划范式；仅把 LLM 输出缩进成大纲不等价于满足形式化 HTN 语义。

## 2. 形象理解

像先设计城市交通网络，再细化到道路、路口和每一处信号灯。

**类比的局限：**抽象规划有助于聚焦，但低层执行仍可能受时刻表、路况与权限约束。

## 3. 技术原理与核心内容

HTN 将 compound task 通过合法 method 展开为若干 task，直到叶节点均为 primitive action。各层须保留约束，并允许选择不同分解方式。可用 `完成采购 → {询价,合规审查,提交审批} → API 调用` 表示；若叶节点不能执行，返回上层选择替代 method。

## 4. 工程实践与设计权衡

**工程案例：**IT 故障应对分为检测、诊断、隔离、恢复；诊断下再细分网络、数据库和应用检查。每个层次设完成条件，防止父节点因某个子节点的文字“成功”而虚假完成。

**失败模式与验证：**层级规划依赖领域知识准确性；如果拆分方法遗漏关键约束，层级越深越易累积误差。检验每个 method 的前置条件、子任务契约与集成结果。

## 5. 关联知识与易混辨析

Hierarchical Planning 强调抽象到具体的精化结构；High-level Plan 只是顶层阶段表达；Task Decomposition 可以是单层、动态或递归，不必属于 HTN。

## 6. 中等难度面试题（含参考答案）

1. **问：HTN 相比纯 action-level 搜索的工程优势？** 答：复用领域模板、约束搜索范围、提供可解释责任边界；代价是维护领域细化方法，且高层错误可能传播。
2. **问：高层任务可行而某叶节点权限不足，应怎样处理？** 答：不能强行执行；在上层按允许 method 寻找可替代流程，或申请授权/人工接管，保证不变量不被破坏。

## 7. 中等难度考试题（含解析）

1. **题：一项复合任务分解为两项并行原子任务各 4、7 min，随后串行验收 2 min，理论最短时间？** 解：max(4,7)+2=9 min；假设原子任务无资源冲突且验收依赖全部完成。
2. **题：“处理投诉”只有层级标题，没有子任务前置条件与执行动作，能称为有效 HTN 解吗？** 解：不能仅凭大纲判定；需要具体可执行叶动作、合法分解方法及满足的先后条件和初始状态。
