# High-level Plan（高层计划）

> 适用领域：AI Agents · 专题：任务规划与决策 · 相关理论与具体产品能力应依据所引来源和版本区分

## 1. 核心定义

**High-level Plan（高层计划）**：High-level Plan（高层计划）以目标、里程碑、关键阶段、风险与交付条件表达总体路线，故意暂不规定每个 API 参数和逐条动作。它帮助 Agent 与用户对齐范围并控制跨阶段依赖。

**适用边界：**高层计划通常是管理和抽象层术语，不应当作可直接发送到生产工具的执行脚本。

## 2. 形象理解

像旅行规划只确定到达城市、住几晚与重要活动，具体打车路线和车次要到行动层再制定。

**类比的局限：**大纲清晰不保证预订成功；重要的预算、签证或时间约束仍要在高层记录。

## 3. 技术原理与核心内容

定义阶段 `phase={goal, deliverable, entry_condition, exit_condition, owner, risk}`，按依赖组织里程碑。每阶段向 Action Plan 下钻，实际执行再获取观察更新完成状态。高层不能声称某阶段成功，除非其退出条件得到验证。

## 4. 工程实践与设计权衡

**工程案例：**迁移数据库时，高层计划是评估→备份与演练→切换→验证→回退窗口结束。切换阶段的细节应在行动计划内列明 SQL、检查点和审批权限，高层只定义风险与门槛。

**失败模式与验证：**高层计划易过于笼统，例如“最后发布”缺少测试成功条件。防止将草拟计划作为完成证据；对时间和资源的估算需标注假设。

## 5. 关联知识与易混辨析

High-level Plan 是抽象阶段与交付目标；Action Plan 是逐步可执行操作；Goal 是最终验收结果。一个 Goal 可有多个高层路线。

## 6. 中等难度面试题（含参考答案）

1. **问：面对一个含 30 个工具调用的复杂任务，高层计划应描述什么？** 答：阶段、交付物、依赖、验收与风险审批；避免在高层写满每个工具参数，但明确进入/退出条件。
2. **问：计划变化后如何判断是否要重写高层路线？** 答：若目标、资源上限或关键里程碑改变，应修订高层；若只替换某个工具参数，通常只需调整行动计划并保持全局约束。

## 7. 中等难度考试题（含解析）

1. **题：阶段 A 2 天，B 与 C 在 A 后并行各 3、5 天，阶段 D 在二者后 1 天，最短完工天数？** 解：2+max(3,5)+1=8 天，假设资源无限且不存在额外排队。
2. **题：高层写“迁移完成”但未核对新库数据，符合完成条件吗？** 解：不符合；应明确行数/抽样一致性、读写成功、服务指标和回退监控等可验收退出条件。
