# Logging（日志记录）

> AI Agents · 专题：工程化、成本与可观测性 · 运行时观测、性能和可核验业务结果

## 1. 核心定义

**Logging（日志记录）**：日志记录是在软件运行时按事件写出时间、严重性、来源与上下文的过程。AI Agent 中需区分规划事件、模型调用、工具调用、授权拒绝和业务提交；日志是事件证据，不保证涵盖所有执行步骤。

**关键边界：**统计、记录和推导应围绕具体组件、时间窗口、资源范围与数据来源展开。对同一指标，模型级、工具级和端到端任务级的计数范围不同；不能把某个厂商的指标名或日志约定误作所有框架的标准。指标异常不必然表示恶意攻击，正常值也不保证业务目标已成功。

## 2. 形象理解

**类比：**像航海日志：船长按时写航向和天气，事故后可按事件复盘。

**类比的局限：**日志可能被采样、丢失或被误写；手记不是航行本身，也不适合作为唯一业务账本。 Agent 还涉及异步执行、不可逆副作用和跨组件故障，必须回到真实时间线及权威状态核验。

## 3. 技术原理与核心内容

Agent Runtime 的事件链可以是 task_started → model_requested → tool_started → tool_finished → task_completed；每条日志携带 UTC 时间、task_id、trace_id、event_name、severity 和受控属性。异常场景用 ERROR 与异常类型，不打印密钥/完整原始提示。日志写入可异步批量发送，但崩溃可能丢尾部记录。

**工程不变量。**模型生成“完成”不等于业务系统提交成功。任务级事件需要和权威后置状态、幂等请求号以及租户范围关联；统计前必须声明计量单位、时间范围、分母与抽样方式。低信任外部内容不可作为系统配置指令，日志/指标不得存放明文凭据。并发执行的时间线应遵循真实因果关系而非简单求和。

**数据路径。**入口生成任务/追踪上下文，模型与工具分别输出带时间和状态的事件；记录系统可作采样、聚合与索引。对失败重试需标注逻辑任务与单次尝试的区别。对隐私敏感字段做 allowlist 和脱敏；对于来源不可信的数据保留标记，不允许它重新定义权限和用户目标。

## 4. 工程实践与设计权衡

**真实工程类型的案例：**购票 Agent 在付款调用超时后生成“失败”日志，实际上后端已完成扣款。排障必须查询订单 ID 并记新的状态核验事件，不能只据超时日志重试支付。

**测试与排障。**为每个概念构造正常、超时、重试、并发、队列积压和返回成功但业务未落库的场景，检查模型建议、实际工具请求、权限判定、后端结果及观测信号是否一致。建立固定数据集与时间窗，独立复算计算题；对于采样数据说明不确定性。可观测性增强有日志/指标存储成本和敏感数据面扩大等代价，应基于服务级别目标和故障价值进行最小化采集。

**权衡。**准确定位问题需要信号足够丰富，但全量记录模型输入可能暴露隐私，过多高基数标签会提高成本。对高影响操作保留必要审计，普通可观测数据按合理抽样、保留与访问策略处理。一个工具返回 200 不意味着整个 Agent 任务成功；必须检查业务层结果。

## 5. 关联知识与易混辨析

Logging 与 Metrics：前者保存离散事件，后者保存可聚合计量；与 Audit Trail：普通日志可能采样或轮转，审计账本另有完整性、保留与权限要求。

需要区分事件、持续时间、聚合率与因果关系这四类信息。构建跨术语查询时应从任务目标→服务行为→运行数据→业务后置条件逐级定位，不可只因为名称相近就混用指标或用 tracing ID 充当权限凭证。

## 6. 中等难度面试题（含参考答案）

1. **问：模型回答失败但支付已成功，如何设计日志才能可靠排障？** 答：按同一 task_id 关联请求、幂等键、工具 attempt 与权威业务后置状态，区分调用失败和交易失败。
2. **问：为什么禁止把完整 prompt 和 access token 直接记入调试日志？** 答：这些信息可被多方日志平台读取、长久保留或被攻击者搜索；采用字段白名单、脱敏和最小访问权限。

优秀回答不仅提出技术机制，还应指出适用范围、失败模式、用户感知结果和能在生产上观察到的验证信号。

## 7. 中等难度考试题（含解析）

1. **题：按题设每秒产 120 条日志，连续 5 分钟且平均每条 500 字节，原始数据量？** 解：120×300×500=18,000,000 字节，约 18 MB（十进制）；未计压缩与索引开销。 **计算口径：**数据、单位和边界均由题设给出；若非随机抽样或存在遗漏，不得外推为真实系统质量。
2. **题：某 Agent 产生 429 后立即重试，怎样写日志帮助定位重试风暴？** 解：记录 attempt 序号、退避时间、下游状态、幂等键与关联 ID，既能识别风暴又不泄密。 **评分重点：**原理、推导步骤、关键反例与可操作的验收方式，而非单句术语记忆。
