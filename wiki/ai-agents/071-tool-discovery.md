# Tool Discovery（工具发现）

> AI Agents · 专题：工具使用与环境交互 · 具体工具行为、权限与版本以官方规范为准

## 1. 核心定义

**Tool Discovery（工具发现）**：Tool Discovery（工具发现）是 Agent 或宿主在运行时查询、识别并加载当前可用工具及其能力元数据的过程。工具集合可能随用户权限、服务连接、租户、版本和健康状态变化，不应被假定永久固定。

**适用边界：**发现工具并不意味着模型已获准执行；发现结果还需要验证来源、版本与授权范围。不同工具协议的列举、分页和缓存行为各有规则。

## 2. 形象理解

像走进大型图书馆先查目录找到相关书籍，再确认是否有权限借阅与是否在架上。

**类比的局限：**目录中出现一本书，不保证可以借到，也不保证内容适合当前问题。

## 3. 技术原理与核心内容

通过工具协议的 list 接口或内部服务目录检索候选定义；典型信息包含 name、description、inputSchema、namespace、capabilities。MCP 的 tools/list 可以返回可用工具集合；大型工具集可能先按需求检索候选，再按受信任工具 ID 动态加载。对发现结果可设置 TTL 和变更通知，但每次真正执行仍需实时授权。

## 4. 工程实践与设计权衡

**工程案例：**企业报表 Agent 接入销售与财务两个系统。用户只授权销售数据时，发现层仅返回适用的只读查询工具；当权限改变时刷新工具缓存，避免旧授权配置泄漏财务能力。

**失败模式与验证：**盲目缓存导致停用工具仍被调用，工具说明被不可信插件篡改导致模型选错，高权限工具被暴露在低权限上下文。审计需记录发现来源、工具目录版本与授权主体。

## 5. 关联知识与易混辨析

Tool Discovery 是获取当前能力列表的动态过程；Tool Registry 是保存可信工具定义的数据结构或服务；Tool Selection 是从已发现能力中决定用哪个。

## 6. 中等难度面试题（含参考答案）

1. **问：工具已在发现列表中，是否能认为当前用户必然可执行？** 答：不能。发现可能只用于能力展示，执行器仍须按可信身份、资源范围和调用时状态做授权校验。
2. **问：几千个工具定义为什么不宜全部注入模型上下文？** 答：会增加 token 成本和混淆。可先按任务检索/延迟加载候选，保存版本和引用，执行前检查工具白名单。

## 7. 中等难度考试题（含解析）

1. **题：工具注册表有 120 个条目，发现阶段按权限排除 50 个、按任务筛掉其中余下的 40 个，若两步无重叠，剩多少？** 解：120−50−40=30 个候选；这是集合过滤的教学假设。
2. **题：新工具部署后模型仍看不到，缓存 TTL 为 10 分钟且未收到变更通知。最值得先检查什么？** 解：检查发现缓存是否过期、目录版本与权限过滤，而不是猜测模型不理解工具名称。
