# Decision Point（决策点）

> 适用领域：AI Agents · 专题：任务规划与决策 · 基础概念与具体 SDK 权限实现需分开判断

## 1. 核心定义

**Decision Point（决策点）**：Decision Point（决策点）是在执行流程中需要依据当前状态、观察和约束，从多个候选动作/分支中作出选择的时刻。它是规划与控制中的概念节点，决定后续控制流。

**适用边界：**决策点可由确定性规则、人工审批或模型策略决定；不是每个节点都必须调用 LLM，也不意味着所有分支等价合法。

## 2. 形象理解

像火车岔道口：调度员先看轨道占用与目的地，才决定进入哪条线路。

**类比的局限：**线路选择不能只凭偏好，信号灯与安全保护是硬约束。

## 3. 技术原理与核心内容

决策过程可写为：读当前 `s` 和观察 `o` → 过滤不满足前置条件/权限的候选 `A_valid` → 估计成本与效用 → 按 policy 选 `a*` → 保存理由与决策 ID → 执行并复核。若 `A_valid` 为空，进入停止/人工升级，不可凭模型捏造未授权分支。

## 4. 工程实践与设计权衡

**工程案例：**故障排查 Agent 在“继续采集日志、回滚服务、升级人工”之间选择。回滚仅当回滚审批、健康检查和授权全部满足，否则只能诊断或升级人工。决策日志保留证据和环境版本，便于事故复盘。

**失败模式与验证：**如果模型选择的分支缺乏独立执行层验证，会形成越权决策。采样概率不能直接替代成本/风险比较；需要对所有高风险分支做负向测试。

## 5. 关联知识与易混辨析

Decision Point 是选择发生的时刻；Action Space 是可选动作全集/合法子集；Policy 是映射观察/状态到动作的规则。

## 6. 中等难度面试题（含参考答案）

1. **问：在哪些决策点用规则比调用 LLM 更合适？** 答：金额上限、权限检查、时序门控等确定性硬约束应交给规则；只有复杂但有约束的权衡才需要模型。
2. **问：如何验证一次 Agent 决策可审计？** 答：记录候选动作、已过滤原因、观察来源/时间、权限检查、选择结果及执行状态，并保留实际业务审批 ID。

## 7. 中等难度考试题（含解析）

1. **题：假设三个允许动作的期望成本分别为 4、7、5 元，且目标仅最小化期望成本，应选哪一个？** 解：选成本 4 元的动作。若存在风险硬约束，必须先过滤违法或不可接受的动作。
2. **题：LLM 给出写数据库动作，但用户只有只读凭证。有效候选集合中能保留这个动作吗？** 解：不能。执行层授权必须过滤该写动作；必要时转人工或选择只读诊断。
