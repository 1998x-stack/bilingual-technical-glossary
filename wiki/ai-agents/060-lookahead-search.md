# Lookahead Search（前瞻搜索）

> 适用领域：AI Agents · 专题：任务规划与决策 · 基础概念与具体 SDK 权限实现需分开判断

## 1. 核心定义

**Lookahead Search（前瞻搜索）**：Lookahead Search（前瞻搜索）在选择当前动作前，利用环境转移模型或模拟器向未来展开若干步，比较可能后果与累计成本/价值，再决定当前动作。它常用于路径规划、棋类、资源调度和模型预测控制。

**适用边界：**lookahead 的预测依赖模型质量，深度有限会产生 horizon effect；更深的搜索增加计算，不保证更好结果，尤其当模型/评价器有偏差时。

## 2. 形象理解

像下棋前先看两三步之后的局面，而不是只看当前落子的立刻得分。

**类比的局限：**未来对手行动和环境事件不完全可预测；看得更远不等于知道真实未来。

## 3. 技术原理与核心内容

给定当前状态 s 和可执行动作 a，可模拟 `s'=T(s,a)`，评估一步奖励 r 与后续价值。深度 H 的近似价值可用 `Q_H(s,a)=r(s,a)+γ·V_(H−1)(s')`，在终端深度用估值函数；不确定转移则对可能的 s' 求期望。动态重规划可在每次真实观察后重新执行短时域搜索。

## 4. 工程实践与设计权衡

**工程案例：**仓库补货 Agent 通过两步模拟比较“立即采购”与“等待低价”的库存缺货风险、价格和到货延迟；每轮先查真实库存与订单状态，再按权限执行，防止模型预测被误当保证。

**失败模式与验证：**分支因子 b、深度 H 造成指数级候选，预测误差随层数累积；不处理终端价值可能偏好眼前收益。通过历史重放、仿真与在线试验评估不同深度的质量/时延。

## 5. 关联知识与易混辨析

Lookahead Search 专注模拟未来动作后果；Heuristic Search 通过估计函数引导扩展，二者可组合；Replanning 是环境变化后重新生成后续动作，不等于前瞻本身。

## 6. 中等难度面试题（含参考答案）

1. **问：为何规划 Agent 不总应该把 lookahead 深度设到最大？** 答：长深度候选数量激增、转移估计误差累积且延迟增加，应按任务风险、时间预算和模拟可靠性确定 H。
2. **问：模型预测“明天库存足够”能直接用来承诺发货吗？** 答：不能。前瞻是模拟预测，需用实时库存/订单和到货确认作为业务证据，且承诺动作有权限与风险约束。

## 7. 中等难度考试题（含解析）

1. **题：折扣 γ=0.9，动作 A 即时奖励 2、下一步估值 10；B 即时奖励 5、下一步估值 5。按一步 lookahead 价值哪个更大？** 解：A=2+0.9×10=11；B=5+0.9×5=9.5，选 A。前提是估值与奖励同口径且无硬约束冲突。
2. **题：每步最多 3 个候选，前瞻深度 3，完全展开（不含根）最多生成多少节点？** 解：3+9+27=39 个后继节点；包含根为 40 个，说明搜索深度的指数增长。
