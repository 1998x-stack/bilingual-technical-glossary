# Task Success Rate（任务成功率）

> AI Agents · 专题：评测体系与常见基准 · 明确分母、独立验证器、证据和安全界限

## 1. 核心定义

**Task Success Rate（任务成功率）**：Task Success Rate（任务成功率）是在给定任务集合中，有多少个任务经预先定义的验收谓词确认为成功的比例。它是 Agent 系统的核心指标之一，但只有在明确任务单位、失败分母和成功条件时才有意义。

**适用边界：**不能只计入可运行且容易的样本而隐藏超时、越权和未完成任务。对于存在多个步骤的任务，最终回答符合字面要求也不一定意味着真实业务动作完成；应按权威 oracle 检查。

## 2. 形象理解

像考试不是看学生写了多少页，而是看规定的题目里多少题真正满足正确答案标准。

**类比的局限：**不同题目难度、分值和风险不同，成功率平均值不能掩盖灾难性失败。

## 3. 技术原理与核心内容

定义成功率 `TSR=Σ_{i=1}^N 1[success_i]/N`，N 包括规定的全部有效任务，预注册允许的忽略项并单独报告未运行比例。success_i 应由可检查条件确定，如 git commit 与测试记录、真实库存变化、审核通过的引用等。对随机 Agent 多次运行应报告 pass@1 或 repeated-run 成功率，以及 bootstrap/Wilson 区间；分场景报告，以免少数高风险任务被简单多数覆盖。

## 4. 工程实践与设计权衡

**工程案例：**AI Agent 处理 100 个创建工单任务，60 个真实创建成功，10 个内容无效，20 个超时未确认，10 个因权限拒绝。严格以已验证成功计，TSR 为 60%，而不是 60/(60+10)。

**失败模式与验证：**从分母删除难题、把 pending 当 pass、把部分步骤成功当整体成功、真实 API 失败但模型回复已完成。锁定任务 ID 集合、oracle 和运行版本，审核所有被剔除项。

## 5. 关联知识与易混辨析

Task Success Rate 衡量每个任务终态；End-to-end Success Rate 要求全链路完成；Action Success Rate 衡量单次环境动作；工具调用准确率只涉及选择和参数，不等于任务成功。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么必须披露未运行与超时数量？** 答：分母变化直接影响成功率，隐藏未运行或超时会产生选择偏差，无法可靠比较系统。
2. **问：为何任务成功率不能代替安全评测？** 答：即使大多数任务成功，一次越权删除或隐私泄露也可能造成高后果，需单独指标和硬约束。

## 7. 中等难度考试题（含解析）

1. **题：100 个任务中 60 成功、20 未完成、20 失败，TSR 是多少？** 解：60/100=60%。
2. **题：在 50 个有效任务里完成 35 个，成功率？** 解：35/50=70%。
