# Consensus（共识）

> AI Agents · 专题：多智能体协作 · 多 Agent 通信、一致性与独立业务验收

## 1. 核心定义

**Consensus（共识）**：Consensus（共识）是在多 Agent 协作中通过规则、投票、证据比较或特定协议形成共同判断/可执行决定的机制。它可服务于观点整合，但 Agent 的多数一致不等于结论的真实性；与分布式系统中严格的 Raft/Paxos 一致性协议不应混称。

**适用边界：**AI Agent 共识常是应用层的意见汇总和验证；分布式共识则要求明确故障模型、复制日志和安全/活性性质。多个使用同一模型或资料的 Agent 误差往往相关，不能把投票数直接当可靠概率。

## 2. 形象理解

像专家委员会讨论技术方案，可以按规则表决，但重要安全结论还需要实验或标准约束。

**类比的局限：**委员会成员可能被同一错误数据误导，5 人都赞成不代表方案一定不会失败。

## 3. 技术原理与核心内容

定义 candidates_i=(answer_i,evidence_i,source_i)，先评估证据独立性、适用时间和冲突，再按预设 voting_rule/weighted_score/quorum 做决策。高风险业务 gate 应是约束式 all-of，不能用多数票绕过一次权限拒绝。若目标是分布式状态一致性，须另有可验证的提交日志、leader/term 和故障模型，而非简单 LLM 协商。

## 4. 工程实践与设计权衡

**工程案例：**合同审查由财务、法务和风控 Agent 分别给出意见。对用词风格可投票，但实际支付仍需法律约束、预算权限和签署证据全满足；即使 2/3 Agent 赞成，也不能取代法定审批。

**失败模式与验证：**共用错误事实导致虚假多数、角色权重随意变化、投票不能处理 unknown、不一致证据被省略。通过矛盾样本、同源偏差、无效投票和最小法定审批约束测试。

## 5. 关联知识与易混辨析

Consensus 是形成共同决策的策略；Conflict Resolution 是处理分歧的过程；Aggregation Pattern 是广义结果合并；Raft 等容错复制协议属于另一类严格分布式共识。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 3 个同一模型生成的回答投票不一定提高事实可靠性？** 答：其错误常高度相关，投票不是独立证据；应核实不同来源和真实业务数据。
2. **问：哪种情况下 2/3 的多数票不足以继续？** 答：存在法定、权限或安全必需条件时，任何未通过的强制 gate 都应阻断动作。

## 7. 中等难度考试题（含解析）

1. **题：5 个 Agent 中 4 个支持某方案，简单赞成率？** 解：4/5=80%，并非方案正确率。
2. **题：3 个独立审查条件必须全部为真，结果 true、true、unknown，能通过 all-of gate 吗？** 解：不能，尚有必要条件未证实。
