# Agent Framework（智能体框架）

> AI Agents · 专题：基础概念与角色 · 适用范围：通用智能体系统设计；具体 SDK 与平台版本以对应文档为准

## 1. 核心定义

**Agent Framework（智能体框架）**：Agent Framework 是为构建智能体提供抽象层的开发库，通常封装模型接入、工具接口、编排、状态与轨迹跟踪；它不自动保证任务正确性或安全。

**适用边界：**不同框架有不同程度的状态持久化、handoff 和并发支持；以具体版本文档为准。

## 2. 形象理解

像搭建工厂的标准化设备和输送带，减少重复接线，却不能替代工艺设计与质检。

**类比的局限：**框架可以组织流程，但模型输出质量、接口权限与真实系统可靠性仍需单独验证。

## 3. 技术原理与核心内容

将模型、工具和上下文封装为可组合对象；执行器按控制流调度调用；callback/trace 收集输入、输出与错误。选型需要核对异步执行、流式传输、状态存储、错误传播与可测试性。

## 4. 工程实践与设计权衡

为客服 Agent 评估两套框架，构造相同的 50 个离线任务，比较成功率、工具调用次数、冷启动与调试性。可用极简自建循环作为基线，避免抽象过度。

## 5. 关联知识与易混辨析

Framework 是开发接口；Runtime 是实际执行/调度环境；SDK 可能只提供其中部分能力。

## 6. 中等难度面试题（含参考答案）

1. **问：如何避免对单一框架形成锁定？** 答：模型/工具协议放在适配层，业务状态使用可迁移结构，保留端到端回归样本；评估导出 trace 和替换执行器成本。
2. **问：框架自动重试有哪些风险？** 答：重复写工具可能发送两次消息或扣款；按幂等性区分失败并确认外部状态，不把框架默认策略当业务保证。

## 7. 中等难度考试题（含解析）

1. **题：题设每项任务使用框架 A 平均 5 次模型调用，B 平均 4 次，100 项任务少多少次？** 解：少 100 次模型调用（500-400）；不能由此断定 B 更便宜，仍需比较每次 token、成功率与基础设施。
2. **题：为什么 SDK 有 trace 就不代表具备完整可观测性？** 解：trace 只是观测数据；还需端到端关联、脱敏、留存、采样、告警及审计策略。
