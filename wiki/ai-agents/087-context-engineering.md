# Context Engineering（上下文工程）

> AI Agents · 专题：上下文、记忆与状态 · 适用范围：通用模型与智能体工程；产品能力以服务文档为准

## 1. 核心定义

**Context Engineering（上下文工程）**：Context Engineering（上下文工程）是针对模型的当前任务，设计、筛选、组织、维护并在多轮交互中更新有效输入信息的系统工程，包括指令、检索证据、工具定义、历史压缩、短期状态和相关记忆。

**适用边界：**它比 Prompt Engineering 范围更广，不是单纯添加提示词。上下文选择依赖任务、数据来源、容量和安全策略；上下文完整性与模型事实正确性仍需独立评估。

## 2. 形象理解

像科学实验的工作台管理：不仅写实验步骤，还要备好准确样本、仪器说明、实时读数和必要的历史记录。

**类比的局限：**工作台布置得再合理，错误的样本来源或仪器校准仍会导致错误结论。

## 3. 技术原理与核心内容

按需构建 `C_t = select(instructions, task_state, retrieved_evidence, memory, tool_schemas)`，目标是在 token/延迟预算下优化相关证据覆盖和可执行性。常用手段包括检索、窗口化、摘要压缩、将长工具输出放到外存、显式保留未完成任务和授权状态、失败时重新取原文。必须为动态注入信息记录 provenance 与 trust level。

## 4. 工程实践与设计权衡

**工程案例：**代码升级 Agent 在每次测试失败后只追加关键错误堆栈和受影响文件片段，把长历史日志写入可检索存储；需要完整栈时按文件定位回读。系统规则和待批准的写操作不能被自动摘要删除。

**失败模式与验证：**把不断增长的工具输出直接追加会挤掉问题约束；把有错误的摘要固化为真实状态会持续传播。通过长任务回归集，分别测任务成功、关键事实遗失率、token 量、时延和注入拦截。

## 5. 关联知识与易混辨析

Prompt Engineering 优化指令与示例的表达；Context Engineering 管理所有进入推理输入的内容和生命周期；Memory Retrieval 是其中一个供给机制。

## 6. 中等难度面试题（含参考答案）

1. **问：多轮 Agent 为什么需要动态重建上下文，而不只修改系统提示？** 答：目标、状态、工具结果和相关证据每轮变化，重要资料应按需要重新筛选和补全，同时守住容量和权限边界。
2. **问：何时适合把长工具返回写入外部存储？** 答：大结果不需每轮全量使用时，保存原文引用与版本，注入短摘要或最相关片段，避免成本上升和上下文被挤占。

## 7. 中等难度考试题（含解析）

1. **题：原上下文 7000 token，经去重与压缩保留 4200 token，减少比例是多少？** 解：(7000−4200)/7000=40%；是否合理仍需测关键事实覆盖与任务正确率。
2. **题：两个配置 A/B 分别花费 0.08/0.06 元，成功率 82%/80%。能直接说 B 更好？** 解：不能，需明确质量/成本目标、样本数与统计不确定性，并确认 B 未丢关键约束。
