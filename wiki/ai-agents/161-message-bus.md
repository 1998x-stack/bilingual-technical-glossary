# Message Bus（消息总线）

> AI Agents · 专题：多智能体协作 · 多 Agent 通信、一致性与独立业务验收

## 1. 核心定义

**Message Bus（消息总线）**：Message Bus（消息总线）是在多个 Agent、工具或服务之间发布、传送并路由事件/消息的中间基础设施。它使发送者和接收者在时间与部署位置上部分解耦，可支持任务派发、进度通知和异步结果收集。

**适用边界：**消息总线并不保证自然意义上的 exactly-once 业务副作用，也不能替代授权和任务验收。不同实现的持久化、顺序、订阅、确认及重试语义不同，不能把 Kafka/NATS 的所有能力当成通用默认。

## 2. 形象理解

像有分拣规则的快递中心，寄件人交付带地址和单号的包裹，分拣系统投递到目标收件点。

**类比的局限：**包裹签收只是交付状态，里面写的‘已付款’不证明真实资金结算；重复包裹也可能出现。

## 3. 技术原理与核心内容

定义 message envelope={message_id,topic,producer,tenant,task_id,correlation_id,created_at,attempt,payload_ref}。生产者发布事件，订阅者根据主题和身份消费，ack/offset 管理处理进度；消费者以业务 ID 去重，失败可退避重试或进入 dead-letter queue。Kafka 的分区顺序只在特定分区内保证；对跨主题的整体顺序需额外协调。

## 4. 工程实践与设计权衡

**工程案例：**多 Agent 代码审核系统由构建 Agent 发布 build.finished 事件，安全扫描订阅后检查同一 commit SHA，汇总器按 task_id 聚合。若扫描消息重复交付，不能因此重复计数漏洞或再次部署。

**失败模式与验证：**订阅权限配置过宽、重复交付造成双写、积压导致引用旧版本、缺 correlation_id 导致结果错配。用断线恢复、重复事件、延迟消息、死信和租户隔离负向测试验收。

## 5. 关联知识与易混辨析

Message Bus 是通信基础设施；Inter-Agent Communication 是跨主体交换数据的过程；Shared Memory 是共同可读写状态；Handoff 改变活跃 Agent 控制权。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么消息总线存在消费确认仍需业务幂等？** 答：消息重试或消费者崩溃可能导致重复执行，ack 只说明消息处理进度，不保证外部支付/部署只发生一次。
2. **问：Kafka 分区内有序能证明多个分区事件的全局顺序吗？** 答：不能。跨分区或跨主题需额外事件时间、业务序列号或协调约束。

## 7. 中等难度考试题（含解析）

1. **题：发送 100 条不同任务消息，有 8 条重试产生重复回执，收到 108 条，应该统计多少个唯一任务？** 解：去重 message_id/task_id 后仍是 100 个。
2. **题：20 条待处理消息，消费者每秒稳定处理 5 条且无新到达，清空最短多久？** 解：20/5=4 秒，忽略启动和排队开销。
