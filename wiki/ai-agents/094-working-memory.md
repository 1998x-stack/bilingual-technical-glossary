# Working Memory（工作记忆）

> AI Agents · 专题：上下文、记忆与状态 · 通用会话与记忆工程；具体框架行为以对应文档为准

## 1. 核心定义

**Working Memory（工作记忆）**：Working Memory（工作记忆）是 Agent 为完成当前步骤或当前任务，主动保留并随执行更新的高相关信息集合，例如当前目标、活动约束、最新观察、局部计划和暂时计算结果。它在概念上类似‘正在使用的工作台’，不必是某个特定 SDK 的独立存储模块。

**适用边界：**工作记忆强调当前任务的有效可用信息，而非跨会话持久性。某些实现把它组织为上下文片段、状态对象或短期缓存；与 Short-term Memory 的界限在产品实践中可能重叠。

## 2. 形象理解

像心算时脑中暂时记住中间进位和待计算数字；完成这道题后不必永久保存每个中间步骤。

**类比的局限：**人类工作记忆类比不表示模型内部一定有可读、持久的记忆系统；输入上下文和外存机制才是工程可控对象。

## 3. 技术原理与核心内容

以任务相关性为基准维护 W_t={goal,current_constraints,recent_evidence,intermediate_results,pending_ids}，每次工具返回后增删内容。通过优先级、TTL 和 token 预算决定哪些进入下一轮模型上下文。涉及交易 ID 与权限的硬约束应保存在结构化状态，工作记忆只持有其引用，避免超限时丢失。

## 4. 工程实践与设计权衡

**工程案例：**数据清洗 Agent 当前正处理第 12 张表，工作记忆保存列映射、异常计数和下一步核验任务；历史全量数据存外部文件，不必每轮重新输入全部行。

**失败模式与验证：**过量历史污染当前关注点、忘掉未解决依赖、把草稿推断作为已验证事实。评估时观察任务完成率、关键变量遗失率、对话长度和工具调用成本。

## 5. 关联知识与易混辨析

Working Memory 是眼前任务需要的活跃信息；Short-term Memory 更强调近期会话信息的保存周期；Context Window 是模型一次推理的容量，不能直接当成工作记忆机制。

## 6. 中等难度面试题（含参考答案）

1. **问：工作记忆与模型 Context Window 有什么区别？** 答：前者是工程上有意识维护的任务相关内容，后者是模型一次调用可处理的容量上限；工作记忆可能存外部、只选择部分注入。
2. **问：哪些状态不能因为工作记忆空间不足而直接丢弃？** 答：未完成交易 ID、用户授权、关键业务约束与已确认外部副作用，应独立持久化或保留可恢复的可靠引用。

## 7. 中等难度考试题（含解析）

1. **题：当前任务可用 1600 token，系统与约束占 600 token，每个观察片段 250 token，最多容纳几个完整片段（忽略其他成本）？** 解：余量 1000 token，最多 1000/250=4 个完整片段。
2. **题：处理 20 个文件，工作记忆只记录当前文件号 12 和摘要，能否推出前 11 个已通过验收？** 解：不能；需读取权威进度/检查点记录，当前文件号不能单独证明之前每个文件成功。
