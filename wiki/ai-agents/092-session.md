# Session（会话）

> AI Agents · 专题：上下文、记忆与状态 · 通用会话与记忆工程；具体框架行为以对应文档为准

## 1. 核心定义

**Session（会话）**：Session（会话）是为一段连续或可恢复的 Agent 交互划定的逻辑边界，可关联会话标识、历史记录、状态、用户/租户权限及生命周期。Session 可以跨越多次模型调用和工具执行，但不必永久存在。

**适用边界：**会话 ID 本身并不等于身份认证；不同 SDK 的 session 对历史保存、并发、过期和压缩支持各不相同。客户端请求结束也不一定意味着会话持久记录立刻消失。

## 2. 形象理解

像医院一次持续的就诊流程：有单号、检查结果和医生交接，患者下次复诊可在授权范围内继续。

**类比的局限：**就诊单号不能代替患者身份认证，也不能让同一单号里的旧体温变成实时读数。

## 3. 技术原理与核心内容

在会话创建时绑定 trusted_user_id、tenant_id 和 session_id，并由后端存储消息、关联事务/任务状态。下一轮运行器从会话存储取回必要历史，再构造模型上下文；请求完成后保存新事件。并发访问需版本号或序列化顺序，配置 retention/TTL 和数据删除策略。对跨设备恢复和中断后继续运行，必须保持业务动作的执行台账独立可信。

## 4. 工程实践与设计权衡

**工程案例：**技术支持 Agent 第一天记录故障 ID、日志引用和计划，第二天用户回来时通过其授权会话继续；设备已修好与否由监控接口验证，而不是仅依据上一次对话结论。

**失败模式与验证：**会话固定不等于无限记忆；过期数据、跨租户 ID 猜测、并发两轮互相覆盖状态，都会导致错误。通过隔离、竞态、过期和会话恢复测试保障正确性。

## 5. 关联知识与易混辨析

Session 是交互范围/生命周期；Conversation History 是其中保存的事件；Session State 是当前运行变量；Long-term Memory 可在授权前提下跨多个 session 共享。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么不能把 session_id 当作唯一授权凭证？** 答：标识符可泄露或猜测，读取会话前必须验证可信身份、租户和对象归属，不能只凭前端传入的 ID。
2. **问：两个并发请求修改同一会话状态怎样防止覆盖？** 答：使用乐观并发版本、事务锁或串行执行，同步不可重复副作用的请求 ID，并处理冲突重试策略。

## 7. 中等难度考试题（含解析）

1. **题：A 会话保留 7 条记录，B 会话保留 9 条；它们逻辑隔离，各自查询应返回几条？** 解：A 只能返回其授权范围 7 条，B 返回 9 条；不能因为合计 16 条就混在一个上下文里。
2. **题：Session 设置保留期 24 小时，距最后活动 26 小时且无延长策略，能依赖旧会话必然继续吗？** 解：不能；按题设它应已过期或进入清理，需重建或通过允许的持久存储恢复必要状态。
