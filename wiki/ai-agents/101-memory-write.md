# Memory Write（记忆写入）

> AI Agents · 专题：上下文、记忆与状态 · 适用范围：系统架构与可靠性工程；具体实现以引用的版本和产品为准

## 1. 核心定义

**Memory Write（记忆写入）**：Memory Write（记忆写入）指将新信息经筛选、核实与授权后保存进 Agent 可重用的存储系统，使其能在后续任务或会话中被安全检索。它是独立的数据治理操作，不是每次模型说“我记住了”就真的发生持久化。

**适用边界：**候选事实不等于已验证事实，用户即时请求不等于长期偏好。跨会话持久信息必须有明确的来源、所有者、敏感级别、生效期限和删除方式；具体产品是否自动记忆须看其实现与权限。

## 2. 形象理解

像向团队知识库添加一条经验：先核对是否真实、是否适用，再登记作者、日期与版本，而不是把聊天记录整篇复制。

**类比的局限：**知识库有写入记录不代表新知识永远正确，也不代表任何人都有阅读它的权限。

## 3. 技术原理与核心内容

设计写路径 `candidate → classify → consent/policy check → validate → deduplicate → store → index → verify`。记录 `{memory_id,owner,namespace,type,value,source,valid_from,expires_at,version}`；对同一对象的更新采用 CAS 或事务，防止并发覆盖。检索索引的更新与主存要有一致性策略；写入失败不得谎称保存成功。对无法证实的用户属性用待确认状态或不写入。

## 4. 工程实践与设计权衡

**工程案例：**售后 Agent 想保存客户‘偏好周末联系’，先确认是明确表达还是临时约定，并按授权范围记录；后续营销或其他用户场景不能自动使用。订单退款的结果由交易系统核对后可存为事件引用，不能从模型总结推断‘已到账’。

**失败模式与验证：**未经确认写入永久偏好、错误摘要成事实、跨租户空间污染、主存写成功但索引缺失。测试应覆盖授权拒绝、并发更新、删除后的不可召回及写入前后检索一致性。

## 5. 关联知识与易混辨析

Memory Write 是写入/更新知识的流程；Memory Retrieval 是受控读取；Memory Consolidation 将多条既存记录提炼；Session State 是运行态控制信息，未必应写为长期记忆。

## 6. 中等难度面试题（含参考答案）

1. **问：对话里出现‘我今天想喝咖啡’，可直接写成用户永久喜好吗？** 答：不能。它可能是临时意图；应考虑用途、明确性和用户允许的范围，避免把单次行为归纳为永久偏好。
2. **问：主数据库写入成功、向量索引更新失败，应如何处理？** 答：记录部分完成并进入重建/重试索引流程，查询侧避免过时读取，不能对用户声称所有检索路径已生效。

## 7. 中等难度考试题（含解析）

1. **题：20 条候选记忆中 4 条无授权、3 条重复、2 条证据不足且互不重叠，可进入新写入队列几条？** 解：20−4−3−2=11 条；仍需通过最终数据库写入与一致性验证。
2. **题：两次并发更新都以 version=7 写入，A 已成功升到 8，B 应怎么办？** 解：B 的条件更新应失败或提示冲突，重读新状态后判断是否重新提交，禁止静默覆盖。
