# Workflow（工作流）

> AI Agents · 专题：工作流与编排模式 · 此篇区分通用计算机科学术语与具体 Agent 实现版本

## 1. 核心定义

**Workflow（工作流）**：Workflow（工作流）是按一组明确的任务步骤、控制条件、输入输出契约与状态转换组织执行的过程。基于 LLM 的工作流常将模型调用、工具、校验和人工审批编排为固定或有条件的执行图。

**适用边界：**Workflow 与自主 Agent 不是同义词：前者通常由程序预定义路径，后者可能由模型根据环境动态决定步骤。工作流中使用 LLM 或工具并不自动意味着拥有自主决策权限。

## 2. 形象理解

像工厂流水线：先验材料、再装配、再质检；若质检不合格可以进入返工分支，但不能跳过安全门控。

**类比的局限：**模型输入有随机性，工具服务有网络故障，实际工作流不一定像机械流水线那样确定和完全可逆。

## 3. 技术原理与核心内容

表示为节点集合 V、边 E 和共享状态 S。节点输入满足前置条件后运行，输出写入经校验的状态，再根据固定或条件边推进；需要终止状态、超时、重试、审计、checkpoint 与部分失败处理。Anthropic 将预定义代码路径的 workflows 与模型动态驱动的 agents 区分；实际工程可以混合两者，例如审批外壳固定、研究步骤由模型探索。

## 4. 工程实践与设计权衡

**工程案例：**财务报销工作流顺序执行 OCR 提取、金额验证、费用类别判定、人工审批与提交；把提交设置为受控写节点，只有前置校验和真实权限齐全才能执行。失败后保留请求 ID，避免重试造成双付款。

**失败模式与验证：**数据依赖未满足时错误并行、模型说成功就跳过业务验收、循环无上界、长流程中断后重复外部写入。用状态机、故障注入、审计 trace 和浏览器 E2E 验证所有条件分支。

## 5. 关联知识与易混辨析

Workflow 指明确的执行过程；Agent Orchestration 是协调实现；Control Flow 决定运行顺序；Data Flow 决定信息怎样在节点间传递；DAG 仅适用于无环依赖结构。

## 6. 中等难度面试题（含参考答案）

1. **问：什么时候更适合固定 workflow 而不是完全自主 Agent？** 答：当步骤可明确分解、风险可控且可测试时，固定流程更容易预测时延和强制审批；开放式研究可采用受限动态子流程。
2. **问：为何工作流的‘节点执行结束’不能自动等于业务完成？** 答：工具可能异步、失败或未知，须单独验证后置条件与权威状态，再进入成功终态。

## 7. 中等难度考试题（含解析）

1. **题：流程 A=2min、B=3min、C=5min 严格串行，总时长？** 解：2+3+5=10min，不含网络排队与人工审批。
2. **题：同一工作流包含‘查询账户’与‘提交退款’，后者是否应仅凭模型文本进入？** 解：不应，须服务端验证账户归属、金额、审批与幂等状态。
