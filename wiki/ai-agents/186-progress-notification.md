# Progress Notification（进度通知）

> AI Agents · 专题：MCP：模型上下文协议 · MCP 2026-07-28 及兼容边界；示例数字为教学题设

## 1. 核心定义

**Progress Notification（进度通知）**：Progress Notification（进度通知）是 MCP 在执行耗时请求时向调用者报告任务处理进展的机制，使 Host 展示正在处理的阶段而非一直空白。它传递运行观测，**不是**结果完成证据，也不能单独用于发起有副作用的新工具动作。

**适用边界：**不同协议版本与传输绑定的进度路由不同：新版本应遵循请求范围内通知与声明的进度标识，不能假设服务端存在可无限推送的全局会话。进度值可能未知或不是线性增长，后端必须明确单位。

## 2. 形象理解

像外卖订单显示‘正在备餐、配送中’，进度让人理解当前阶段，但‘90%’不等于已经送达。

**类比的局限：**某些阶段需要外部批准，进度百分比可能只是估计；后端是否成功仍需权威终态。

## 3. 技术原理与核心内容

客户端在请求中声明 progressToken，服务端按协议返回 `notifications/progress` 类型消息，参数可包括 progress、total、message 等，与具体请求 ID/令牌绑定。Host 按业务任务 ID 存储阶段进度，展示最新消息时避免旧通知覆盖新结果。若总量未知不应计算错误百分比，若 total>0 且 progress=30、total=100，显示为 30%，而非把进度当真实答复。

## 4. 工程实践与设计权衡

**工程案例：**知识库 MCP Server 对 1000 份文档建立索引，在同一工具请求的 SSE 流中显示已完成文件数及失败条目。用户看到 100% 后仍须等待工具返回 `success` 和索引版本号；有部分失败则展示 partial。

**失败模式与验证：**乱序事件让进度倒退、把 progress=100% 当数据已持久化、断线时通知丢失、没有限制通知数量造成 UI 卡顿。对重连、重复、无效 total 和取消后进度更新作测试。

## 5. 关联知识与易混辨析

Progress Notification 反馈当前运行情况；A2A Streaming Update 表示另一个协议的任务事件；Checkpoint 是可恢复的状态快照；Task State 是生命周期状态。

## 6. 中等难度面试题（含参考答案）

1. **问：工具报告 progress=100 是否可以直接提交后续付款？** 答：不可以。它不是业务成功证明，需要独立的工具完成结果与服务端事务核验。
2. **问：为什么客户端必须用令牌或请求 ID 关联进度？** 答：多个并发任务的通知会交错，按到达顺序渲染可能把 A 的进度显示到 B 上。

## 7. 中等难度考试题（含解析）

1. **题：已处理 300 个文件，预计总共 1200 个，进度百分比？** 解：300/1200=25%，前提 total 真实有效。
2. **题：任务 A 的事件 task_id=12 却显示在 task_id=13 页面，应怎样处理？** 解：拒绝关联错误的通知，按 ID 路由并记录异常。
