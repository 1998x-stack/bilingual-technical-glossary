# JSON Schema（JSON 模式）

> AI Agents · 专题：开发实践与生态术语 · 结构化能力、工具契约与执行安全

## 1. 核心定义

**JSON Schema（JSON 模式）**：JSON Schema 是描述 JSON 实例形状与约束的标准体系，可用于 Agent 工具参数验证、结构化输出与数据契约。当前正式发布的 Draft 2020-12 区分 Core 与 Validation 语义，不应把 JSON Schema 当作任意业务逻辑或授权系统。

**适用边界：**通用术语与特定规范的关系需分别确认。MCP、Agent Skills、JSON Schema 等有各自版本与作用域，不能把某个宿主的实现行为假定为标准要求。读取声明、通过校验和产生外部业务结果是不同的阶段，不可一概称为“执行成功”。

## 2. 形象理解

**类比：**像海关申报表的机器可读检查规则，规定哪些栏位必须填、填何种类型。

**类比的局限：**真实 Agent 还涉及权限、分布式网络、模型选择与动态状态，直观比喻没有完整表达数据流和并发失败。即使一个参数格式合法，也不表示执行主体有权读取/写入相应资源。

## 3. 技术原理与核心内容

常用关键词 `type`、`properties`、`required`、`enum`、`minimum`、`items`、`additionalProperties`、`oneOf`。`properties` 不自动使字段必填，需 `required`；`additionalProperties` 默认允许额外属性。Draft 2020-12 的 `format` 通常作为 annotation，是否执行强校验取决于 validator 的方言/配置，不能假定 `format: email` 一定会拒绝所有非法邮箱。

**可信执行边界。**Schema、Instruction File、Tool Manifest 和 Skill 文件都属于声明/约束信息，无法直接证明数据真实、调用被授权或外部动作已成功。Agent 应按照可信用户授权、宿主执行策略、工具后端 ACL 和真实业务状态分别检查；外部工具说明与文件内容必须保持低信任。读取一个 Skill 或发现一个 Tool 不意味着可以运行敏感脚本，参数形状校验更不能代替付款/删除等操作的服务端鉴权。

**实施步骤：**确定用户目标与可用资源→解析声明和规范版本→匹配技能/工具→校验具体输入及其来源→应用后端权限与业务规则→记录后置状态。对外部脚本设置沙箱、网络出口和秘密隔离；对工具输出保留来源标签，阻止提示词注入跨越数据/指令边界。

## 4. 工程实践与设计权衡

**工程案例：**工具 schema 定义 `recipient_id` 为 string、`amount` 为 number 且 minimum:0、`currency` 为 enum；校验通过仅说明结构合规，实际付款需按用户身份和账户状态授权。

**工程化检验。**用受控案例覆盖版本升级、缺字段、类型错误、未知字段、工具动态更新、技能投毒、未经授权资源访问以及调用超时。要记录真实的 validator 输出、工具执行日志和权威后置状态，而非只看模型说“格式正确”。将 Schema 规范版本与宿主/SDK 版本固定在测试配置，避免不同 validator 方言造成静默差异。每个练习计算的数量都是教学假设，不代表行业覆盖率。

**设计取舍：**严格 schema 和最小工具能力能降低误用风险，但对旧客户端的兼容性、动态发现与维护成本有影响。需明确版本迁移、allowlist、错误信息及回退策略，保证正常任务仍能完成而不会因模糊约束绕开权限。

## 5. 关联知识与易混辨析

JSON Schema 是模式定义的一种表示法；JSON 是数据交换格式。Function Calling 的 schema 验证属于参数形状约束，不代表权限校验或外部副作用已成功。

实践时要区分“静态描述”“动态发现”“真正的调用”和“业务写入确认”。通用 Schema 可选择多种语言，JSON Schema 是其中一种；Skill 说明文件和工具注册元数据也不具备后端的认证授权能力。

## 6. 中等难度面试题（含参考答案）

1. **问：`properties` 中列出的字段为什么仍可能被遗漏？** 答：默认并不必填，必须在 `required` 数组中声明；还要处理 null 与缺字段的区别。
2. **问：`additionalProperties:false` 是否在任意 allOf 组合中都能按直觉工作？** 答：不一定，跨 subschema 时涉及关键字评估作用域；要理解 Draft 2020-12 的 unevaluatedProperties 或按同一层声明。

面试答案应给出具体规范关键词、版本边界、危险反例与可执行的后端控制，不能仅把“Schema 校验通过”当成安全结论。

## 7. 中等难度考试题（含解析）

1. **题：对象 schema 有 properties x,y，required 只含 x，实例只有 x 是否合规（其他条件均满足）？** 解：合规；y 在 properties 中但不属于 required，不应错误拒绝。 计算或判断的假设由题设明确，须给出完整推理。
2. **题：若 schema 使用 `type:number`，实例是字符串 `"5"`，是否合规？** 解：不合规。字符串和 number 类型不同；除非外层业务显式转换，标准验证不会擅自转换。 要区分结构校验和真实业务授权，不能把格式错误自动转换为合法数据。
