# Long-term Memory（长期记忆）

> AI Agents · 专题：上下文、记忆与状态 · 概念与实际框架行为以来源和版本为准

## 1. 核心定义

**Long-term Memory（长期记忆）**：Long-term Memory（长期记忆）指 Agent 在多个任务或会话之间持久保留、可以按权限再次召回的信息，包括已核实的事实、稳定偏好、情景经验与操作策略。它通常依赖数据库/索引，而非无限扩大单次模型上下文。

**适用边界：**跨会话保存不表示无限期保留；数据授权、用途限定、撤回、删除、时效和跨租户隔离是必要条件。不能把模型推测直接写成用户的永久事实。

## 2. 形象理解

像维护团队知识库，保存可复用的标准、经验和常见问题的处理依据。

**类比的局限：**旧知识可能因制度或系统版本改变而失效，长期保存不等于永久正确。

## 3. 技术原理与核心内容

可建立 candidate → privacy/consent filter → source verify → store(namespace,owner,version,expiry,provenance) → retrieve → revalidate 的流程。语义事实、经历、操作模板分别存储并建立索引；更改记忆时保留版本与来源，必要时撤销相应索引。业务权限和实时状态以权威系统为准。

## 4. 工程实践与设计权衡

**工程案例：**客服 Agent 经用户授权记住其沟通语言偏好，下次允许继续使用；但报销限额必须按最新正式制度检索，不能凭两年前的历史记忆直接批准款项。

**失败模式与验证：**错误记录跨会话重复污染、索引已删主存仍可召回、跨租户资料串线和对敏感事实过度推断。评估持久正确率、权限泄露率、过期内容命中率及用户纠正流程。

## 5. 关联知识与易混辨析

Long-term Memory 是跨任务/会话的持久知识；Short-term Memory 是近期线程范围；Conversation History 是事件日志；Context 是当轮模型实际接收的内容。

## 6. 中等难度面试题（含参考答案）

1. **问：为何不应把一次聊天中模型推断出的偏好自动当永久事实？** 答：可能只是临时需求或错误推断，需要可信来源、适用范围、授权及纠正/删除通道。
2. **问：长期记忆中的旧财务制度能直接用于操作吗？** 答：不能。先核对当前有效版本与审批政策；旧记录只作为查找依据。

## 7. 中等难度考试题（含解析）

1. **题：120 条记忆中有 90 条已验证，其中 18 条过期且包含在已验证集合内，当前有效已验证比例？** 解：有效 90−18=72 条，占总量 72/120=60%。
2. **题：用户撤回一条私人记忆，但向量搜索仍能召回，是什么故障？** 解：存储删除和索引同步/权限屏蔽未完成，需阻断该记录的召回并核验删除传播。
