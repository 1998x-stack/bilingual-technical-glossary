# Reasoning Model（推理模型）

> AI Agents · 专题：模型能力与推理 · 通用概念；产品特性以文档版本和模型接口为准

## 1. 核心定义

**Reasoning Model（推理模型）**：Reasoning Model（推理模型）是针对多步推断、复杂问题分解、规划和工具使用等任务优化的模型或推理配置。相对直接回答，它可能在输出前执行额外内部推断步骤，利用更多推理阶段的计算与 token。

**适用边界：**并无跨所有提供商的唯一架构定义；模型能力、推理预算及是否暴露推理内容均由模型/API 决定。

## 2. 形象理解

像解复杂数学题时会先检验条件和方案的学生，而不是仅凭第一印象作答。

**类比的局限：**“想得更久”不保证答案更正确，内部推理也不一定完整或可供外部审计。

## 3. 技术原理与核心内容

模型在上下文中基于输入形成中间推断并生成结果；部分 API 的内部 reasoning token 计入输出用量与上下文，却不向调用方显示原始内容。可将推理预算作为质量与延迟间的可调参数，但支持的档位、计费口径因模型而异。评测时需固定样本集、解码与工具环境，不能仅比较示例题。

## 4. 工程实践与设计权衡

**工程案例：**复杂代码变更 Agent 可在高难任务使用更高推理预算，在确定性格式化任务使用低预算；以测试通过率、回归数、端到端时延和用量对比，逐题分配预算而不是一律最大化。

**失败模式与验证：**常见误区是把推理模型等于可证明推理、将高预算等于稳定正确，以及假设长思维记录都可被应用日志获取。应对关键结论运行独立验证器。

## 5. 关联知识与易混辨析

Reasoning Model 是模型/配置能力；Inference-time Compute 是调用时花费的计算量；Test-time Compute 是为了提高结果质量而额外安排的推理阶段计算策略。

## 6. 中等难度面试题（含参考答案）

1. **问：推理模型在 Agent 中何时值得更高预算？** 答：多步依赖、失败代价较高且能够验证答案时值得试验；做固定字段抽取可能延迟和成本损失大于收益。用相同任务集测成功率、成本和 P95 时延。
2. **问：如何检验模型的推理结果，而不依赖暴露内部思维？** 答：对结构化答案运行规则校验，代码跑单测，数学独立重算，外部操作读权威状态；把可验证结论与隐藏的推理过程分离。

## 7. 中等难度考试题（含解析）

1. **题：题设普通模型每次 1.0 s、成功率 70%，推理配置每次 1.8 s、成功率 84%，两者成功率差是多少百分点？吞吐比（相同串行条件）？** 解：差 14 个百分点；串行吞吐近似从 1/1.0=1 次/s 降到 1/1.8≈0.556 次/s。不能从这一题设推断实际模型性能。
2. **题：为什么一个推理模型回答数学题正确不能说明退款 Agent 可靠？** 解：数学正确率是局部模型能力；退款系统还依赖权限、工具参数、幂等性、事务状态和故障恢复，需要端到端场景测试。
