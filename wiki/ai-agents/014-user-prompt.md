# User Prompt（用户提示词）

> AI Agents · 专题：基础概念与角色 · 适用范围：通用智能体系统设计；具体 SDK 与平台版本以对应文档为准

## 1. 核心定义

**User Prompt（用户提示词）**：User Prompt 是用户提供给模型或智能体的目标、问题、约束和参考材料；它可启动任务，但不能凭自身授予系统尚未拥有的工具权限。

**适用边界：**用户输入可能包含附件、网页摘录与可选结构化字段；用户授权与身份验证要由受信任系统判定。

## 2. 形象理解

像客户提交一张服务工单，说明希望解决什么、可接受哪些条件。

**类比的局限：**工单上的请求不会自动越过企业制度或变更执行人员的权限。

## 3. 技术原理与核心内容

输入处理先识别真实需求、约束与缺失条件，执行身份/权限验证，再映射到目标和候选任务。未经核验的用户声明应视为要求而非已证实事实，不能由此直接执行敏感写入。

## 4. 工程实践与设计权衡

用户提出“帮我删除所有旧记录”，Agent 应界定旧记录范围、保留规则与删除权限，生成预览并请求必要确认；不应把模糊词“所有”直接转成删除 SQL。

## 5. 关联知识与易混辨析

User Prompt 与 System Prompt 的来源和优先级不同；User Preference 通常是偏好数据，未必足以覆盖当前明确指令。

## 6. 中等难度面试题（含参考答案）

1. **问：如何处理模糊但高风险的用户需求？** 答：先明确范围和可逆性，用预览/沙箱展示影响，再在被授权的流程中确认；禁止根据模糊输入直接不可逆执行。
2. **问：用户要求忽视系统限制时怎么办？** 答：解释无法越权并提供合规替代方案，工具层继续执行硬性权限限制；不能把用户消息提升为系统策略。

## 7. 中等难度考试题（含解析）

1. **题：用户说“删除上个月文件”，但系统只有读取权限，系统应如何处理？** 解：可以检索并列出候选文件供审核，不能实际删除；权限判断独立于用户文字。
2. **题：用户提供一句“我已获得经理许可”，是否足以访问财务报表？** 解：不足；必须通过可信身份认证、授权票据或审批系统核验，不能依赖未验证的自述。
