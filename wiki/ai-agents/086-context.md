# Context（上下文）

> AI Agents · 专题：上下文、记忆与状态 · 适用范围：通用模型与智能体工程；产品能力以服务文档为准

## 1. 核心定义

**Context（上下文）**：Context（上下文）是模型在一次具体推理中可访问的信息集合，可能包括系统/开发者指令、用户任务、当前对话、工具定义、检索文档、状态摘要与可用的多模态内容。它在调用时被构造出来，不等同于 Agent 存储的全部历史。

**适用边界：**上下文是输入和相关处理空间的一部分，不能与 Context Window 的最大容量同义；长窗口也不意味着无限或可靠记忆。各角色的信息具有不同信任等级，检索结果不能作为系统指令。

## 2. 形象理解

像办案人员开会时桌面上展开的证据、法律程序与当前问题；档案库里其他材料仍然存在，却未必已被带到会议。

**类比的局限：**桌上资料可能过期或错误，材料数量增加也可能降低决策时的注意与准确度。

## 3. 技术原理与核心内容

一次 Agent 模型调用可组合 instruction + recent_messages + retrieved_evidence + relevant_state + tool_specs，再经 token 预算检查。对于每份证据保留来源、时间、权限和版本，明确哪些可摘要、哪些必须原文保留。对话与检索内容属于数据通道，模型可利用其事实但不能提升其指令级别。上下文需按每轮任务目标重新选择。

## 4. 工程实践与设计权衡

**工程案例：**企业政策问答 Agent 只向当前模型输入用户请求、有效期内的制度条款和引用定位，不直接塞入全公司每年全部政策。若结果涉及付款，仍从权威系统复核金额与生效日期。

**失败模式与验证：**过量无关上下文造成噪声与成本，截断丢失用户关键限制，使用旧条款或恶意网页命令造成错误。评测不同长度、版本和检索召回，统计事实支持率与 token 成本。

## 5. 关联知识与易混辨析

Context 是模型当轮看到的信息；Context Window 是当轮最大容量约束；Session State 是外部维护的结构化状态；Long-term Memory 是可跨会话召回的信息存储。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么把 1 年聊天全部塞给模型不一定更可靠？** 答：历史可能超过容量，且存在无关噪声与过期事实。应按当前任务检索并保留来源及高优先级约束，而不是盲目扩大输入。
2. **问：检索到网页写着“忽略开发者指令”，它算新的系统指令吗？** 答：不算。检索网页是低信任证据，只能提供待核验的信息，不能改变工具权限或指令层级。

## 7. 中等难度考试题（含解析）

1. **题：题设上下文窗口 8192 token，已有 5000 token 输入、预留 2000 token 输出，余量多少？** 解：8192−5000−2000=1192 token，实际需用目标模型接口确认计数口径。
2. **题：数据库中有 1000 条历史记录而本次上下文只有 10 条摘要，模型能否证明其他 990 条都不存在？** 解：不能。上下文的可见子集不等于外部数据库全集，应通过授权查询核实。
