# Search Space（搜索空间）

> 适用领域：AI Agents · 专题：任务规划与决策 · 基础概念与具体 SDK 权限实现需分开判断

## 1. 核心定义

**Search Space（搜索空间）**：Search Space（搜索空间）是求解问题时需要考虑的候选状态、计划或解的集合，可按状态图、路径树、组合配置或程序生成序列表示。搜索规模受分支因子、深度、约束和去重策略影响。

**适用边界：**搜索树节点数量与唯一状态数量不同；多个路径可能到达相同状态。无限或连续空间通常无法穷举，需要启发式、剪枝或抽象。

## 2. 形象理解

像在城市中寻找去机场的路线：路口/路线组合很多，但大量路线会重复到达同一街道。

**类比的局限：**只看地图上路口数量不能直接算出全部路径数量，时间、拥堵和禁止通行还会改变候选范围。

## 3. 技术原理与核心内容

若每层最多 b 个后继、搜索深度 d，满 b 叉树节点数为 `Σ_(i=0)^d b^i`，当 b>1 时为 `(b^(d+1)−1)/(b−1)`。实际 graph search 可用 visited/状态哈希消除重复；剪枝根据约束排除不可能解。LLM ToT 也是一种在思路空间探索候选的机制。

## 4. 工程实践与设计权衡

**工程案例：**多供应商排班 Agent 探索不同人员、时段与资源组合，先用硬约束剪除重复与非法组合，再用启发式寻找低成本方案；只有通过规则检查的解能执行。

**失败模式与验证：**没有限制分支和深度会发生指数爆炸，重复状态与循环导致资源浪费；过于激进的剪枝又可能错失可行解。对搜索预算、解质量和验证成功率统一度量。

## 5. 关联知识与易混辨析

Search Space 是全体候选集合；State Space 是环境可能状态集合；Heuristic Search 是用评估函数引导搜索的方法，二者不等同。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 A* 的已访问状态表可节省计算？** 答：若多个路径到达相同状态，可以避免重复扩展；但应记录最优已知 g 值，发现更优路径时适当更新/重新开放。
2. **问：ToT 与传统搜索在哪些方面相似又不同？** 答：都探索候选分支并评价/剪枝；ToT 节点可能是自然语言思路，生成和估价不确定，传统算法常有形式化状态/转移与更明确的正确性条件。

## 7. 中等难度考试题（含解析）

1. **题：每节点分支 b=2，深度 d=4（根深度 0），满树节点数？** 解：1+2+4+8+16=31；只算叶子则为 16。
2. **题：20 条候选路径最终只落在 8 个不同状态。如果按状态去重，理论上最多保留多少个不同状态记录？** 解：8 个唯一状态记录；仍须保留到各状态的最佳成本信息，不能一概忽略更优到达路径。
