# Prompt Engineering（提示词工程）

> AI Agents · 专题：上下文、记忆与状态 · 适用范围：通用模型与智能体工程；产品能力以服务文档为准

## 1. 核心定义

**Prompt Engineering（提示词工程）**：Prompt Engineering（提示词工程）是围绕模型任务设计和改进指令、示例、输出约束、边界条件与交互方式的实践，以提高模型行为的一致性和任务完成率。它在 Agent 中承担清晰表达目标和规则的角色，但不替代外部系统权限。

**适用边界：**提示词技巧不保证跨模型、跨版本普遍有效；模型可以遵循格式却输出错误事实。涉及高风险动作时，工具白名单、授权和业务校验必须由执行器硬性实施。

## 2. 形象理解

像给新员工编写清晰的操作说明：说明目标、步骤示例、产出格式和异常处理方式。

**类比的局限：**说明书不等于员工拥有保险柜钥匙，也无法保证所有步骤被完美执行。

## 3. 技术原理与核心内容

将任务拆成角色/目标、可信输入、约束条件、成功定义、输出 schema 和少量高质量示例。通过固定任务集做版本 A/B 对比，评价正确率、格式遵循率、工具误用率、拒答和 token 成本；对模糊指令设反例与负向测试。外部文档或检索摘要应作为数据引用，不得直接当成可修改系统约束的指令。

## 4. 工程实践与设计权衡

**工程案例：**财务费用分类 Agent 提示明确：只有合理科目可输出、缺失票据请标记待核验、报销金额不可猜测。对合法 JSON 再跑会计科目规则和金额核对；若信息不足，返回结构化不确定状态。

**失败模式与验证：**以提示词禁止删库却保留真实删库权限、把某条示例过拟合到所有案例、长提示挤占证据、恶意工具输出诱使角色切换。上线前用对抗样本、版本回归及业务风险评测。

## 5. 关联知识与易混辨析

Prompt Engineering 更关注如何表达模型指令及示例；Context Engineering 同时决定哪些状态、记忆、证据、工具说明进入请求；Structured Output 负责结果格式契约。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 System Prompt 不能代替服务器端访问控制？** 答：模型指令不是安全边界，可能被误解或对抗输入影响；执行器应独立验证身份、资源范围和动作类型。
2. **问：如何证明提示词修改真正改善效果？** 答：固定同一任务集、模型与预算，采用可复核标签、对照实验和误差分类；只展示几条成功案例不足以证明。

## 7. 中等难度考试题（含解析）

1. **题：原提示方案 200 次中正确 150 次，改版正确 166 次，准确率提升多少百分点？** 解：原为 75%，新版为 83%，提升 8 个百分点。还需评估统计显著性和关键风险指标。
2. **题：提示要求“无法核实时明确说明”，模型却编造文献链接，是什么失效？** 解：事实性和引用支持检查失效，应由外部检索验证文献存在及断言，不是只增加一句强调。
