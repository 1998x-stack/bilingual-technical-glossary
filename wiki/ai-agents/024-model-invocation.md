# Model Invocation（模型调用）

> AI Agents · 专题：模型能力与推理 · 通用概念；产品特性以文档版本和模型接口为准

## 1. 核心定义

**Model Invocation（模型调用）**：Model Invocation（模型调用）是客户端向模型服务提交完整请求，并接收响应或错误的一次交互。请求通常包含模型标识、输入消息、输出格式、工具定义及预算等配置；实际计费/上下文口径由 API 决定。

**适用边界：**一次模型调用可能触发多个工具调用建议，也可能没有外部工具；流式输出仍属于对应的调用/响应生命周期。

## 2. 形象理解

像向一个计算服务提交作业：有入参、请求编号、超时、结果或错误，不能把“已请求”当成“已完成”。

**类比的局限：**模型回复成功不代表下游工具执行成功，也不保证返回内容满足业务规则。

## 3. 技术原理与核心内容

客户端 `serialize → validate → send → await/stream → inspect(status, usage) → parse/verify`。记录 request_id、模型版本、token 用量、超时和必要的 trace（注意敏感信息脱敏）。遇到网络超时或流中断，应按服务语义决定是否重试，勿把第二次模型输出与第一次外部副作用混为一谈。

## 4. 工程实践与设计权衡

**工程案例：**为报表自动化设计一层模型网关：统一参数白名单、并发限制、指数退避、结构化输出解析和日志关联；面向故障注入测试 429、5xx、断连、JSON 不完整与用户取消。

**失败模式与验证：**频繁分散调用会重复发送大量上下文；未检测 incomplete 状态可能消费到半截 JSON；忽略 usage 会低估费用。缓存请求/响应前先处理隐私与数据有效性。

## 5. 关联知识与易混辨析

Model Invocation 是一次 API 层交互；Agent Loop 是可能包含多次 invocation 和工具调用的控制过程；Tool Call 是模型提议的外部动作接口。

## 6. 中等难度面试题（含参考答案）

1. **问：流式输出遇到中断如何避免把半截内容写入数据库？** 答：汇集并检查响应完成状态，再做模式/业务验证，提交前采用事务或暂存机制；不要在接收每个 chunk 时直接执行副作用。
2. **问：如何定位模型调用延迟突然增长？** 答：拆分排队、网络、输入长度、首 token、输出长度、工具等待和重试成本；按模型版本与请求特征分析 P50/P95，而不是只看平均值。

## 7. 中等难度考试题（含解析）

1. **题：串行调用三次模型分别耗时 0.5、0.9、0.6 s，网络和工具另耗 0.4 s，总端到端时间？** 解：0.5+0.9+0.6+0.4=2.4 s；这是顺序执行的题设估算，不表示生产环境测量。
2. **题：一次响应 HTTP 200 但 `status=incomplete` 且 JSON 缺结尾括号，应存为成功结果吗？** 解：不应；必须检查模型响应完成标志、结构解析与业务约束；可按策略增大预算/重试或返回明确失败。
