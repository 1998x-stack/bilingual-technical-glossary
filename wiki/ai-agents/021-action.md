# Action（动作）

> AI Agents · 专题：基础概念与角色 · 通用概念；产品特性以文档版本和模型接口为准

## 1. 核心定义

**Action（动作）**：Action（动作）是 Agent 根据目标与状态选择的一次具体操作，可以是信息读取、模型内的下一步决策，也可以是向外部系统提交具有副作用的命令。动作是否真正发生，由运行器和环境反馈确认，而非由模型文字声明决定。

**适用边界：**动作是决策语义，不等于成功执行；同名工具在不同授权主体下也可能不可用。

## 2. 形象理解

像仓库管理员手中的作业单：写着“查看库存”“移动货物”；发出作业单和实际完成搬运是两件事。

**类比的局限：**业务动作可涉及不可回滚的支付、发送和删除，不能都类比成随时撤销的纸面操作。

## 3. 技术原理与核心内容

可形式化为动作集合 A(s)，策略 a_t=π(o_≤t, goal, state)，执行器执行 `check_permission(a_t) → validate_arguments → execute → record_result`。把只读、可重复写入和不可重复写入拆为不同风险等级。环境状态可按 `s_(t+1)=T(s_t,a_t,noise)` 改变；若发生超时，不能从“无响应”推断 `T` 未执行。

## 4. 工程实践与设计权衡

**工程案例：**在账单助理中，“获取账单”是只读动作；“退款”涉及金额、对象和审批。发送 `refund(order_id, amount, idempotency_key)` 前先核对金额上限和权限，之后从权威账务记录确认。

**失败模式与验证：**常见故障是重复执行非幂等动作、工具参数被模型猜测、授权不足和把外部网页里的指令当成操作命令。测试应包含超时后已成功、重试冲突、错误参数以及工具返回与数据库不一致。

## 5. 关联知识与易混辨析

Action 与 Observation：前者是系统选择的操作，后者是操作后获知的反馈；Action 与 Tool Call：前者是概念上的行动，后者是其中一种技术承载方式。

## 6. 中等难度面试题（含参考答案）

1. **问：工具调用超时但第三方可能已创建工单，你会立即重试吗？** 答：不能直接重复非幂等写入。应利用业务幂等键或查询接口确定第一次调用是否已完成；仅在确认未生效或有服务端去重保证时重试，并记录请求 ID。
2. **问：如何为一个 Agent 划分动作权限？** 答：先区分只读与写入，再按数据范围、金额、操作可逆性配置最小权限；高风险动作采用参数校验和人工审批。提示文本不等于访问控制。

## 7. 中等难度考试题（含解析）

1. **题：设环境初始库存 30 件，动作 a1 读库存，a2 成功扣减 7 件，a3 读库存。在无并发且读写强一致的题设下两次观察各是多少？** 解：第一次读到 30 件；执行 a2 后状态为 30−7=23 件，第二次读到 23 件。若存在并发/缓存则需额外假设，不能直接套用。
2. **题：订单退款工具返回 HTTP 超时且没有业务结果，状态属于失败、成功还是未知？设计下一步。** 解：属于未知；记录请求标识并查询账务/退款记录。仅有网络超时不足以断定服务端未执行，避免无保护重试造成双重退款。
