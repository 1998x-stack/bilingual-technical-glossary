# Memory Forgetting（记忆遗忘）

> AI Agents · 专题：上下文、记忆与状态 · 适用范围：系统架构与可靠性工程；具体实现以引用的版本和产品为准

## 1. 核心定义

**Memory Forgetting（记忆遗忘）**：Memory Forgetting（记忆遗忘）是按用途限制、时间、用户撤回、数据治理或知识质量规则删除、屏蔽、失效或降低记忆内容的可检索权重。对用户明确要求删除的记录，‘降低相似度排名’不能替代实际的数据删除。

**适用边界：**遗忘是工程治理概念，不保证已训练模型的参数中相关信息被清除；持久存储、缓存、向量索引、摘要和备份各有独立生命周期，应明确删除范围与限制。

## 2. 形象理解

像档案管理到期销毁不再需要的资料：不能仅把目录上名字划掉，而让其他复印件继续随意取阅。

**类比的局限：**依法留存的审计记录与用户可检索记忆可能遵循不同规则，不能将‘界面不可见’宣称等于全部媒介擦除。

## 3. 技术原理与核心内容

制定 `memory_id → tombstone/revocation → hide from retrieval → delete primary record → purge/rebuild index/cache → verify`。需要时对备份设置到期清除与恢复后再删除的机制。对‘事实已过期’可用 valid_to/TTL 标记无效，查询时强制过滤；对用户撤回需按适用政策删除并检查多个衍生摘要引用。为删除请求保存最小化审计信息，而非复制被删除的敏感原文。

## 4. 工程实践与设计权衡

**工程案例：**客户撤回‘记住我的电话’请求后，Agent 不应在下一次 Memory Retrieval 中继续返回手机号；即使向量库延迟同步，也应在权限/撤回黑名单层立即阻断召回，再完成索引删除。

**失败模式与验证：**只删主表却忘记向量索引；备份恢复时旧记忆重新出现；TTL 到期仍通过缓存返回；‘遗忘’误删会话执行中的必要交易状态。测试删除后各个检索入口、异步传播和恢复场景。

## 5. 关联知识与易混辨析

Memory Forgetting 是信息生命周期管理；Context Compression 只是减少模型输入；Memory Consolidation 是整理/去重；Model Unlearning 涉及模型参数层面的不同研究问题。

## 6. 中等难度面试题（含参考答案）

1. **问：为何从向量索引删除记录不能保证完整遗忘？** 答：可能有主存、缓存、对话摘要、备份和衍生记录，需要覆盖所有被允许删除的路径并防止后续重建恢复。
2. **问：用户要求撤回记忆时，系统只把相似度分数减半可以吗？** 答：不可以把降权冒充删除；对有效删除请求应禁止检索并落实数据生命周期处理，按政策说明备份等边界。

## 7. 中等难度考试题（含解析）

1. **题：主库 100 条记忆中有 20 条过期、5 条用户撤回且互不重叠，应有多少条仍可见？** 解：100−20−5=75 条；查询仍应按用户权限过滤。
2. **题：删除后 ANN 索引仍可返回该记录，但主库存储已移除。是否达到‘不可被召回’验收？** 解：没有，索引仍暴露内容/元信息；需要查询端阻断和索引同步删除。
