# Cost per Task（单任务成本）

> AI Agents · 专题：工程化、成本与可观测性 · 模型用量、成本预算与缓存治理

## 1. 核心定义

**Cost per Task（单任务成本）**：在已声明成功判定与费用归属口径下，一个 Agent 任务平均消耗的模型、工具、计算、检索和其他可计费资源成本。它可按所有发起任务或仅成功任务计算，两者不应混为一谈。

**定义边界：**有关 token、价格、配额和缓存的产品语义可能依模型与服务版本变化。本文只定义可以迁移的工程方法；练习数字均假设给定，不能误称任何供应商当前实际价格或基准数据。成本不是唯一目标，正确的任务结果、隐私和安全权限应具有清晰的最低门槛。

## 2. 形象理解

**类比：**像餐厅算每份订单成本，不只看菜价，还要计耗材、配送和退单损耗。

**类比的局限：**简单均值会隐藏高成本长尾和未成功订单，成本低也不代表交付质量高。 实际 Agent 有多种费用、资源状态和分布式后置结果，因此不能从类比推导精确计费或可靠性保证。

## 3. 技术原理与核心内容

定义单位周期总任务成本 C_total，若按所有接收任务算 C_total/N_received；若按成功完成任务算 C_total/N_success，分母必须标记清楚。用 trace/task ID 汇总模型请求、工具费、GPU 时间、重试与缓存，不将单位成本等同单次 LLM API 价格。

**成本模型与治理边界。**一个 Agent 任务会跨多次模型调用、检索、数据库、工具、人工审批和失败重试；应依调用 ID 归集用量，再按相应计价规则计算，不凭空使用特定厂商报价。要区分当前已结算与在途预留，模型回答成功不等于业务完成。缓存值、外部工具结果和旧记忆属于数据来源，不得因低成本或高相似度而突破现有授权与业务实时状态。

**执行闭环。**入口分配 task_id 和共享额度，执行器在每个子任务前检查预估资源需求，随后记录实际 usage 与工具费用；必要时主动拒绝或降级。所有业务写入仍要使用真实权限和幂等键，不能因为缓存或便宜模型的建议就直接行动。

## 4. 工程实践与设计权衡

**工程案例：**自动报表 Agent 对每个请求做三轮检索和两轮审核。统计发现失败重试占模型费用的 25%，应先定位错误根源再优化，而不是减少审批或权限校验。

**验证程序。**用固定任务集同时统计输入/输出用量、模型/工具调用数、重试次数、实际成功数、端到端 P95、成本与安全拦截；计算两组候选方案的成功摊销成本并标记计费口径。注入并发、超时、缓存过期、权限变更和费用报告滞后等边界用例，不使用真实客户数据。把质量阈值和安全边界作为必须满足的约束，不应以平均费用下降证明总体方案更优。

**失败与取舍：**便宜模型可能增加修复重试次数；高命中缓存若权限键错误会泄露数据；账单告警并不必然是执行层硬上限。预算控制应对不确定价格做保守预留，对失败任务记录消耗，在权限或关键事实变更时使旧结果失效。

## 5. 关联知识与易混辨析

Token Usage 是调用量，Cost per Task 是货币归因；Cost–Quality Trade-off 还需要衡量真实任务质量。平均成本与 P95 成本可能严重不同。

应把调用级 token、任务级费用、预算策略、缓存有效性和业务完成率作为不同量分别建模。进行选型或成本报告时注明单位、统计期间、纳入的工具费用和失败样本，否则“每次调用价格下降”可能掩盖真正的任务总成本上升。

## 6. 中等难度面试题（含参考答案）

1. **问：为何成本优化不能仅看每 token 的价钱？** 答：工具/计算/重试/人工费用、缓存折扣和失败任务都会影响完整成本；应完整归因。
2. **问：如何公平比较两个成功率不同的 Agent 工作流？** 答：同时报告总费用、成功任务成本和业务完成率，按照统一任务集合比较，不能只按 API 调用价格。

回答应覆盖数据来源、并发资源控制、计量精度以及业务边界，说明如何用受控任务评测验证所提出的优化。

## 7. 中等难度考试题（含解析）

1. **题：100 次任务合计花 20 美元，80 次成功，单次接收任务成本与单次成功任务摊销成本？** 解：20/100=$0.20/次接收；20/80=$0.25/次成功（假设所有成本计入）。 明确分母、币种或 token 数、所含费用范围，并验证数值合理性。
2. **题：A 每次请求 $0.04 成功率 50%，B 每次 $0.06 成功率 90%，哪者每次成功摊销成本更低？** 解：A: 0.04/0.5=$0.08/成功；B: 0.06/0.9≈$0.0667/成功，B 较低。 要解释正确原因和常见误用，不能把成本优化与忽略业务授权混同。
