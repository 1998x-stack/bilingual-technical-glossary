# Structured Output（结构化输出）

> AI Agents · 专题：模型能力与推理 · 适用范围：通用智能体系统设计；具体实现以官方文档为准

## 1. 核心定义

**Structured Output（结构化输出）**：Structured Output（结构化输出）是让模型返回符合约定字段、类型和格式的结果，如满足指定 JSON Schema 的对象。它能提高机器解析一致性，但不会自动保证字段值真实、合法或符合业务授权。

**适用边界：**各提供商支持的 schema 子集不同；模型拒绝、安全失败或输出截断必须单独处理。

## 2. 形象理解

像填写固定表格，计算机很容易按栏目读懂。

**类比的局限：**表格格式正确并不代表填报内容真实。

## 3. 技术原理与核心内容

首先规定 schema，再在支持的模型接口声明输出格式。运行时生成→解析→结构校验→业务校验→持久化。比如 `amount:number`、`currency:enum`、`order_id:string`，即使类型都通过，也须检查金额范围与订单是否存在。严格接口可能要求所有字段 required、对象 `additionalProperties:false`，具体依当前官方文档为准。

## 4. 工程实践与设计权衡

**工程案例：**客户工单提取系统以 schema 返回主题、客户编号和优先级，使用服务器查客户编号及风险等级。响应的拒绝或 incomplete 状态不能写入生产数据库。高风险字段需和原始票据核对，而不是只看解析成功。

**失败模式与验证：**常见问题包括把错误金额填入正确类型字段、将空值编为字符串、schema 版本变化和未处理拒绝。按字段准确率、端到端完成率与误写率评测，避免“100% JSON 合法”掩盖事实错误。

## 5. 关联知识与易混辨析

Structured Output 是外部输出契约；Constrained Decoding 是实现契约的技术；Function Calling 是请求宿主执行工具的交互，两者不等价。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 schema 通过率不能代替准确率？** 答：schema 只能约束字段和类型；金额来源、实体映射、权限需要业务/原始证据核验。
2. **问：面对模型不支持的 schema 关键字如何处理？** 答：优先使用支持的子集，把交叉字段和业务约束放在应用层校验，同时测试拒绝与截断分支。

## 7. 中等难度考试题（含解析）

1. **题：200 次输出中 188 次 schema 合格、169 次内容正确，结构通过率和端到端正确率？** 解：188/200=94%，169/200=84.5%，两种指标衡量不同层面。
2. **题：`{"amount":-20,"currency":"USD"}` 类型正确但负数非法，应在哪层拦截？** 解：在 schema 增加支持的 minimum 或由业务验证器拦截；类型正确不等于金额业务合法。
