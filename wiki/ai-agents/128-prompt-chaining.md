# Prompt Chaining（提示链）

> AI Agents · 专题：工作流与编排模式 · 区分编排模式、执行权限和模型行为边界

## 1. 核心定义

**Prompt Chaining（提示链）**：Prompt Chaining（提示链）是通过多次依赖的 LLM 调用，将一个复杂任务分解为更明确的模型子任务，上一轮生成的内容经检查后作为下一轮提示的一部分。它适合任务自然可拆分、每步输出可验证的场景。

**适用边界：**多次模型调用不必然比一次调用更准确；它会增加延迟、费用及上游幻觉传播风险。链中不可信检索文档与模型产出仍不能自动获得更高的指令优先级。

## 2. 形象理解

像写一篇研究报告：先生成大纲，确认主题后逐段写作，最后进行事实审核与排版。

**类比的局限：**大纲若建立在错误前提上，写作越充分可能越强化错误；中间必须有客观检查。

## 3. 技术原理与核心内容

例如 `outline = LLM(prompt_A)` → `gate(schema,coverage)` → `draft=LLM(prompt_B,outline)` → `review=LLM(prompt_C,draft,evidence)`。Anthropic 建议在明确可拆分的步骤间加入编程 gate；每步按同一用户目标、token 预算和权限配置调用，并记录原始证据，不能把 LLM 生成的引用直接当真实来源。

## 4. 工程实践与设计权衡

**工程案例：**本地化 Agent 先抽取 UI 文案与变量占位符，再翻译，再校验 `{username}`、金额格式与长度限制，最后提交人工复核。出现占位符缺失时退回翻译，而不是让下一步发布错误文案。

**失败模式与验证：**每一步都改写前面关键约束、幻觉不断传递、错误引用无法追溯、模型费用高于收益。对关键字段保留率、逐步正确率、总延迟与最终任务质量开展 A/B 评估。

## 5. 关联知识与易混辨析

Prompt Chaining 是连续模型调用模式；Chaining 可以包含代码/工具；Evaluator–Optimizer 是带评价反馈的循环；单次复杂提示不等于提示链。

## 6. 中等难度面试题（含参考答案）

1. **问：什么时候值得把单次 LLM 提示拆成提示链？** 答：存在自然阶段、每阶段可结构化验证且提升可抵偿额外费用与时延时；否则简单流程可能更好。
2. **问：为何不应让模型产出的引用直接进入下一阶段事实表？** 答：模型可能虚构来源。应验证引用 URL、文档片段和支持关系，并将其标记为外部可核查证据。

## 7. 中等难度考试题（含解析）

1. **题：提示链三步调用时延 0.8、1.2、0.6 秒，各后一步依赖前一步，总时延（忽略其他开销）？** 解：0.8+1.2+0.6=2.6 秒。
2. **题：三步每步通过概率均为 0.9 且独立，总体全部通过概率？** 解：0.9³=0.729，即 72.9%；这是教学独立性假设。
