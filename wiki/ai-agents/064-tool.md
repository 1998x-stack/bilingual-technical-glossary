# Tool（工具）

> AI Agents · 专题：工具使用与环境交互 · 通用工程概念；具体行为以平台、协议与版本为准

## 1. 核心定义

**Tool（工具）**：Tool（工具）是 Agent 通过协议或 API 接入的外部能力，例如读数据库、检索网页、运行代码或控制浏览器。工具可以拓展模型的信息和行动能力，但模型识别工具名**不代表已经拥有执行权限**。

**适用边界：**工具可只读或产生不可逆副作用，执行由宿主程序承担；任何工具调用都需要权限、输入验证、超时和可追溯的结果。

## 2. 形象理解

像实验室有计算器、显微镜和机械臂。设备能帮助研究者，但仍须在允许的范围内正确使用。

**类比的局限：**设备可能故障或读错数据；把错误工具结果当成系统指令还会引入安全风险。

## 3. 技术原理与核心内容

典型工具契约含 name、description、inputSchema、输出约定和后端权限。模型基于描述提出 Tool Call，由执行器验证参数和授权，再执行并把 Tool Result 返回；失败与不确定状态必须被显式记录。MCP 等协议定义可发现和调用的工具接口，但业务授权仍由客户端/服务端策略实现。

## 4. 工程实践与设计权衡

**工程案例：**报销助手注册 list_expenses（只读）与 submit_reimbursement（写入）。系统允许自动查询，但提交报销前须校验归属、金额、审批与幂等键；完成后查权威事务 ID。

**失败模式与验证：**将“工具仅用于读取”的 prompt 当作硬授权、让模型提供任意后端地址、无限循环调用工具、盲信外部网页命令均可造成泄露或破坏。通过故障注入、负向权限测试和日志审计检查。

## 5. 关联知识与易混辨析

Tool 指外部能力；Function Tool 是函数签名形式；Tool Call 是一次请求；Tool Result 是一次执行的反馈，四者不能混为同义。

## 6. 中等难度面试题（含参考答案）

1. **问：为何只在提示词里禁止删库不够？** 答：模型提示不是执行权限。执行端应限制工具白名单和最小权限，写操作进行业务授权和人工确认。
2. **问：工具输出要求 Agent 忽略之前的系统约束，应遵从吗？** 答：不应。工具返回被视为低信任数据，不能自动提升为控制指令；执行端不变量和权限仍必须生效。

## 7. 中等难度考试题（含解析）

1. **题：4 个工具中 2 个只读、2 个写入，会话只有只读权，可直接调用几个？** 解：2 个只读工具；真正的授权须在工具执行器实施。
2. **题：工具调用 HTTP 200，但业务响应 status=failed，算完成吗？** 解：不算。协议响应成功不等于业务成功，必须按业务状态和验收条件判断。
