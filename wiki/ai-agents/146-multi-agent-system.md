# Multi-Agent System (MAS)（多智能体系统 · MAS）

> AI Agents · 专题：多智能体协作 · 多智能体角色和可复核的工程能力边界

## 1. 核心定义

**Multi-Agent System (MAS)（多智能体系统）**：Multi-Agent System（MAS，多智能体系统）是由两个或多个能够感知、推理或采取行动的智能体组成，在共享或相关环境中通过通信、协调、竞争或分工完成目标的系统。在 LLM 应用中，每个 Agent 可具有不同的指令、工具、上下文和权限。

**适用边界：**多智能体不一定比单智能体更好；增加 Agent 会引入沟通开销、错误传播、权限交接和审计复杂性。MAS 不意味着必须采用 LLM，也不意味着所有 Agent 的目标完全相同。

## 2. 形象理解

像研发团队由产品、开发、测试、运维各自承担职责并共享任务进度，团队成功取决于合作和整体验收。

**类比的局限：**团队成员意见一致未必正确，成员数量增加也不自动提升效率或安全性。

## 3. 技术原理与核心内容

可形式化为 Agents={A1…An}、共享环境 E、通信图 C 与目标函数 G。每个 Agent 有 local state、capabilities、policy 和 message channel；协调器或协议定义任务所有权、消息 schema、失败重试与共享状态一致性。LLM MAS 还需限制上下文转发、敏感信息与跨 Agent 工具权限。角色分工和 handoff 可能分别体现经理式集中控制和同伴式接管。

## 4. 工程实践与设计权衡

**工程案例：**软件迁移项目让架构 Agent 规划、代码 Agent 修改、测试 Agent 复核；实际 merge 和发布仍由受控审批流程负责。两位 Agent 同时改同一配置文件需要冲突检测和合并审查，而不是最后写入者获胜。

**失败模式与验证：**Agent 互相循环委派、以重复讨论替代证据、跨 Agent 泄露数据、共享状态冲突、沟通 token 成本超过收益。评测端到端任务成功、角色边界、时延、成本及负向授权案例。

## 5. 关联知识与易混辨析

MAS 是多个 Agent 互动的整体系统；Orchestrator–Workers 是一种集中动态分工模式；Specialist/Generalist 主要描述能力范围；Manager/Coordinator 是编排职责。

## 6. 中等难度面试题（含参考答案）

1. **问：什么时候多智能体架构不值得采用？** 答：任务简单、单 Agent 已能可靠完成或多角色沟通成本高时，拆分可能降低质量、增加 token 和时延。
2. **问：如何判断两个 Agent 的协作真的成功？** 答：从共同业务目标、工具真实结果和独立验收判断，而不是统计对话次数或各 Agent 的自评。

## 7. 中等难度考试题（含解析）

1. **题：3 个 Agent 严格串行耗时 2、3、4 秒；若各自独立可并行且汇总需要 1 秒，理想节省时间？** 解：串行 9+1=10 秒，并行 4+1=5 秒，节省 5 秒，忽略调度开销。
2. **题：两个 Agent 都能提交退款，且都读到尚未退款，为什么危险？** 解：并发可能双重提交，需要服务器端幂等键、资源授权与原子一致性控制。
