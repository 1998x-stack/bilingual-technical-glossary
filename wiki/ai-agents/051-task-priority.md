# Task Priority（任务优先级）

> 适用领域：AI Agents · 专题：任务规划与决策 · 基础概念与具体 SDK 权限实现需分开判断

## 1. 核心定义

**Task Priority（任务优先级）**：Task Priority（任务优先级）是多个已可执行任务竞争有限资源时，调度器决定其服务顺序的一种排序规则。优先级可综合时限、关键路径影响、业务价值、风险和等待时长，但它本身不改变任务前置依赖。

**适用边界：**优先级是调度政策，不是任务能否运行的授权证明。对于互斥资源，还必须考虑公平性、饿死问题和优先级反转。

## 2. 形象理解

像急诊分诊：最需要紧急处理的病人优先，但也要看手术室、医生和必要检查是否就绪。

**类比的局限：**“优先”不表示随时可以跳过手术前检查，也不表示普通任务可以永远不被处理。

## 3. 技术原理与核心内容

为就绪队列中的任务设置调度键，如 `key=(-priority,deadline,arrival)`；只有依赖满足的节点才能进入队列。业务规则可采用 aging，让等待时间越长的低优先级任务逐渐提高调度权重，防止 starvation。关键路径任务优先可以减少总体完工时长，但资源争用和执行时间不确定会影响结果。

## 4. 工程实践与设计权衡

**工程案例：**研究 Agent 同时处理客户故障与后台摘要生成，前者在服务质量上优先；若后台工作长期积压，需通过保底配额或 aging 保证完成。调用工具时仍执行权限与速率限制。

**失败模式与验证：**只用单一高优先级通道会让低优先任务饥饿；缺失依赖检查会让高优先任务提前写入。监控等待 P95、超期率和不同优先级的完成率。

## 5. 关联知识与易混辨析

Task Dependency 决定任务何时就绪；Task Priority 决定多个就绪任务谁先运行；Utility Function 则可以提供价值排序依据，但不应替代强制业务限制。

## 6. 中等难度面试题（含参考答案）

1. **问：高优先级但前置任务未完成，可以先执行吗？** 答：不可以。优先级只在依赖和权限满足的候选中发挥排序作用；否则违反任务图与业务前置条件。
2. **问：如何诊断低优先级任务长期无进展？** 答：查看就绪队列等待分布、高优先流量、资源饱和与依赖阻塞，采用 aging/保底资源并评估对紧急任务 SLA 的影响。

## 7. 中等难度考试题（含解析）

1. **题：单执行器上 A、B 均就绪且不抢占，A 耗时 5 min 优先级 2，B 耗时 2 min 优先级 5，按数值越大越先运行，总完工时间和 A 完成时间？** 解：先 B 后 A，总完工 2+5=7 min，A 在第 7 分钟完成；若先 A，A 在第 5 分钟完成。
2. **题：C 的优先级最高，但依赖 D，D 未完成；E 已就绪。调度器现在可以启动哪个？** 解：只能选择满足依赖和权限的 E（或其他已就绪节点），不能因 C 优先级高跳过 D。
