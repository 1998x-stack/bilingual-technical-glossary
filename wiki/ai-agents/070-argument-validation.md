# Argument Validation（参数校验）

> AI Agents · 专题：工具使用与环境交互 · 通用工程概念；具体行为以平台、协议与版本为准

## 1. 核心定义

**Argument Validation（参数校验）**：Argument Validation（参数校验）是工具执行前针对具体入参进行结构检查、类型/范围检查、业务不变量校验和执行时状态核对的过程。它是模型输出转为真实动作前的关键门控，不应简化为 JSON 能解析。

**适用边界：**结构校验、业务规则、资源归属和授权属于不同层次，必须逐层执行；自动纠正歧义可能造成错误副作用。

## 2. 形象理解

银行柜台不仅检查汇款单有无漏填，还要核对账号归属、金额、授权与风控规则。

**类比的局限：**格式都正确的表单仍可能转错钱，必须依据权威业务记录校验。

## 3. 技术原理与核心内容

典型管线 parse → schema_validate → normalize → business_invariants → authZ → current_state_check → execute。对金额/URL/文件路径/命令参数使用明确范围与允许集合，防范路径穿越、SSRF、注入及执行前检查到执行时变化的 TOCTOU 竞态。无法满足条件应返回结构化拒绝，写操作不可自动盲试。

## 4. 工程实践与设计权衡

**工程案例：**文件 Agent 的 delete_file(path) 只允许操作受控工作目录，执行器解析路径和符号链接、验证真实归属及文件版本，并经过用户确认。dry-run 可显示计划删除的文件，但不能取代实际权限。

**失败模式与验证：**只查字段类型会放行危险路径和跨租户 ID；仅靠 prompt 要求谨慎无法阻止工具执行。测试边界数值、编码变体、无权限请求、并发修改以及拒绝后零副作用。

## 5. 关联知识与易混辨析

Tool Schema 给出静态预期；Argument Validation 检查实际值；Authorization 判断主体是否能操作资源；业务验证确认操作满足实时业务不变量。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 schema 通过后还要做 AuthZ 与业务验证？** 答：类型合法可能仍有越权 ID、危险金额或状态失效，应由服务端基于可信身份与当前数据强制校验。
2. **问：为什么字符串前缀比较目录不是安全的文件路径验证？** 答：符号链接、编码、相似前缀等可能绕过；应使用可信路径规范化、目录句柄约束和最小权限。

## 7. 中等难度考试题（含解析）

1. **题：工具金额范围是 1–500 的整数，输入 0、250、501，允许哪项？** 解：只有 250；0 低于下限，501 超出上限。
2. **题：order_id 类型正确但用户无权访问此订单，能执行吗？** 解：不可以；结构层可能通过，但授权层必须拒绝。
