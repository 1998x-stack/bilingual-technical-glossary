# Routing Pattern（路由模式）

> AI Agents · 专题：工作流与编排模式 · 区分编排模式、执行权限和模型行为边界

## 1. 核心定义

**Routing Pattern（路由模式）**：Routing Pattern（路由模式）是在流程入口依据输入类别、能力要求、风险级别或成本，将任务发送到不同专家模型、工具路径或子工作流的控制结构。它将不同类型问题交给有针对性的处理路径，不仅是普通网络层的请求转发。

**适用边界：**路由分类可能不确定；高风险任务应有保守回退/人工审查。路由器的输出只是路径建议，不能替代执行层资源授权与安全门控。

## 2. 形象理解

像医院分诊先判断急诊、普通门诊或专科，再由对应科室进行处理；不确定或危险症状要升级处理。

**类比的局限：**分诊成功不代表治疗有效，分类误判仍可能把病人送错地方。

## 3. 技术原理与核心内容

入口先提取 intent/risk、可用能力和当前权限，计算 route=f(query,metadata,policy)；根据置信阈值或规则进入 specialized_handler，低置信进入 fallback。每条分支应有自己的 schema、超时、预算和最终验收。可用规则分类器或 LLM 做路由，但敏感动作必须二次授权。度量 confusion matrix，尤其关注把危险请求误路由至只读/写路径的风险。

## 4. 工程实践与设计权衡

**工程案例：**客户服务 Agent 将‘退款状态查询’路由到只读查询，而‘新退款申请’进入授权与人工确认流。二者都含‘退款’词，不得仅以关键词相似性选择能扣钱的工具。

**失败模式与验证：**分类误路由、动态工具目录变化导致无效分支、置信度未经校准、跨租户路径继承错误。使用包含模糊/对抗意图的流量测试，检查错路由率、业务完成率与延迟。

## 5. 关联知识与易混辨析

Routing Pattern 是业务/模型流程路径分配；Tool Routing 把具体已批准工具请求送给后端执行器；Conditional Branch 是更一般的条件控制结构。

## 6. 中等难度面试题（含参考答案）

1. **问：如何处理模型不确定的路由判断？** 答：进入有界的澄清/保守只读分支或人工复核，不默认调用高风险写工具；记录不确定性和候选。
2. **问：为何路由器的高置信分数不等于执行授权？** 答：模型分数不是用户身份及资源权限，真正执行器必须验证当前主体和动作对象。

## 7. 中等难度考试题（含解析）

1. **题：100 次请求路由到 A/B 分别为 60/40，A 误路由 6 次、B 误路由 4 次，总误路由率？** 解：(6+4)/100=10%；还要按风险等级拆分误路由代价。
2. **题：用户要求‘查看支付状态’，路由到 issue_payment 会出现什么问题？** 解：把只读任务变成有副作用写入。应路由查询状态工具并阻止越权付款。
