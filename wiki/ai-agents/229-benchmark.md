# Benchmark（评测基准）

> AI Agents · 专题：评测体系与常见基准 · 定义、工程边界、可复算题目与独立事实核验

## 1. 核心定义

**Benchmark（评测基准）**：Benchmark（评测基准）是由固定任务、运行环境、评分标准和结果报告规则构成的可比较测试框架，用于衡量不同模型、Agent 策略和工具系统的能力。一个好 benchmark 需要保证足够代表性、运行可复现和训练/测试隔离。

**适用边界：**排行榜分数通常对具体版本/工具预算/提示设置有效，不能泛化为所有真实工作。公开任务可能被模型训练或人为调参污染，需披露日期、环境、超时、运行次数与数据去重策略。

## 2. 形象理解

如驾驶考试提供统一道路规则和评分表，能比较同条件考生，但不能保证某人能在所有恶劣天气安全驾驶。

**类比的局限：**反复练习公开考题可能抬高成绩却不反映真实泛化，现实问题也可能超出考场范围。

## 3. 技术原理与核心内容

BenchmarkSpec={dataset_version,environment_image,toolset,permissions,max_steps,seed,scoring_oracle,run_count}。如 SWE-bench 将真实软件仓库 issue 和可执行测试结合，评价补丁是否满足问题而不是模型是否宣称已修复。比较两个 Agent 应使用相同实例与预算，报告成功率、区间、时间和费用；测例不可随意删除失败项，且需保留出错日志和运行资产。

## 4. 工程实践与设计权衡

**工程案例：**评测两个代码修复 Agent 时固定 100 个测试 issue 和隔离容器，分别进行 3 次独立运行并记录每次通过数量与成本；不允许只选最高一轮结果作为整体水平。

**失败模式与验证：**训练数据泄漏、测试基础设施损坏、评估器错误、跑不同版本工具造成分数不可比、隐藏失败用例。建立每次测试版本锁、可重放日志和基准数据审核。

## 5. 关联知识与易混辨析

Benchmark 是任务+环境+评分完整规范；Evaluation Dataset 是组成它的样例；Task Success Rate 是一个结果指标；排行榜只是指标呈现。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么同一 Agent 在不同工具权限下的 Benchmark 成绩不可直接比较？** 答：权限与能力改变了任务可解性与风险，需统一条件或明确单独报告。
2. **问：高 benchmark 分数为什么不证明无实际生产风险？** 答：标准测试覆盖有限、分布偏移与未知失效仍会存在，需要真实环境监控与安全边界。

## 7. 中等难度考试题（含解析）

1. **题：200 个基准任务完成 84 个，成功率多少？** 解：84/200=42%。
2. **题：两轮 100 题分别成功 80 与 90，算术平均率多少？** 解：(80+90)/2/100=85%，不应只报 90%。
