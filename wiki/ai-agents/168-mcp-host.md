# MCP Host（MCP 主机）

> AI Agents · 专题：MCP：模型上下文协议 · 截至 2026-11 的协议版本须区分 2025-11-25 与 2026-07-28

## 1. 核心定义

**MCP Host（MCP 主机）**：MCP Host（MCP 主机）是使用 MCP 的上层 AI 应用，例如聊天界面、开发工具或 Agent 运行器，负责管理一个或多个 MCP Client、对模型暴露可用工具以及处理用户同意和上下文边界。Host 是应用角色，不是服务器端提供工具的 MCP Server。

**适用边界：**Host 的具体实现可能把多个逻辑连接器聚合为一个 UI；标准化协议并不规定 Host 必须允许模型自主调用全部工具。是否执行高风险动作应由 Host 和执行服务共同实施权限与用户确认。

## 2. 形象理解

像笔记本电脑操作系统管理外接设备与权限弹窗，设备提供功能，但系统决定哪些应用可使用。

**类比的局限：**连接设备不意味着应用可以无条件读所有文件，Host 也不能仅凭提示词保证服务器侧访问安全。

## 3. 技术原理与核心内容

Host 把用户与开发者约束、模型输出和工具调用过程协调到多个 Client；每个 Client 针对某 Server 完成协议能力发现与请求编码。对 modern 2026 版本按请求元数据申报协议版本/能力；对 legacy 支持 initialize。Host 管理工具命名冲突、权限 scope、确认 UI、证据来源和工具结果的低信任处理，避免跨来源内容污染执行策略。

## 4. 工程实践与设计权衡

**工程案例：**企业编码 IDE 同时接入 Git 服务器和工单服务器，Host 将不同命名空间的 tools/list 合并展示，用户只授权读取指定仓库。若模型选择删除分支，Host 应要求确认并由 GitHub 真实权限再校验。

**失败模式与验证：**工具名冲突导致错误服务器被调用、缓存列表未根据用户 token 更新、把不可信提示模板变成系统命令、意外跨项目共享对话。通过多服务器同名工具、租户切换和授权撤回测试。

## 5. 关联知识与易混辨析

Host 是管理连接和用户/模型交互的应用；MCP Client 是它与某服务通信的协议组件；MCP Server 暴露能力；Tool Adapter 是应用侧协议适配设计而非必须独立服务。

## 6. 中等难度面试题（含参考答案）

1. **问：Host 与 MCP Client 有何区别？** 答：Host 管理用户体验、模型上下文和整体工具权限；Client 负责针对 MCP Server 的协议交互，通常为 Host 管理的连接器。
2. **问：一个服务的 tools/list 变化后，Host 是否可以永久使用旧缓存？** 答：不应。应按协议缓存与变更规则更新，并重新检查有效授权，防止陈旧或越权工具。

## 7. 中等难度考试题（含解析）

1. **题：Host 中两个服务都暴露 tool 名为 search，怎样安全区分？** 解：使用服务 ID/命名空间建立唯一调用键，并按授权路由，不可仅凭 search 字符串猜测目标。
2. **题：用户撤回了数据库访问授权，但 Host 仍展示旧工具，是否允许调用？** 解：不允许。Host 与 Server 应基于当前凭证/ACL 拒绝，不因 UI 缓存可见而执行。
