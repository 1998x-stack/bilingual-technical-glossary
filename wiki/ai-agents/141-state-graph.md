# State Graph（状态图）

> AI Agents · 专题：工作流与编排模式 · 图编排、同步和权限边界；SDK 特性以对应版本文档为准

## 1. 核心定义

**State Graph（状态图）**：State Graph（状态图）是以状态、执行节点及状态转换关系描述计算或智能体执行过程的图模型。与无环的依赖 DAG 不同，状态图可以包含条件路径和循环，以便表达多轮工具交互、反思修正与恢复流程。

**适用边界：**状态图不等于自动持久化的有限状态机：图节点可执行复杂函数，状态更新规则、并发 reducer 和 checkpoint 语义依框架实现。即使图上允许循环，也须强制终止预算。

## 2. 形象理解

像地铁线路图中有换乘与环线：可以依据当前位置与目的地选择方向，但必须知道当前实际站点和可达路线。

**类比的局限：**线路图标出回路不意味着可以无限乘车而不付费，图也不保证某站点当前开放。

## 3. 技术原理与核心内容

将每个节点定义为 `node(state)->partial_state_update`，边定义为 static edge 或 conditional router(state)。执行器按消息/状态版本逐步更新，共享字段需要明确覆盖或 reducer 语义。LangGraph 的 StateGraph 用状态 schema、nodes、edges 定义图行为，循环可配合终止节点和 recursion limit；长运行应保存 checkpoint，并避免外部写操作恢复时重复。

## 4. 工程实践与设计权衡

**工程案例：**工单 Agent 的状态图从分类到检索，再由证据是否充分决定直接回答或返回补检；查证三轮仍不足则进入未确认终态，不继续无限询问。涉及退款节点需要独立授权和交易对账。

**失败模式与验证：**错误地把局部状态更新覆盖整段历史、循环未终止、并行更新同一键产生冲突、恢复时重播发信。以状态转换覆盖、冲突更新与无限环压力测试验证。

## 5. 关联知识与易混辨析

State Graph 表示状态驱动的可循环控制结构；DAG 是无环依赖图；Loop Node 是实现重复执行的一个节点；Control Flow 是更抽象的执行顺序语义。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 State Graph 可以表达‘检查失败则再试’，而静态 DAG 不可直接有回边？** 答：状态图允许从一个节点根据条件转移回前置节点，DAG 禁止有向环。DAG 可改用展开多轮节点，但本质与动态循环不同。
2. **问：如何防止两条并行边更新同一个状态字段时互相覆盖？** 答：定义明确 reducer/合并语义或串行化更新，使用版本检查；避免以模型最后回复顺序覆盖全部状态。

## 7. 中等难度考试题（含解析）

1. **题：状态图 A→B→A 最多允许 B 被执行 3 次，实际 B 执行第 3 次后仍失败，下一步应该是什么？** 解：触发预算停止/失败状态，不得无条件再次回到 A 循环。
2. **题：图包含 4 个不同状态、6 条有向边，能仅凭节点和边数确定有无环吗？** 解：不能，需检查具体连线是否构成有向环。
