# State Space（状态空间）

> 适用领域：AI Agents · 专题：任务规划与决策 · 基础概念与具体 SDK 权限实现需分开判断

## 1. 核心定义

**State Space（状态空间）**：State Space（状态空间）是任务或环境所有可能状态的集合 S，每个状态表示在决策模型中足以描述当前局面的变量取值。状态可能包含库存、订单处理阶段、权限或位置等；真实系统不一定能被 Agent 完全观察。

**适用边界：**State Space 不等于上下文窗口里的文字；部分可观测问题常用观察 O 或信念状态 b(s) 表示关于未知真实状态的分布。

## 2. 形象理解

像棋盘所有可能局面构成状态空间，但玩家可能只能看到棋盘的一部分。

**类比的局限：**状态数量巨大时无法逐项枚举，也不能用一份日志保证获得完整真实状态。

## 3. 技术原理与核心内容

MDP 定义 `(S,A,P,R,γ)`，其中 `P(s'|s,a)` 描述状态转移。若状态由 k 个独立布尔变量组成，完整组合上限为 `2^k`。若状态含连续值则空间可能无限。将与目标无关的变量投影掉形成抽象状态可降复杂度，但可能损失决策所需信息。

## 4. 工程实践与设计权衡

**工程案例：**订单 Agent 用 `status, payment_confirmed, stock_reserved` 三个字段构造业务状态；若只看 status='paid' 可能遗漏退款/库存并发变化，故写操作前需向权威服务重新读取。

**失败模式与验证：**状态建模遗漏关键变量会使策略在看似相同的两个局面中做出错误动作。用一致性测试、版本号、观察时间戳和状态转移日志检查模型。

## 5. 关联知识与易混辨析

State Space 表示可能局面；Observation 是 Agent 实际收到的传感/工具信息；Context 是模型可处理的文本或多模态输入。三者不可简单等同。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 Agent 的对话历史不能当作完整真实状态？** 答：它可能过期、缺少后台事务、被截断或含错误工具返回；关键状态由持久化系统和权威 API 校验。
2. **问：怎样缓解状态空间组合爆炸？** 答：提取决策相关变量、使用层级/因式分解表示、启发式搜索或状态聚合；同时用测试核查抽象未丢失安全关键信息。

## 7. 中等难度考试题（含解析）

1. **题：订单状态由 4 个独立布尔字段构成，忽略业务限制时共有多少种组合？** 解：2^4=16 种组合；实际业务不变量会排除一部分。
2. **题：某 Agent 只观察到“网络超时”，能否确定支付服务内部是 success 或 failure？** 解：不能；超时可能发生在成功提交后，应保留未知状态并查询交易 ID。
