# Reactive Execution（反应式执行）

> AI Agents · 专题：工作流与编排模式 · 应用架构、状态恢复与工程权衡

## 1. 核心定义

**Reactive Execution（反应式执行）**：Reactive Execution（反应式执行）是 Agent 依据当前观察和环境反馈直接选择下一步动作，而不是始终依赖一次性预生成的完整长期计划。它适用于变化快、信息不完整或需要频繁调整行为的交互环境。

**适用边界：**反应式并不代表没有目标或任何规划；也不意味着可以跳过权限和业务状态校验。只关注最近一步可能导致短视、循环或高成本探索。

## 2. 形象理解

像足球运动员根据对手位置和球的滚动实时调整下一步，而不完全照搬赛前分秒固定的跑位表。

**类比的局限：**只有即时反应而不考虑整体战略可能错失最终目标；观察也可能延迟或噪声严重。

## 3. 技术原理与核心内容

循环 `observe o_t → update state s_t → policy π(s_t) → choose action a_t → execute → verify`。策略可由规则、模型或组合产生，并有安全动作集 A_valid(s) 与停止准则。ReAct 研究把模型推理与工具/环境行动及观察交织；工程实现应对状态不确定、工具结果低信任、限流与重复写操作作独立保护。

## 4. 工程实践与设计权衡

**工程案例：**网站巡检 Agent 先查看最新可用性指标，如果某站点恢复则停止重试；若服务转移到备用区，再查目标区域健康状态。对扩容等写动作必须依据当前监控与审批，而不是模型猜测。

**失败模式与验证：**局部最优导致反复跳转、对噪声过度响应、调用次数不受控、工具响应延迟造成误操作。用观测乱序、环境突变、阈值抖动和故障超时验证安全停止。

## 5. 关联知识与易混辨析

Reactive Execution 按观察选择下一步；Plan-and-Execute 先规划序列再执行；Replanning 可在两者间桥接，用新状态重新求计划；Agent Loop 是承载观察-行动的整体运行机制。

## 6. 中等难度面试题（含参考答案）

1. **问：什么环境更适合反应式执行？** 答：快速变化且无法精确预测的环境，或者每步可通过反馈立即调整；高后果动作仍需硬性授权和验证。
2. **问：如何避免观测噪声导致不断在两个动作间切换？** 答：采用迟滞阈值、冷却时间、稳定窗口、最小动作间隔及状态版本检查。

## 7. 中等难度考试题（含解析）

1. **题：监控系统每 2 秒采样一次，连续 5 次异常才触发动作，若第一次采样在 t=0，最早触发时间？** 解：第 5 次在 t=8 秒；假设每次均异常且无额外等待。
2. **题：动作‘重启服务’已发出但无回执，Agent 观察到短时错误，能立即重启第二次吗？** 解：不应，需查询部署/进程状态并核对初次操作，防止故障期间重复写动作。
