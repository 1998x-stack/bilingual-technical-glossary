# End-to-end Success Rate（端到端成功率）

> AI Agents · 专题：评测体系与常见基准 · 明确分母、独立验证器、证据和安全界限

## 1. 核心定义

**End-to-end Success Rate（端到端成功率）**：End-to-end Success Rate（端到端成功率）是要求 Agent 从接收请求、理解意图、选择工具、执行操作到验证最终交付的完整链条满足业务目标的任务比例。其成功谓词一般比单步模型质量或某一工具调用返回 200 更严格。

**适用边界：**端到端不一定要求所有中间工具调用都绝对正确；只要有合法恢复和最终结果满足约束可以算成功。但任何不可接受的安全违规、未授权副作用或错误交付版本应使该次运行不合格。

## 2. 形象理解

像快递从下单、取件、运输到本人签收全过程完成才算真正交付，而不是仅凭司机取到包裹便报成功。

**类比的局限：**某一阶段晚到或补偿成功可能仍满足整体业务目标，应按预注册的验收规则而非简单步骤数判定。

## 3. 技术原理与核心内容

构建 E2E success predicate `AND(goal_reached,correct_resource,authorized,no_critical_violation,within_budget)`；按 task ID 串起 trace，读取真实后端状态/Artifact hash/用户验收。离线实验模拟第三方依赖时明确说明模拟范围；在线隔离环境则检查数据库和外部服务的后置条件。比较单步与端到端漏斗，找出主要失败阶段，并保留重试次数及恢复后成功的细节。

## 4. 工程实践与设计权衡

**工程案例：**采购 Agent 先查合同、再申请审批、最后创建采购单。模型把合同信息说对、审批工具也返回 accepted，但数据库没有采购单记录，E2E 仍失败；反之某次临时错误经合法重试后真实创建，可按协议计成功。

**失败模式与验证：**只测最终文本、误把审批成功当采购完成、丢失事件导致跨任务匹配、未统计交付后用户无法下载的情况。对动作前后快照、资源权限和失败注入做验收。

## 5. 关联知识与易混辨析

E2E success 面向全过程达成，Task Success Rate 可能根据任务定义较宽或同样严格；Action Success Rate 只看某个动作；Process Evaluation 关心路径规范。

## 6. 中等难度面试题（含参考答案）

1. **问：为何 99% 的工具请求 HTTP 成功率可能对应低 E2E 成功率？** 答：工具可能选错、参数错误或结果未达到业务目标，且多个阶段的成功概率会叠加受限。
2. **问：恢复后最终交付成功应不应该算 E2E 成功？** 答：若在允许预算、合法授权和验收标准内，可以计成功，并另报告重试/恢复成本。

## 7. 中等难度考试题（含解析）

1. **题：三阶段独立成功概率分别 0.9、0.8、0.95，且全部必须成功，理想端到端概率？** 解：0.9×0.8×0.95=0.684，即 68.4%；独立是假设。
2. **题：50 个任务中 42 个正确交付，其中 2 个越权，严格 E2E 成功率？** 解：(42−2)/50=80%。
