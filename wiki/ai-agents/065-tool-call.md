# Tool Call（工具调用）

> AI Agents · 专题：工具使用与环境交互 · 通用工程概念；具体行为以平台、协议与版本为准

## 1. 核心定义

**Tool Call（工具调用）**：Tool Call（工具调用）是模型或 Agent 向某个已声明工具发出的一次具体执行请求，通常包括工具名称、结构化参数和用于匹配结果的 call_id。它只是**调用意图或请求**，不是已成功执行的凭证。

**适用边界：**一轮模型响应可能包含零到多项工具调用；是否执行与如何并发由宿主控制，尤其不能并行处理具有依赖关系的写操作。

## 2. 形象理解

像在餐厅提交点菜单：单子写清菜品和数量，不等于菜已经做好。

**类比的局限：**生成订单编号不等于完成履约；厨房还会拒单、缺货或者超时。

## 3. 技术原理与核心内容

常见流程：模型输出 (call_id,name,arguments) → 工具名白名单校验 → schema 校验 → 权限/业务状态检查 → 执行 → 返回以 call_id 关联的工具结果 → 下一轮模型推理。call_id 主要用于关联消息，**不是**后端幂等键。写操作须明确业务请求键、重试语义及确认机制。

## 4. 工程实践与设计权衡

**工程案例：**日程 Agent 先 get_events 检查空闲，再 create_event 创建会议。创建前复查时区、与会人范围和日历权限；执行后获取 event_id 并通过日历接口查证。

**失败模式与验证：**将多个并发结果按返回顺序错配、只验证 JSON 而不核对归属、工具超时后重发非幂等写入，都可能导致错误结果。对这些情况设计带 trace_id 的测试。

## 5. 关联知识与易混辨析

Tool Call 是请求；Tool Execution 是宿主实际动作；Tool Result 是反馈；Function Calling 是实现请求/反馈循环的一类模型 API 模式。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么模型 Tool Call ID 不能当业务幂等键？** 答：call_id 用于关联模型响应与工具结果，后端去重必须由业务 API 支持并独立显式提供幂等标识。
2. **问：模型同时建议查询库存和扣减库存，应并行吗？** 答：通常不应；扣减依赖库存查询、权限和库存版本检查，执行器应按依赖顺序运行。

## 7. 中等难度考试题（含解析）

1. **题：一轮产生 3 个工具调用，已有 2 个工具完成且成功，能把整个任务标成成功吗？** 解：不能。至少仍有 1 个未完成调用，且最终还需业务目标验收。
2. **题：退款写工具超时，能否直接当作失败并重试？** 解：不能，可能已成功；应查权威状态并使用受支持的幂等语义判断是否可重试。
