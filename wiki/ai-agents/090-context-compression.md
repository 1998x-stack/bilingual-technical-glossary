# Context Compression（上下文压缩）

> AI Agents · 专题：上下文、记忆与状态 · 适用范围：通用模型与智能体工程；产品能力以服务文档为准

## 1. 核心定义

**Context Compression（上下文压缩）**：Context Compression（上下文压缩）是通过摘要、去重、过滤、结构提取或引用外存，减少模型当轮输入中的 token 量，同时尽量保留对任务正确性和后续决策必需的信息。压缩应有可测的保真要求，而非仅追求短。

**适用边界：**任何摘要都有丢失细节或产生错误的风险；对于法律条款、金额、授权和未完成事务 ID 等关键内容，通常需要保留原文/结构化状态或可回溯引用。

## 2. 形象理解

像把十页会议纪要归纳为一页行动清单，但涉及合同金额、截止时间和审批责任时不能随意省略。

**类比的局限：**摘要不是原始证据，不能用一句“已审核”代替仍需核验的签署记录。

## 3. 技术原理与核心内容

压缩管线可用 `history → classify critical facts → deduplicate → summarize/compact → verify invariants → store raw references`。重点跟踪任务目标、权限范围、活动工具请求 ID、未完成动作、证据来源和当前状态。压缩后进行问题回归或关键事实对照，确保不可恢复的信息不被抹除。系统通常还需保留必要的最新轮次和可重取的原始工具结果。

## 4. 工程实践与设计权衡

**工程案例：**运维 Agent 每轮产生数千行日志，压缩为错误码分布、首次/末次发生时间、代表性堆栈和日志 URL。要保留故障关联 ID 与原始日志位置，方便工程师验证结论。

**失败模式与验证：**关键状态被摘要成错误内容、旧错误经验被当成事实、丢失工具调用对应的 result ID、摘要截断授权范围。测试长会话多轮后的正确率、事实遗失率、源引用完整率与成本。

## 5. 关联知识与易混辨析

Context Compression 是缩减输入量的处理手段；Memory Retrieval 是从外部存储取回信息；Truncation 直接截断通常更容易丢失关键上下文，不能等同于保真压缩。

## 6. 中等难度面试题（含参考答案）

1. **问：如何判断上下文压缩是否‘成功’？** 答：不仅检查 token 压缩比，还要核对关键事实/权限/请求 ID 完整性，以及压缩前后同一任务集的成功率和错误模式。
2. **问：哪些信息不应仅被自然语言摘要而不可恢复地删除？** 答：支付事务 ID、用户授权范围、法律原文依据、仍在执行的工具请求与不可逆操作证据；应有结构化存储和原文引用。

## 7. 中等难度考试题（含解析）

1. **题：上下文从 10000 token 压到 3500 token，压缩率（按减少比例）是多少？** 解：(10000−3500)/10000=65%；节省 token 不保证 65% 性能提升。
2. **题：压缩后遗漏了一条‘不得发邮件’的用户限制，模型后续发送了邮件。问题归属哪一层？** 解：压缩未保留关键约束且执行端权限/审批不足；应将硬约束与外部动作授权独立持久化，不能只依赖摘要。
