# Document Ingestion（文档摄取）

> AI Agents · 专题：检索与知识增强 · 适用范围：知识管理与检索工程；具体 API 以版本文档为准

## 1. 核心定义

**Document Ingestion（文档摄取）**：Document Ingestion（文档摄取）是将 PDF、网页、Office、Markdown 等来源抽取、解析、标准化、分块并建立索引，使其进入可检索知识库的处理流程。它不只是‘上传成功’，还要保证来源可追溯、内容可读、权限生效与更新一致。

**适用边界：**解析准确性随文档类型变化；扫描 PDF、复杂表格、公式、图片和多栏布局可能需专门处理。未经授权的文件不能仅因被上传而允许所有检索用户访问。

## 2. 形象理解

像图书入馆：除了收下书，还要验收、编目、登记版本、归档页码并设置借阅范围。

**类比的局限：**收书入库不代表目录标注正确；如果表格被拆乱，后来检索到的句子可能改变本意。

## 3. 技术原理与核心内容

典型 ETL 是 `fetch → mime/checksum → malware/privacy checks → parse/OCR if needed → normalize → attach document/page metadata → chunk → embed/keyword index → verify counts`。应使用 doc_id、版本和 content_hash 保证幂等重摄取，支持按来源差异做增量更新。解析表格和脚注时保留结构引用，避免跨列合并导致错误语义。

## 4. 工程实践与设计权衡

**工程案例：**金融政策 Agent 摄取含表格的报销手册，需要保留行列标题与适用地区；如果 OCR 将 1000 识别成 10000，系统必须检测结构异常并人工复核后再允许用于回答金额上限。

**失败模式与验证：**文件类型伪装、页码丢失、跨用户权限继承错误、索引部分提交、旧版本仍可检索、文档内隐藏提示注入。用抽样视觉对照、内容哈希、文档数/段落数校验和索引同步失败回归。

## 5. 关联知识与易混辨析

Document Ingestion 是知识库的离线/增量导入阶段；Chunking 是其中分块步骤；Embedding 产生语义向量；Retrieval 是读索引并返回相关内容的在线阶段。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 PDF 上传成功不表示可放心用于 RAG？** 答：仍可能解析丢表格、公式或页码，索引未完成或权限错配；需验证内容覆盖、结构一致性和可定位来源。
2. **问：如何安全处理同一文档的新版本？** 答：用稳定 doc_id、content_hash 和版本元信息更新，原子替换或明确并存，清理/标记旧索引，避免新旧条款混用。

## 7. 中等难度考试题（含解析）

1. **题：某次摄取 80 份文件，其中 5 份解析失败、3 份权限检查拒绝且互不重叠，最多进入索引多少份？** 解：80−5−3=72 份，最终应以索引提交验证为准。
2. **题：同一文档重复上传两次，content_hash 相同且采用幂等摄取，应产生几份逻辑文档？** 解：1 份逻辑文档，除非业务明确要求保留两个不同身份的副本。
