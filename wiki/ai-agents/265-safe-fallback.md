# Safe Fallback（安全回退）

> AI Agents · 专题：安全防护与治理 · 明确安全边界、执行权限与可验证的用户决定

## 1. 核心定义

**Safe Fallback（安全回退）**：Safe Fallback（安全回退）是在目标操作因权限、资源、模型不确定性或环境故障无法安全继续时，转向风险更低的行动，例如只读解释、请求补充信息、转人工、保存未提交草稿或结束任务。它要求不越过用户授权和禁止事项。

**适用边界：**回退不能私自替用户作出不可逆替代动作，也不能把部分结果冒充完全成功。特别是外部工具超时后结果未知时，安全回退可能是保留事务 ID、暂停后续步骤和查询权威状态，而不是重新执行。

## 2. 形象理解

像导航在道路关闭时建议绕行或停车等待，但不能擅自把车辆开上禁止通行的应急道路。

**类比的局限：**回退可能牺牲速度或完成度，需要向用户清楚标识未完成步骤和实际风险。

## 3. 技术原理与核心内容

设计 FallbackDecision={original_goal,blocking_condition,safe_options,required_approval,partial_artifacts,unknown_operations}。策略层先判断是否允许继续；如果不可执行写操作，可选择 read-only plan 或生成待批准草案；若缺事实则标 unknown 并补充检索。系统不能自动扩大 scopes 或将不可信检索结果变为权威决定，必须在执行层再次校验新路径的所有工具权限和 side effect。记录 fallback_reason 和用户可操作下一步，避免循环重试。

## 4. 工程实践与设计权衡

**工程案例：**自动部署 Agent 发现生产集群的当前版本不明，且审批 SHA 已过期。安全回退为保存变更计划与 CI 日志，告知需要运维重新确认；不能默认部署到另一个集群或以旧签名继续。

**失败模式与验证：**回退路径本身越权、隐瞒部分结果状态、用过时缓存推断成功、遇到 403 后换其他 token 绕过。测试安全策略阻断、无可用回退和重复失败退出条件。

## 5. 关联知识与易混辨析

Safe Fallback 是替代路径；Refusal 是不执行当前动作；Failover 是切换运行节点或服务；Compensation 是撤销已提交业务效果的后续操作。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么‘换一个有管理员权限的服务再试’不是安全回退？** 答：这会扩大权限或绕过拒绝，违反最小权限与授权约束。
2. **问：支付 API 返回 timeout 的合理安全回退是什么？** 答：记录原 operation_id、暂停依赖动作、查询支付网关权威状态，并向用户披露 unknown。

## 7. 中等难度考试题（含解析）

1. **题：一个任务有 4 个步骤，前 3 个只读完成，最后 1 个写操作被拒，能说整个任务成功吗？** 解：不能，应该报告 3/4 部分完成及最后一步未执行。
2. **题：安全回退可提供 2 种合法只读方案，但都未获用户选择，能自动提交付款吗？** 解：不能，默认继续只读或询问用户，不得擅自执行付款。
