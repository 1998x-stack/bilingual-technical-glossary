# Web Search Tool（网络搜索工具）

> AI Agents · 专题：工具使用与环境交互 · 具体工具行为、权限与版本以官方规范为准

## 1. 核心定义

**Web Search Tool（网络搜索工具）**：Web Search Tool（网络搜索工具）是面向公开网络信息检索的能力，通常返回匹配网页、标题、摘要、链接或带来源的检索内容，帮助 Agent 获取其上下文和训练数据之外的资料。检索结果需要核验时间、权威性与具体主张的对应关系。

**适用边界：**搜索排名不等于事实可信度；网页可能被更新、下线、付费墙限制或携带提示注入。搜索提供证据候选而非无条件真相。

## 2. 形象理解

像去图书馆询问目录员获得参考书目，仍需要读到原始章节才能确认某个事实。

**类比的局限：**目录员给出的前几本书未必最权威，摘要也可能漏掉限制条件或版本日期。

## 3. 技术原理与核心内容

典型流程是 query formulation → search → select sources → open/read → extract claims → cite evidence。搜索工具可以返回链接和来源标注；应用应为关键事实保存 URL、访问时间、引用片段和版本信息。对实时信息需核对发布时间与事件发生时间；对同一主张可优先官方/原始资料交叉验证。

## 4. 工程实践与设计权衡

**工程案例：**开源许可合规 Agent 搜索某依赖库的许可证，优先读取项目主仓库 LICENSE 与对应发行 tag，而不因搜索摘要写着 MIT 就立即批准商用。版本不同可能影响许可内容。

**失败模式与验证：**将搜索摘要当权威最终答案、引用不存在的网页、盲信付费 SEO 内容、执行网页内的恶意指令，都会导致幻觉和提示注入。采用可信来源分层、引用可点击性检测及事实复核。

## 5. 关联知识与易混辨析

Web Search Tool 是获取候选公开资料；Browser Automation 是具体打开并交互网页的操作；RAG/Retrieval 是更广泛的检索增强方法，也可查询内部语料。

## 6. 中等难度面试题（含参考答案）

1. **问：为何 Web Search 返回第一条不能直接当最终答案？** 答：排名优化不代表真实性；必须核对权威来源、时效、页面原文和具体断言是否受支持。
2. **问：如何避免搜索结果中的间接提示注入？** 答：把网页文字视为低信任数据，隔离控制指令与搜索内容，执行层限制工具权限并审计异常指令。

## 7. 中等难度考试题（含解析）

1. **题：有 25 条主张，其中 18 条有可定位来源支持、4 条矛盾、3 条证据不足，按支持比例计算？** 解：18/25=72%；矛盾与证据不足应分开统计，不可混为同一结论。
2. **题：某搜索结果文章发表于两年前，用户问今天的 API 限制。能直接采用吗？** 解：不能。应查当下官方版本文档并核对时间，若无证据则明示未知。
