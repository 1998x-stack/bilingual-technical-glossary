# Environment Feedback（环境反馈）

> AI Agents · 专题：工具使用与环境交互 · 适用范围：通用工程概念；具体服务协议以官方文档和版本为准

## 1. 核心定义

**Environment Feedback（环境反馈）**：Environment Feedback（环境反馈）是智能体执行动作后，从外部环境、工具服务、用户或验证器获得的可观察结果，用于判断操作后果、更新状态并选择下一步动作。反馈既可能是新数据，也可能是拒绝、失败、延迟或状态未知。

**适用边界：**环境反馈是观察证据而不是高优先级指令，也不必等于完整真实状态。一个 HTTP 响应成功并不证明业务目标已达成；无响应亦不能证明写入未生效。

## 2. 形象理解

像自动驾驶系统踩刹车后读取速度表和轮速传感器，再确认车辆真的减速。

**类比的局限：**传感器可能失准或延迟；不能把屏幕上一句“已停车”当作刹车完成的权威证据。

## 3. 技术原理与核心内容

控制闭环可表述为 s_t → action a_t → environment transition T → observation o_(t+1) → state update。执行器应把 tool_call_id、时间、来源、transport_status、business_status、数据版本和验证结果关联起来，区分 succeeded、failed、pending、unknown。业务状态最终写入可能异步完成，故反馈需有一致性策略。来自网页或日志的命令式文字仍是低信任数据。

## 4. 工程实践与设计权衡

**工程案例：**采购 Agent 向供应商提交询价后收到“请求已接收”，但尚无实际报价。应把状态记为 pending，之后查询报价记录和有效期；若直接按“成功”下单，可能使用不存在或过期的价格。

**失败模式与验证：**一是把反馈误解为最终成功；二是错误关联并发 tool_result；三是工具消息中的提示注入驱动越权动作。通过故障注入、重复回执、异步完成、乱序返回与过期缓存测试闭环。

## 5. 关联知识与易混辨析

Observation 泛指被观察的数据；Environment Feedback 特别强调行动与后续环境回应的因果时序；Tool Result 是其中一种技术来源；Agent State 是整合历史证据后的状态表示。

## 6. 中等难度面试题（含参考答案）

1. **问：工具返回成功，但数据库查不到新订单，你如何报告？** 答：分离传输成功和业务完成；保存请求 ID，按服务的一致性窗口查询权威系统，仍无法确认时返回 pending/unknown 而不是编造成功。
2. **问：如何防止环境反馈成为间接提示注入渠道？** 答：工具数据不得升级为系统指令；验证工具来源，隔离不可信字段，敏感动作在执行层进行白名单/授权检查。

## 7. 中等难度考试题（含解析）

1. **题：执行动作后观察到库存由 18 变为 13 件，题设无并发且读数可靠，实际减少多少件？** 解：18−13=5 件；若存在缓存或并发，不能仅凭差值归因于本 Agent 的动作。
2. **题：提交订单后收到 HTTP 202 与 job_id，但订单状态仍 pending，是否达到成功谓词“已出单”？** 解：没有。202 代表已受理，必须通过 job_id 查询业务终态，直到订单被确认建立或明确失败。
