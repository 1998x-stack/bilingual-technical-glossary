# Tool Routing（工具路由）

> AI Agents · 专题：工具使用与环境交互 · 通用工程概念；具体行为以平台、协议与版本为准

## 1. 核心定义

**Tool Routing（工具路由）**：Tool Routing（工具路由）是将已经选择且经过校验的工具请求，按照命名空间、版本、租户身份和协议分派给实际后端执行器的基础设施过程。它与模型根据任务语义选择工具是不同阶段。

**适用边界：**路由成功不等于工具执行成功；不能把模型返回的任意 URL 直接作为后端，防止 SSRF、内网访问与凭证误发。

## 2. 形象理解

快递分拣系统按地区和授权网点分发包裹，保证它进入正确配送链。

**类比的局限：**分拣正确不等于包裹已签收；渠道路由本身也必须核对安全与身份限制。

## 3. 技术原理与核心内容

采用受信任的 registry 解析 namespace.tool@version → 鉴权及租户绑定 → 选择 adapter/backend → 参数序列化 → 请求 → 标准化结果。服务地址来自批准配置，不来自模型自由生成文本。只读服务可以按策略故障转移；非幂等写入必须先确定原目标事务是否已生效。

## 4. 工程实践与设计权衡

**工程案例：**公司内部有 sales.get_status、finance.get_status 等相似能力；路由时按命名空间和租户确定后端，用服务器管理的服务身份调用，结果带 trace_id。跨租户缓存必须分隔，防止其他客户数据泄漏。

**失败模式与验证：**错命名空间会调用无关服务；无认证路由可能泄露内网 API；超时自动转发第二个写入接口可能双扣款。用多租户隔离、故障注入和同名工具回归测试验收。

## 5. 关联知识与易混辨析

Selection 是选择语义能力；Routing 是绑定执行目标；Tool Adapter 是统一协议差异的层；Tool Registry 保存可信工具元信息。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么不应让模型直接传任意 endpoint？** 答：它可能指向攻击者站点或内部服务；路由必须使用受控白名单/注册表、服务身份鉴权和网络隔离。
2. **问：如何安全支持多租户工具调用？** 答：可信上下文中绑定 tenant_id，权限和工具空间按租户隔离，结果缓存与审计也按租户分区。

## 7. 中等难度考试题（含解析）

1. **题：一个路由器按 2:3:5 向三个后端分流 1000 次请求，理论各分多少？** 解：200、300、500 次；前提是各后端健康且没有其他约束。
2. **题：非幂等付款写请求超时，路由器直接将其发给另一个后端，主要风险？** 解：第一次可能已完成付款，故障转移导致重复写；必须检查权威状态及端到端幂等协议。
