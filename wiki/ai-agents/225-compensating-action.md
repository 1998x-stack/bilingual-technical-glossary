# Compensating Action（补偿操作）

> AI Agents · 专题：执行状态、持久化与恢复 · 时延、恢复和外部事务的真实边界

## 1. 核心定义

**Compensating Action（补偿操作）**：Compensating Action（补偿操作）是对已成功执行且无法纳入统一事务回滚的业务步骤采取具有相反业务效果的后续动作，例如取消预订、冲销账务或撤回通知。它属于 Saga/补偿事务设计，不等同于数据库回滚或简单重复负值操作。

**适用边界：**补偿未必能完全还原原状态：邮件已送达、运费已产生、市场价格已变化或外部用户已看到信息，均不能通过 API 完美逆转。必须遵守新的授权、审计和补偿幂等约束。

## 2. 形象理解

像旅行订了机票和酒店后取消行程，需要分别申请退款和取消住宿；即使成功，手续费也可能无法追回。

**类比的局限：**补偿有业务成本与剩余责任，不能声称所有副作用从未发生。

## 3. 技术原理与核心内容

跨服务 Saga 序列 T1…Tn，每个提交步骤指定可行的补偿 C_i，失败后按依赖以适当顺序执行补偿，并记录 compensation_id、原始 operation_id、权限与结果。补偿本身可以失败，需重试策略、人工升级和对账；对于不可补偿动作，应在执行前设定更严格 gate。原先的付款流水不能直接删除，应该通过冲销凭证形成可审计的逆向交易。

## 4. 工程实践与设计权衡

**工程案例：**旅游 Agent 先订酒店再订高铁，高铁无票时调用酒店取消接口；若酒店已过免费取消期，补偿只可按当前政策申请部分退款并把剩余费用报告给用户。

**失败模式与验证：**补偿顺序不满足依赖、双重退款、把冲销当数据库删除、对不可逆邮件声称完全撤回。用补偿中断、退款失败、重复调用和审计余额测试。

## 5. 关联知识与易混辨析

Compensating Action 是补救某个外部副作用；Transaction Boundary 是局部原子性边界；Retry 是重复原操作；Cancellation 表示希望停止正在进行的工作，不会天然冲销已提交结果。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么补偿操作不能简单写成对付款金额取负数？** 答：合法退款/冲销涉及原始交易 ID、支付渠道、规则和审计凭证，不一定可直接用负金额抵消。
2. **问：补偿失败是否意味原业务步骤自动撤销？** 答：不，需保持明确未补偿状态、对账和人工升级，不能隐瞒风险。

## 7. 中等难度考试题（含解析）

1. **题：预订酒店 300 元，取消只可退 80%，补偿成功退多少且仍损失多少？** 解：退款 300×0.8=240 元，损失 60 元。
2. **题：三个已提交步骤 T1、T2、T3，T3 导致整体失败，通常需要如何组织补偿？** 解：依据依赖与业务契约逆向补偿可撤销的步骤，不机械假定任意顺序都安全。
