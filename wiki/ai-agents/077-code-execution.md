# Code Execution（代码执行）

> AI Agents · 专题：工具使用与环境交互 · 具体工具行为、权限与版本以官方规范为准

## 1. 核心定义

**Code Execution（代码执行）**：Code Execution（代码执行）是 Agent 在受控计算环境中运行程序，以完成确定性计算、数据转换、脚本测试、文件处理或模型无法可靠心算的任务。执行代码产生的输出可作为独立验证依据，但它本身也带有安全风险。

**适用边界：**代码可能读取文件、发送网络请求或执行系统命令，因此应按任务分配容器/沙箱权限与资源上限；不能把模型生成代码视为安全代码。

## 2. 形象理解

像把数学公式交给计算器或实验室仪器，得到实际可复现的运算结果。

**类比的局限：**计算器程序写错也会给出错误答案；运行成功与业务正确性并不必然一致。

## 3. 技术原理与核心内容

典型管线是 generate/source code → static checks → select sandbox → execute with CPU/memory/time limits → capture stdout/stderr/exit code/artifacts → validate results。网络访问、凭证、目录挂载应最小化，执行进程不能拥有未授权主机权限。对外部代码依赖固定版本并记录输入/环境，避免无提示地安装不可信包。

## 4. 工程实践与设计权衡

**工程案例：**数据分析 Agent 读取脱敏 CSV，用受控 Python 计算均值与标准差并生成图表。若数据含 PII，执行环境避免外部网络，将敏感信息保存在授权范围，最终文件输出经过质量检查。

**失败模式与验证：**无限循环造成资源耗尽、模型生成 shell 注入、依赖供应链风险、路径泄露和数据出站都是常见问题。应注入超时、无权限文件访问、错误退出码并验证工作区清理。

## 5. 关联知识与易混辨析

Code Execution 泛指运行任意程序；CLI 是命令行入口形式；Function Tool 可以封装固定计算函数，范围更窄、可控性通常更好；结果验证应独立于程序能否启动。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 Agent 写的 Python 脚本不能直接在宿主生产机执行？** 答：代码来源不受完全信任，可能访问文件、网络和凭证；应用应采用沙箱、权限隔离、资源配额和必要的静态/动态审查。
2. **问：程序退出码为 0 是否证明计算结果正确？** 答：不证明。进程正常退出只表示控制流完成，仍需断言、独立测试、数值范围检查和数据来源验证。

## 7. 中等难度考试题（含解析）

1. **题：一个脚本最多允许 4 秒，执行 6 秒后被终止。应记录哪种结果？** 解：超时/资源限制终止，而不是成功；需保存日志与是否产生部分输出的状态。
2. **题：对数组 [2,4,6,8] 计算平均值，使用运行器结果 5。如何独立核对？** 解：(2+4+6+8)/4=5；还应确认输入数组和程序版本正确。
