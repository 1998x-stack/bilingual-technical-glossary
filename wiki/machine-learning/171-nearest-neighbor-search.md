# Nearest Neighbor Search（最近邻搜索）

> 领域：机器学习 · 专题：支持向量机、核方法与近邻 · 数学、工程实践及邻域检索

## 1. 核心定义

最近邻搜索（Nearest Neighbor Search）是在指定特征表示和距离/相似度规则下，针对查询向量找出索引库中最相近的一个或多个样本的检索问题。它可以是 KNN 分类器的底层操作，也可以独立用于向量检索、推荐召回、去重和异常检测。

## 2. 形象理解

像图书馆找与某篇文章语义最接近的几篇旧文献：搜索先返回候选和相似分，后面是否分类、推荐或人工审核是另一阶段。

**类比的局限：**返回最近不意味着真的相关或正确；距离函数、向量模型、过滤权限和索引新鲜度会显著影响结果。

## 3. 技术原理与核心内容

精确暴力搜索对 n 个 d 维样本一次查询的基本距离计算约 O(nd)；KD-tree/ball-tree 可在低维、合适度量下通过剪枝减少查询候选，但高维会遇到维数灾难。近似最近邻（ANN）允许牺牲一些真实 top-k 召回率以换取速度与内存，可用 HNSW/IVF 等结构（具体索引支持依系统）。评估 Recall@k 需以同一嵌入与度量的精确 top-k 作为基准；还需监控 P95 延迟、更新成本和并发。

## 4. 工程实践与设计权衡

知识库 RAG 检索采用统一 embedding 版本、固定归一化规范与精确 top-k 基准，比较 ANN 索引配置；保证租户过滤、过期文档删除与权限更新正确，不能只看向量 Recall。

## 5. 关联知识与易混辨析

Nearest Neighbor Search 只定义查询检索；KNN 在结果上投票/回归；Cosine Similarity 定义排序依据，Euclidean Distance 是可选距离；Vector Database 是承载数据、索引和过滤的系统层。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 ANN 索引召回率要相对于精确同口径 top-k 计算？** 答：否则无法区分索引近似丢失和向量模型语义质量问题；同一个 embedding 与距离度量的精确答案才是相应检索基准。

2. **问：为何高维 KD-tree 不必然比 brute force 更快？** 答：空间划分剪枝能力随维度提高下降，索引和分支开销可能超过直接批量向量化扫描；需按真实数据与查询负载评测。

## 7. 中等难度考试题（含解析）

1. **题：100 万条 128 维向量逐点算 L2 距离，忽略常数项一次查询约需要多少标量维度比较？** 解：n×d=1,000,000×128=128,000,000 个维度的差与平方贡献，未计索引/硬件向量化。

2. **题：查询的精确 top-5 是 {1,2,3,4,5}，近似返回 {2,4,5,7,8}，Recall@5？** 解：共同元素为 {2,4,5} 共 3 个，Recall@5=3/5=0.6。
