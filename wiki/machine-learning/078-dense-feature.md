# Dense Feature（稠密特征）

> 领域：机器学习 · 专题：数据预处理与特征工程 · 定义、原理、数学与真实工程边界

## 1. 核心定义

稠密特征是多数维度具有实际数值的向量或矩阵表示，例如连续传感器统计量、浮点隐层激活和典型的神经嵌入向量。它支持连续内存与高效向量化，但“稠密”是表示特性，不等于携带更多有效信息。

## 2. 形象理解

像一张每个格子几乎都写了数字的表格，整块搬运和矩阵乘法便利；空格极少时无需记录空格位置。

**类比的局限：**稠密数值可能来源于无意义噪声；所有维度非零并不意味着信息充分，也不自动解决数据偏差。

## 3. 技术原理与核心内容

对于 n×d 的 float32 稠密矩阵，原始数值存储约 4nd 字节，矩阵乘法及批量归一化易利用 BLAS/GPU。若原始为极稀疏词袋却转换成 dense，内存会从 O(nnz) 膨胀到 O(nd)。训练时需考虑 dtype、顺序、对齐、批大小与缺失值 NaN 的算子语义；尺度调整应使用训练折统计参数。

## 4. 工程实践与设计权衡

多模态检索中 768 维向量常以连续 float32 保存并使用向量索引，但需比较 float16/int8 量化的召回影响及冷启动缺失；存储 100 万向量时单原始特征数据量已可达数 GB。

## 5. 关联知识与易混辨析

Dense Feature 与 Sparse Feature 描述值分布及数据存储；Embedding 是语义/表示学习方法，通常产生 dense 向量但存在稀疏嵌入等变体；Dense Layer 是神经网络全连接层，概念不同。

## 6. 中等难度面试题（含参考答案）

1. **问：什么时候将稀疏特征转换为 dense 会造成工程事故？** 答：若高维且每行仅少量非零，物化 n×d 数据占用巨大内存，甚至触发 OOM；先估算字节数并寻找稀疏兼容算子。

2. **问：为什么稠密 embedding 需要检查向量范数分布？** 答：模型输出可能随领域、长度或训练批次发生范数漂移；余弦与内积检索对范数敏感度不同，需明确检索相似度和归一化约定。

## 7. 中等难度考试题（含解析）

1. **题：1000000 个 128 维 float32 向量，纯原始数值占多少字节？** 解：1,000,000×128×4=512,000,000 字节，约 512 MB（十进制），未计索引结构。

2. **题：一个 50×20 的 float64 稠密矩阵仅算数据值占多少字节？** 解：50×20×8=8,000 字节；对象与元数据另算。
