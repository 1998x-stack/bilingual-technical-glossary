# Sandbox（沙箱）

> AI Agents · 专题：安全防护与治理 · 明确安全边界、执行权限与可验证的用户决定

## 1. 核心定义

**Sandbox（沙箱）**：Sandbox（沙箱）是为 Agent 生成的代码、浏览器操作、外部文件解析和工具执行建立资源与权限受限的运行环境，使不可信程序即使出错或遭攻击也难以影响宿主系统。沙箱可使用容器、虚拟机、用户态内核或其他隔离机制，但隔离强度不同。

**适用边界：**Docker 容器不等于高强度安全 VM：共享宿主内核与权限配置可能导致逃逸。沙箱也不能替代应用层资源 ACL、网络出口控制或用户确认；高危工具权限必须另外限制。

## 2. 形象理解

像化学实验在独立通风柜中操作危险试剂，柜内可完成实验，但泄漏物和能量被严格限制在安全范围。

**类比的局限：**通风柜不是万能屏障，错误接入实验室管线仍可能造成外部影响，需要其他安全操作规程。

## 3. 技术原理与核心内容

定义执行 profile={read_roots,write_roots,network_allowlist,cpu,memory,wall_time,syscalls,secrets}。通过容器 seccomp、user namespace、rootless、read-only fs、资源配额和 egress proxy 限制操作；不挂载主机 Docker socket，不直接继承生产云凭证。需更强隔离可使用 gVisor 或 VM；在解压、运行任意脚本和解析恶意文档时尤其要考虑文件穿越、OOM、fork bomb 和网络 SSRF。所有工具完成后检查输出文件归属和哈希。

## 4. 工程实践与设计权衡

**工程案例：**代码 Agent 自动执行不可信 PR 的测试脚本，在临时容器中只读挂载源码，写入允许的 build/，禁止公网和云元数据服务访问，最多使用两核与 2GB 内存。任务成功后仅导出有验证签名的测试报告，不保留 secret。

**失败模式与验证：**容器启用 privileged、挂宿主 socket、网络可以访问内部 IMDS、临时文件泄漏到其他任务、进程退出后资源未清理。做越权文件读取、SSRF、逃逸尝试和资源耗尽测试。

## 5. 关联知识与易混辨析

Sandbox 约束执行环境；Access Control 控制业务对象访问；PoLP 最小化授权；Trust Boundary 识别低信任输入进入高权限组件的交界。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么不能把 Docker 容器称作绝对安全隔离？** 答：容器共享宿主内核且隔离取决于配置，privileged、挂载 socket 和过宽网络都可能削弱保护。
2. **问：为何沙箱仍需要服务端 ACL？** 答：即使沙箱无法访问宿主文件，仍可能通过被允许的 API token 越权读取业务对象。

## 7. 中等难度考试题（含解析）

1. **题：沙箱允许读 5 个目录但任务只需 2 个，按最小权限应怎么设定？** 解：仅开放必要的 2 个目录及相应文件范围。
2. **题：脚本使用 2.5GB 内存，容器限制 2GB，安全执行器应如何处理？** 解：触发资源限制/终止，明确报告不完整而不放宽到宿主无限内存。
