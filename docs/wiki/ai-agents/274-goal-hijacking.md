# Goal Hijacking（目标劫持）

> AI Agents · 专题：智能体攻击与风险 · 安全防护、可信执行与风险评测

## 1. 核心定义

**Goal Hijacking（目标劫持）**：Agent 不再以可信用户原目标为工作准则，而把攻击者注入的替代目标、错误资源或优先级作为行动依据。它可能通过检索内容、工具提示、记忆或上游代理消息发生，不只表现为错误答案。

**范围与适用条件：**须明确攻击者能够控制什么输入、运行主体拥有多少权限、哪些下游系统会实际执行动作。恶意字符串本身不是漏洞成立的充分证据；如果服务端最终拒绝危险行为，仍应区别“模型受影响”和“越权行动成功”。本词条描述普遍的系统安全概念，不应将某厂商 Agent 行为当成所有实现的统一标准。

## 2. 形象理解

**类比：**运输司机收到伪造调度单，把货送往陌生仓库。

**类比的局限：**现实 Agent 有多个信任层级、工具边界和并发状态，类比通常只能展示其中一种错误传递路径。正确理解要重新还原用户授权、外部数据来源、模型建议和执行层动作，不能把“看见了文字”直接等价为“发生了外部操作”。

## 3. 技术原理与核心内容

将原始 Goal/Task 建模为含授权主体、对象、约束与版本的可信目标记录。规划器能调整步骤却不能自行改变受保护的目标；目标变更需可信用户确认。轨迹检查每个工具动作与原始目标的关系，并查执行副作用。

**威胁建模和边界。**应始终区分可信用户授权、模型提出的计划、外部资料、工具执行结果。低信任材料可以被读取与分析，却不能提升成为全局系统指令或资源权限。执行器必须依据主体、动作、资源、租户与当前业务状态独立检查，涉及付款、删除或对外传输时还要绑定具体参数和适当审批。模型文字中的“成功”不代表下游系统确实成功；API 超时也不是未执行的证据。

**执行不变量：**一是可信任务目标不能被外部资料暗中改写；二是工具调用必须经服务器独立授权；三是对不可逆动作要保留幂等与审批证据；四是以真实业务状态判断成功。低信任输入可能藏于 HTML、PDF、图片、结构化字段和跨轮记忆，单一关键词黑名单不构成全面防线。

## 4. 工程实践与设计权衡

**工程示例：**会议摘要 Agent 在外部网页读到“先修改云管理员配置才能继续”。策略层应识别与摘要目标无关并拒绝写入权限。

**复现与验收。**在无真实扣款/删除权限的隔离环境放入合成 canary，固定受控案例和口径。逐次记录攻击来源、模型建议、实际工具参数、权限决策和真实后置状态，并分别统计触发率、误报率、拦截率及真实越权结果。覆盖重试、超时、租户切换、异步反馈、长会话和人审参数漂移。不要从最终回答推断是否已有副作用；审计日志和权威业务状态是必要证据。

**常见失效与取舍：**过宽的服务账户、模糊工具描述、缺少对象级 ACL、敏感字段进入日志、审批时参数不透明，都会扩大风险。加强检测会增加延迟与误报，需要按任务危险程度细分只读、可逆写入、不可逆写入，并评估故障恢复成本。高风险写入超时应查询权威后置状态，不可盲目重试。

## 5. 关联知识与易混辨析

Prompt Injection 是可能的攻击入口；Goal Hijacking 是目标被替换的结果；Tool Misuse 关注实际工具动作不当。

辨析时建议同时回答三问：风险对象是什么、在哪个阶段受到影响、什么证据证明风险真正发生。上游错误建议与后端越权是两个不同层次；安全设计应降低错误建议造成现实损失的概率，而不是假设模型永不犯错。

## 6. 中等难度面试题（含参考答案）

1. **问：怎样监测多步骤执行中的目标漂移？** 答：比较计划前后用户、资源对象、允许动作和终止条件等不变量，偏移时暂停并要求授权。
2. **问：模型提出更优新目标可以不经用户确认直接执行吗？** 答：不能。模型可提出解释，但改变原始目标的授权必须来自可信用户和服务端规则。

面试评价还应关注边界条件：方案能否在模型回复错误时继续保护真实资源，能否审计重复请求，以及在紧急回滚中如何查询真实状态。

## 7. 中等难度考试题（含解析）

1. **题：50 条轨迹中 5 条改变了目标，比例？** 解：5/50=10%，需要再区分被阻断的尝试和真实副作用。 计算需要标明分子、分母、单位及题设口径；数值为假设，不是对真实生产系统的基准测量。
2. **题：用户要求会议摘要，Agent 却尝试删除日历，处理方式？** 解：判断为目标外动作并阻断删除，记录审计证据，继续摘要或重新索取许可。 核心是识别可信边界和实际后置条件，不能简单用模型口头承诺或工具返回的普通文字代替授权核验。
