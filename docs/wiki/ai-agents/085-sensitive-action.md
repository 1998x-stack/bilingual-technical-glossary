# Sensitive Action（敏感操作）

> AI Agents · 专题：工具使用与环境交互 · 适用范围：通用工程概念；具体服务协议以官方文档和版本为准

## 1. 核心定义

**Sensitive Action（敏感操作）**：Sensitive Action（敏感操作）是在财务、隐私、权限、安全、外部通知、删除或生产基础设施领域可能造成较高后果的行为。Agent 系统应按风险强制权限、前置确认与独立验收，而不是只在提示词中要求模型谨慎。

**适用边界：**敏感程度依业务场景、金额、数据分类、影响半径及用户身份变化；只读动作也可能因读取机密信息而敏感，不能只按读写二分。

## 2. 形象理解

医院护士能查看与工作有关的病历，不代表可以随意修改处方或把病历发送给任何人。

**类比的局限：**权限不是人为“信任模型”就自然出现，必须以真实身份和资源范围为基础。

## 3. 技术原理与核心内容

可将每个工具动作标记 risk_level、required_scope、approval_policy、side_effect_class、audit_rule。执行管线先用服务端身份做 AuthZ，检查资源归属、金额/频率/目的，再要求必要的人类批准（明确展示实际参数），最后以幂等事务执行和记录核验。特别防范跨工具链越权：一个低风险搜索结果不能变成删除权限或出站发送指令。

## 4. 工程实践与设计权衡

**工程案例：**HR Agent 获授权读取部门招聘统计，但批量导出员工个人信息属于敏感动作。需要独立导出权限、范围和用途确认，审计导出对象；若用户只要求统计，优先返回脱敏聚合。

**失败模式与验证：**广泛部署管理凭证、让模型直接控制任意 CLI、自动点击付款确认、忽略二次确认和审批范围，都会扩大 Excessive Agency 风险。评估权限拒绝率、误放率、审批匹配和高后果事故模拟。

## 5. 关联知识与易混辨析

Sensitive Action 是风险分类；Side Effect 是状态变化；Authorization 是主体-资源-动作的许可检查；Human-in-the-loop 是某些高风险决策的审批机制，不替代强制授权。

## 6. 中等难度面试题（含参考答案）

1. **问：为何只读读取 API 也可能是敏感操作？** 答：读取医疗记录、工资和凭证可能侵犯隐私；需要按数据分类和身份最小权限限制，不能只把写操作标成高风险。
2. **问：模型称用户曾经批准过删除，足够执行吗？** 答：不够。应在可信审批通道验证批准主体、目标、范围、版本与有效期，再由服务端独立授权。

## 7. 中等难度考试题（含解析）

1. **题：题设每笔付款大于 500 元必须人工复核；请求金额 500 与 501 元分别如何处理？** 解：500 元不触发该金额阈值，501 元触发人工复核；两者仍需正常身份及业务校验。
2. **题：一个只读查询会返回全部员工工资单，另一个写操作只更新用户自己的显示主题。哪一个必然更敏感？** 解：无法单按读写判断；工资单读取具有高隐私风险，主题更新通常低风险，必须结合数据与业务影响评估。
