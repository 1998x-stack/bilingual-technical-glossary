# Subtask（子任务）

> AI Agents · 专题：基础概念与角色 · 适用范围：通用智能体系统设计；具体 SDK 与平台版本以对应文档为准

## 1. 核心定义

**Subtask（子任务）**：Subtask 是从更大 Task 拆出的可执行、可验收的子工作单元。它继承上层任务的授权与成功标准，但可有独立依赖、执行者和重试策略。

**适用边界：**子任务不一定是模型的一次调用；它可以是多个工具操作形成的局部工作流。

## 2. 形象理解

写报告时，把“完成报告”拆成数据收集、制图、校对和发布四张子任务卡。

**类比的局限：**拆得越细不一定越快；交接、网络调用和上下文同步都有成本。

## 3. 技术原理与核心内容

构建依赖图：子任务节点包含 input、outputs、preconditions、acceptance；边表示依赖。调度只能在前置任务满足后释放节点；结果汇总需校验每个关键子任务及最终目标。拆分必须明确失败传播和不可撤销副作用。

## 4. 工程实践与设计权衡

智能研究助手将“对比三家云服务”拆成三个并行数据收集子任务和一个串行综合评估子任务；所有引用需保存来源，任一未完成则报告证据缺口。

## 5. 关联知识与易混辨析

Task 是一个可交付单元；Subtask 强调隶属关系；Tool Call 是执行动作，可能是一个子任务的局部步骤。

## 6. 中等难度面试题（含参考答案）

1. **问：拆分子任务的边界怎样确定？** 答：以可独立验证、上下文最小化和失败隔离为原则，同时估算协调成本；有强共享状态的任务不宜机械拆成多 Agent。
2. **问：某子任务失败时是否重跑整个目标？** 答：先判断是否存在隔离的重试或替代数据源；若已有外部写操作，需核对状态与补偿策略，不能盲重跑。

## 7. 中等难度考试题（含解析）

1. **题：假设 3 个独立子任务分别耗时 2、4、5 min，并行无限资源且汇总需 1 min，总用时下界？** 解：max(2,4,5)+1=6 min；串行则 2+4+5+1=12 min，忽略调度开销。
2. **题：A 与 B 均依赖数据收集 C，D 必须等待 A、B，哪些子任务能并行？** 解：先完成 C，再并行 A 与 B，最后执行 D；不能在 C 完成前启动依赖任务。
