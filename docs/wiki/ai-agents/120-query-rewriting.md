# Query Rewriting（查询改写）

> AI Agents · 专题：检索与知识增强 · 信息检索基础与 Agent 工程实践；计算示例为教学题设

## 1. 核心定义

**Query Rewriting（查询改写）**：Query Rewriting（查询改写）是在检索前将用户自然语言问题改为更适合搜索系统的表达，可以进行消歧、同义扩展、拼写修正、补足上下文和拆成多个子查询。改写必须保存用户的关键约束与意图，不能擅自改变目标。

**适用边界：**并非所有改写都会提升质量；过度扩展可能引入噪声，删除地区、时间、否定与精确型号会导致错误召回。改写后的字符串仍需受到权限和查询开销限制。

## 2. 形象理解

像图书馆员把‘上次那个网络连不上’ 明确为‘公司 VPN 登录失败 Windows 11 官方排障步骤’，同时保留原问题要求。

**类比的局限：**如果馆员擅自把‘今年政策’简化成‘政策’，就可能给出过期答案。

## 3. 技术原理与核心内容

可实现 `original query → extract invariants(date,region,entity,negation) → rewrite/expand → retrieve → evaluate coverage → optionally refine`。Ma 等的 Rewrite-Retrieve-Read 研究通过专门的重写阶段帮助后续检索与阅读模型。工程上可选择多查询检索、HyDE 或基于历史的消歧，但所有变换需保留原始 query、规则约束和来源，不能将模型生成的假设当成已确认事实。

## 4. 工程实践与设计权衡

**工程案例：**员工问‘上周提交的国内差旅怎么报？’，Agent 提取差旅类型、日期和区域后，将检索请求改成‘国内差旅报销制度 2026 生效版本’，并补查用户具体单据；不能把‘国内’改成‘国际’或删除时间限制。

**失败模式与验证：**改写导致实体漂移、把推测的用户地点写进查询、无限生成相近查询而浪费成本、注入网页内容改变搜索目标。评估改写后 recall@k、最终答案支持率、原始约束保持率和查询数。

## 5. 关联知识与易混辨析

Query Rewriting 是上游查询表达变换；Agentic Retrieval 决定多轮何时/到何处检索；Hybrid Search 融合不同检索信号；Reranking 对已有候选后处理。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么查询改写要提取不可丢失的条件？** 答：时间、地区、实体 ID 和否定词经常决定业务答案；改写可以补充表达，但不得改变这些硬约束。
2. **问：如何评估自动改写是否值得部署？** 答：在同一标注查询集比较检索 recall、最终回答正确率与来源支持度，并记录延迟成本和错误改写率。

## 7. 中等难度考试题（含解析）

1. **题：100 个测试查询中 70 个改写后召回改善、20 个不变、10 个变差，改善比例是多少？** 解：70/100=70%，但仍要考虑变差案例严重程度与最终结果质量。
2. **题：原问题‘不允许自动退款的条件’，被改写成‘自动退款条件’，丢失了什么？** 解：丢失否定约束，可能召回完全相反的政策；需保留‘不允许’或结构化 filter。
