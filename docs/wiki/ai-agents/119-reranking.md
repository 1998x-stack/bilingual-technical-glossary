# Reranking（重排序）

> AI Agents · 专题：检索与知识增强 · 信息检索基础与 Agent 工程实践；计算示例为教学题设

## 1. 核心定义

**Reranking（重排序）**：Reranking（重排序）是在粗召回产生少量候选后，使用更精细的相关性模型或业务规则重新排列结果的阶段。典型两阶段检索是低成本 BM25/kNN 先高召回，再由 cross-encoder 等对 query-document 对进行较昂贵的精排。

**适用边界：**Reranker 不能从未召回的文档中凭空找到正确答案；若第一阶段 recall 很低，精排上限也低。重排分数是相对相关性或模型估计，不能等同事实真实性。

## 2. 形象理解

像初筛 50 份简历后，再由专家对职位要求逐条评估，挑选最合适的前几位。

**类比的局限：**如果最适合的人在初筛中被排除，后续专家再准确也无法选到他。

## 3. 技术原理与核心内容

两阶段管线：`retrieve top-N → filter ACL/version → rerank(query, candidate) → return top-k`，通常 N>k。cross-encoder 在同一模型中联合编码查询与文档，能捕捉更丰富互动，但延迟随候选数量增加。按候选预算与硬约束过滤做权衡，记录第一阶段 recall@N 和最终 nDCG@k/MRR；对错误证据必须继续验真。

## 4. 工程实践与设计权衡

**工程案例：**医疗指南内部检索先召回 40 条条文，再按病种、地区与生效日期过滤后精排最相关 5 条。系统不会因高相关性而跳过适用范围或允许无授权读取病历。

**失败模式与验证：**第一阶段漏召回、跨版本精排错误、排分很高但来源不可靠、对低信任文本中的恶意指令不设隔离。测试排序提升、候选覆盖、P95 时延、引用一致性和权限边界。

## 5. 关联知识与易混辨析

Reranking 是对已有候选排序；Hybrid Search 融合召回信号；Vector Search 是候选生成之一；Query Rewriting 修改查询以影响上游召回。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 reranker 不能修复所有召回错误？** 答：它只能重新排序给定候选，相关文档未进入 top-N 时无法恢复，必须先提高候选召回。
2. **问：如何决定从 top-20 还是 top-100 做精排？** 答：结合第一阶段 recall@N 的边际增益、reranker 的成本、P95 延迟与业务风险，在验证集上调参。

## 7. 中等难度考试题（含解析）

1. **题：第一阶段 top-20 中包含 8 个相关项，全部库共有 10 个相关项。recall@20 是多少？** 解：8/10=80%；即使 reranker 完美排序，未召回的 2 个也不可得到。
2. **题：40 个候选每个重排计算 15 ms，完全串行忽略开销时精排耗时？** 解：40×15=600 ms；真实系统可批处理并行。
