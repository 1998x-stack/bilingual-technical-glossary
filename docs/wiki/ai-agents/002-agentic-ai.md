# Agentic AI（智能体化人工智能）

> AI Agents · 专题：基础概念与角色 · 适用范围：通用智能体系统设计；具体 SDK 与平台版本以对应文档为准

## 1. 核心定义

**Agentic AI（智能体化人工智能）**：Agentic AI 是强调任务级决策、调用工具、根据反馈推进目标的 AI 应用范式，不是一个统一的模型架构或独立的基础模型类别。

**适用边界：**“Agentic”描述系统行为，具体自主程度、可执行权限与边界要在系统设计中单独定义。

## 2. 形象理解

普通问答像给出路线说明；智能体化系统像能据交通状况调整路线并代为预约的导航服务。

**类比的局限：**能执行多步任务不代表具备完全自主权或能够保证达到目标。

## 3. 技术原理与核心内容

从固定提示 → 有工具的单次调用 → 可循环运行的控制器 → 有持久化状态/多代理编排逐级增加决策自由度。每升一级都新增状态一致性、授权、终止与观测成本。衡量重点是实际完成目标，而非仅增加推理轮数。

## 4. 工程实践与设计权衡

在工单系统先用分类器+规则流程建立基线；只有在异常处理分支大量变化、人工规则维护成本高时，才引入动态 Agent。对比同一测试集的任务完成率、风险事件和成本。

## 5. 关联知识与易混辨析

Agentic AI 是系统设计取向；Generative AI 强调生成内容；AI Agent 是一个具体执行实体。三者有交集却不是同义词。

## 6. 中等难度面试题（含参考答案）

1. **问：什么业务条件下不该上 Agentic AI？** 答：路径稳定、风险高而收益低、接口权限难隔离时，规则引擎更易审计；先量化异常比例与维护成本。
2. **问：怎样评价“更自主”是否更好？** 答：测任务成功率、误动作率、用户确认负担、平均轮数与费用，且控制任务难度；自主等级不能替代安全或效果指标。

## 7. 中等难度考试题（含解析）

1. **题：固定流程成功 92/100 项，Agent 成功 95/100 项但多发生 3 次未授权动作，能否只按成功率选 Agent？** 解：不能；应把未授权动作作为硬约束或风险成本，按任务等级定义验收阈值。
2. **题：比较可动态选工具与固定顺序调用三个工具的系统。** 解：前者通常更体现 agentic 决策；后者是编排工作流。两者均可能由 LLM 提供某一步的内容生成。
