# Continuous Integration (CI)（持续集成）

> AI Agents · 专题：开发实践与生态术语 · 生产治理、可复现变更与持续交付

## 1. 核心定义

**Continuous Integration (CI)（持续集成）**：持续集成是团队频繁将变更整合进共享代码库，并通过自动化构建、静态检查、单元/集成/回归测试尽早发现兼容性和质量问题的软件工程实践。CI 检查通过表示所定义的验证项通过，不等于产品已发布或所有专业事实正确。

**适用条件：**这里对生产、版本控制和 CI/CD 采用可迁移的工程定义。各组织的审批、发布与支持策略可能不同，特定 GitHub Actions 功能的可用性也取决于计划、仓库配置及权限。不能把 PR 自动测试通过误称已合并 main 或完成领域专家审核。

## 2. 形象理解

**类比：**像印刷厂每次收到新版稿件就执行排版检查、错别字筛查和试印，避免最终汇总时才发现一整批错误。

**类比的局限：**类比未涵盖真实分布式负载、模型随机性、外部副作用和可重复部署限制。即使打包或测试环节全部通过，也不能推出用户业务结果正确；仍需产品级验收与必要的人工授权。

## 3. 技术原理与核心内容

常以 Pull Request、push 或合并事件触发流水线：锁依赖→构建→lint/typecheck→单元测试→集成测试→安全扫描→Agent eval→前端浏览器 E2E→产出报告。运行应可重现且尽量隔离测试数据和外部服务；PR 工作流尤其需保护 secrets，不能在不可信代码上下文开放生产写入凭据。GitHub Actions 可以显示每个 PR 的工作流结果，但质量门槛需要项目自行制定。

**权威边界。**AI Agent 模型回答、工具返回与最终业务后置状态彼此不同。代码审查、测试和配置也不能替代独立的权限校验及真实业务验收。对模型/提示词等非确定性组件，需要以可重复的任务集与条件化质量目标评估；所有外部写入需由可信服务端检查用户、租户与资源授权，并处理未知执行状态和幂等重试。日志不得输出明文秘密。

**关键机制。**先定义变化的提交、配置和构建标识，再记录每一阶段测试的输入、结果及发布门槛；将安全策略、环境权限、成本预算与失败恢复作为流水线的明确条件，而不是依赖提示词承诺。外部业务提交应有独立后置状态与幂等凭据。

## 4. 工程实践与设计权衡

**工程案例：**为术语 Wiki 仓库检查 332 个文章的标题/slug、八章节、每篇 2+2 问答、镜像一致、索引文件和公式渲染。CI 失败则阻止合并；全通过仍需要独立专家核实技术定义与引用。

**工程验证。**在沙箱中演练 schema 迁移、模型响应偏移、工具 429/503、并行工作流、回滚和恢复后的重复写入。记录 commit SHA、artifact digest、Prompt/Model 版本、tool schema 版本、测试结果与 trace ID；检查任务成功率、尾延迟、费用、告警与审计。真实生产灰度应有可执行停止条件和 Runbook。自动化合格不等于独立专家人工技术审核完成。

**设计取舍。**频繁变更可以降低一次发布的差异量，却要求稳定测试和可追溯流水线；过度依赖人工会延迟反馈，完全忽略人工专业复核又可能放行结构上正确而内容错误的文章。应将可自动验证的内容尽量自动化，把领域事实、授权与高风险动作留在明确审核关口。

## 5. 关联知识与易混辨析

CI 侧重持续整合与自动验证；Continuous Delivery 把合格软件维持在可发布状态；Continuous Deployment 进一步在通过条件后自动上线。CI 不代表代码审查或领域专家审核。

评审时需要严格区分“Git commit 存在”“CI 通过”“产物可部署”“已经正式上线”和“真实用户任务完成”五个状态。每一项分别需要自己的证据来源，不能由后一项自动推导另一项。

## 6. 中等难度面试题（含参考答案）

1. **问：怎样为大量 Agent Wiki 文章设计 CI 才能捕捉真实质量回归？** 答：组合 schema/目录一致性、引用与计算题、单元测试、浏览器 E2E 和固定评测；专家内容校审不可由结构测试取代。
2. **问：为何不应给来自 fork 的不可信 PR 测试任务直接开放生产 Secrets？** 答：PR 中脚本可以被恶意修改，需隔离权限与资源，原则上不向不可信代码暴露生产凭据。

面试答案应兼顾理论与运行时约束，解释哪些部分可以完全自动化，哪些部分需要独立审核或可追溯的权限批准。

## 7. 中等难度考试题（含解析）

1. **题：假设独立运行的 5 个 CI 作业分别用时 2、3、6、4、5 分钟，完全并行且忽略队列时间，完成全部需要多久？** 解：max(2,3,6,4,5)=6 分钟，而非 20 分钟。 计算结果只在题设条件下成立。
2. **题：一条 CI 流水线执行了 100 项测试且全部通过，能否推断系统完全没有缺陷？** 解：不能，只说明这些测试及其所覆盖的条件通过，未覆盖路径和人工内容审查仍有风险。 应区分统计样本、项目实际状态和对外发布保证。
