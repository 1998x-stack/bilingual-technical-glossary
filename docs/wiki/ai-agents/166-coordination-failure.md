# Coordination Failure（协作失效）

> AI Agents · 专题：多智能体协作 · 截至 2026-11 的协议版本须区分 2025-11-25 与 2026-07-28

## 1. 核心定义

**Coordination Failure（协作失效）**：Coordination Failure（协作失效）是多个 Agent 在分工、消息传递、状态共享、权限或结果整合中出现的整体任务错误，哪怕部分子 Agent 单独表现正常也可能发生。它通常源于依赖关系、责任边界、时序或证据互相矛盾，而非某一模型‘不够聪明’。

**适用边界：**单 Agent 内容错误与多 Agent 协作失效可能同时出现，应分别诊断。消息超时、重复派工和越权交接都可能在业务上造成真实副作用，不能仅靠生成更长总结来修复。

## 2. 形象理解

像接力赛每个人跑得快，但交接棒掉落或跑错跑道导致队伍失败。

**类比的局限：**完成个人分段不代表整场比赛成功，团队评分应以实际终点和规则验证为准。

## 3. 技术原理与核心内容

建立 coordination invariant：任务覆盖无遗漏、每个 task_id 有唯一有效 owner、消息关联一致、状态版本单调、审批 gate 不可跳过。利用分布式 trace、correlation_id、事件序列与业务成功谓词定位问题是 routing、handoff、shared state 还是 aggregation。常见修复包括幂等派工、CAS、超时升级、重放保护、schema 和 ACL 强约束。

## 4. 工程实践与设计权衡

**工程案例：**运营 Agent 让库存、物流和账单三个 Worker 办同一订单，但物流 Worker 使用了上周库存摘要、账单 Worker 没有收到订单 ID 更新，导致错误运费。协调者应冻结本次事务并重新同步订单版本，不能靠三个 Agent 投票声称结果正确。

**失败模式与验证：**遗漏边界条件、两个 Worker 处理同一支付请求、控制权循环交接、共享状态被过期事件覆盖、错误权限跨租户传播。回归测试必须覆盖重复/乱序消息、失联、越权、部分失败与冲突任务。

## 5. 关联知识与易混辨析

Coordination Failure 是整体协作问题；Tool Error 是单次工具调用故障；Conflict Resolution 是不一致处理方法；Consensus 是意见形成方式，不能修复基础数据错配或越权。

## 6. 中等难度面试题（含参考答案）

1. **问：全部 Worker 报 success，为什么仍可能存在协调失效？** 答：可能有缺失任务、错用订单版本、共享资源竞态或重复副作用；必须按整体任务图和权威状态验收。
2. **问：如何定位多 Agent 系统里的消息乱序故障？** 答：用 task_id、correlation_id、版本与时间线重建事件，并检查业务约束而非按到达先后配对。

## 7. 中等难度考试题（含解析）

1. **题：计划需完成 12 个不同任务 ID，系统收到 13 条成功回复，但其中 2 条是同一 ID 的重复，且只有 11 个唯一任务，任务覆盖率？** 解：11/12≈91.7%，不能宣告全部成功。
2. **题：某 Agent 已提交付款但 ACK 丢失，另一个 Agent 重新派发同付款动作，最大风险是什么？** 解：双重付款；需要查询事务 ID 并用后端幂等、任务归属与审批控制阻止重复执行。
