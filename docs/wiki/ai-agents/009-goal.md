# Goal（目标）

> AI Agents · 专题：基础概念与角色 · 适用范围：通用智能体系统设计；具体 SDK 与平台版本以对应文档为准

## 1. 核心定义

**Goal（目标）**：Goal 是智能体要实现的预期结果或目标状态，最好能够被外部条件验证；通常包含范围、截止时间、预算和安全限制。

**适用边界：**目标并不等于模型的一条动作指令；存在冲突时应由明确的指令优先级和权限边界裁决。

## 2. 形象理解

像导航目的地与到达条件，而每一步转弯是临时行动。

**类比的局限：**目标存在并不保证可达；成功指标若含糊可能导致奖励误导或越权捷径。

## 3. 技术原理与核心内容

把需求转成可测成功谓词 success(state)、硬约束 constraints(action,state)、预算 budget，执行过程中按谓词校验。目标分解为任务时需保持原目标的授权范围与验收标准。

## 4. 工程实践与设计权衡

“帮我整理 10 张发票”要明确输出文件位置、字段完整率、不能删除原件、异常处理方式；否则 Agent 可能把“没有待办”误当完成。

## 5. 关联知识与易混辨析

Goal 是结果导向；Task 是可执行工作单元；Termination Condition 是达到结果、失败或停止的判定规则，三者不可互换。

## 6. 中等难度面试题（含参考答案）

1. **问：如何避免 Agent 追求表面完成而破坏约束？** 答：把授权和不变量写成执行前校验，成功目标必须同时满足完整性和权限；不能仅凭奖励或自然语言提示。
2. **问：需求“尽快完成”怎样转化为可验收目标？** 答：明确质量门槛、时间预算、允许的工具与操作风险；无法兼顾时要求用户选择或升级人工审批。

## 7. 中等难度考试题（含解析）

1. **题：题设目标：处理 20 个文件且错误率不超过 5%。最多允许错误多少个？** 解：0.05×20=1 个；若有 2 个错误即 10%，不满足目标。
2. **题：业务请求“尽可能多采集用户信息”，为什么不是合格目标？** 解：缺少授权范围、必要性与退出条件；应限定最小数据集与保留期限，并定义是否完成的可验证条件。
