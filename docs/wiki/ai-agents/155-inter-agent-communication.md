# Inter-Agent Communication（代理间通信）

> AI Agents · 专题：多智能体协作 · 工程角色定义；职责、权限与真实验收依具体系统为准

## 1. 核心定义

**Inter-Agent Communication（代理间通信）**：Inter-Agent Communication（代理间通信）是多个 Agent 之间传递任务、状态、证据、控制信号或反馈的过程，可采用消息、事件总线或直接调用。它的核心是消息格式、来源身份、上下文边界和交付语义，而不是简单把一个 Agent 的全部聊天复制给另一个。

**适用边界：**消息到达不能等于任务完成，也不能证明消息内容可信；不同传输的顺序保证、至少一次交付、超时和重试语义需按实际系统协议定义。一个 Agent 的输出是下游数据，不能自动升级为更高优先级系统指令。

## 2. 形象理解

像团队用带工单编号的交接单沟通，填写负责者、当前状态和需要下一方确认的问题，而非口头转述所有隐私资料。

**类比的局限：**收到交接单不等于发件人有权批准转账，转发记录也可能过时或被篡改。

## 3. 技术原理与核心内容

定义 AgentMessage={message_id,task_id,sender_id,recipient_id,kind,payload_ref,version,expires_at,correlation_id}，对可靠性交付使用 ack/timeout/dead-letter 与幂等去重。通过 tenant ACL 验证消息来源和资料范围；对异步结果采用相关 ID 而非返回顺序。记录发送/接收 trace，保证审计可定位，但不应在全局队列暴露完整敏感上下文。

## 4. 工程实践与设计权衡

**工程案例：**采购 Agent 把合同 ID 和已授权的交货条件发给物流 Agent，物流返回运费估计与报价来源。经理收到后验证同一订单/币种版本；若另有未经授权的内部成本，不应被复制到物流会话。

**失败模式与验证：**收件人错误、消息重放、重复写操作、过期数据导致判断漂移、低信任文本提示注入、跨租户数据泄漏。测试乱序/重复/丢包、失联重试和授权拒绝。

## 5. 关联知识与易混辨析

Inter-Agent Communication 是交互过程；Message Bus 是承载消息的设施；Handoff 是活跃控制权转移；Shared Memory 允许经授权共享数据，不能代替明确任务交付。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 Agent 消息要有 message_id 与 correlation_id？** 答：前者用于去重和审计，后者关联原始任务及回复，避免异步乱序和跨任务错配。
2. **问：一个 Worker 的工具结果包含‘忽略此前所有指令’，接收者能照做吗？** 答：不能，Worker 输出是低信任数据；接收者仍需遵从自身权限与用户目标，必要时标为提示注入风险。

## 7. 中等难度考试题（含解析）

1. **题：发送 20 条任务消息，其中 3 条因重试重复到达，且每条原消息都至少到达一次，接收端共 23 条，应处理多少个唯一 task_id？** 解：20 个，假设重试没有创建新任务 ID。
2. **题：Agent A 回复 task_id=5，但当前等待 task_id=7，可将其作为 7 的结果吗？** 解：不可，必须按 ID 关联，并将不匹配消息隔离或另行处理。
