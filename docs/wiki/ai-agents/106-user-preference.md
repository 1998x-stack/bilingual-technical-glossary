# User Preference（用户偏好）

> AI Agents · 专题：上下文、记忆与状态 · 适用范围：知识管理与检索工程；具体 API 以版本文档为准

## 1. 核心定义

**User Preference（用户偏好）**：User Preference（用户偏好）是用户在交互、工作流或配置中表达的语言、呈现方式、通知时机等选择。偏好可能是单次任务临时约束，也可能在获得适当授权后成为跨会话可检索的长期信息。

**适用边界：**偏好不等于敏感身份属性、事实推断或授权操作。例如用户喜欢简洁报告并不表示同意自动发送邮件；不同任务对偏好的优先级与适用范围可能不同。

## 2. 形象理解

像咖啡店记录顾客常点无糖饮品，但本次顾客明确说要加糖时，应以最新明确订单为准。

**类比的局限：**消费历史不足以证明长期偏好，自动记录可能侵犯隐私；偏好也不是可以绕过安全规则的许可。

## 3. 技术原理与核心内容

偏好记录可含 `{owner,scope,value,source,confirmed_at,expires_at,version}`，区分 explicit 与 inferred。一次性偏好保留在 Session State；跨会话偏好经同意写入长期记忆，使用时优先遵从本轮用户明确要求。访问必须按主体隔离，用户能更正/撤回；冲突时检查时间、任务和规则优先级。

## 4. 工程实践与设计权衡

**工程案例：**写作 Agent 已保存用户偏好‘中英术语都给出’，当前任务用户指定‘仅中文’，应在本轮采用明确新约束，而不是强制使用长期偏好。正式财务报表的格式硬约束也不会被个人风格覆盖。

**失败模式与验证：**把一次英语提问推断为永久语言偏好、用户撤回后仍从向量索引返回、把偏好当支付授权或跨租户误用。进行用户修改、删除、偏好冲突和上下文压缩的回归测试。

## 5. 关联知识与易混辨析

User Preference 是一类可能被记住的个人/任务选择；Long-term Memory 是存储机制；Memory Write 是保存流程；User Instruction 是当前可信指令，可能覆盖某条旧偏好。

## 6. 中等难度面试题（含参考答案）

1. **问：用户过去偏好英文回复，此次明确要求中文，该按哪个？** 答：优先满足本次明确请求，在不违反更高约束的前提下覆盖旧偏好；若是长期更新仍要考虑授权与适用范围。
2. **问：为何不能通过点击记录偷偷生成敏感属性偏好？** 答：推断可能不准确且超出用途，应最小化存储、尊重同意/撤回，不能由一次行为推出受保护属性。

## 7. 中等难度考试题（含解析）

1. **题：题设 10 个任务里 7 个用户明确要求双语、2 个明确仅中文、1 个未说明；系统统一输出双语能保证满足几个明确要求？** 解：只可确定满足那 7 个双语请求；2 个仅中文明显不满足，未说明那 1 个不能判断。
2. **题：用户撤销通知偏好，但 Session 缓存还持有旧值，如何处理？** 解：使撤回成为有效的状态更新，立即阻止使用旧缓存并同步存储/索引，必要时回查偏好版本。
