# Completion（参数自动补全）

> AI Agents · 专题：MCP：模型上下文协议 · 以 2026-07-28 规范为当前基准，区分 legacy 模式

## 1. 核心定义

**Completion（参数自动补全）**：Completion（参数自动补全）是 MCP Server 根据 Prompt 或 Resource 参数已经输入的前缀给出候选值，以便选择合法对象、减少拼写错误。它面向参数辅助，不是 LLM 模型采样，也不代表执行工具。

**适用边界：**补全是按实际 capability 支持的可选功能。候选名单本身可能泄漏项目名、客户 ID 或敏感标识，因此必须以当前用户和作用域过滤；出现在候选中不证明调用时仍然有读取权限。

## 2. 形象理解

编辑器提示可访问的仓库名称，输入 `pay` 时列出当前身份能看的 `payment-core`，而不是所有公司私有项目。

**类比的局限：**自动补全可能过期或相似误匹配，真正执行仍要复查参数和权限。

## 3. 技术原理与核心内容

调用 `completion/complete` 指定 `ref`（prompt 参数或资源模板）、`argument`（名称、已有片段）及可选上下文，返回建议数组、total/hasMore 等元数据。现代协议请求仍应包含必需 `_meta`。实现可用前缀、模糊匹配与缓存，但需设置速率限制、候选个数上界、当前用户 ACL、版本失效和可见性规则；不要自动把建议插入未经用户核对的危险工具调用。

## 4. 工程实践与设计权衡

**工程案例：**Wiki Agent 调用可复用文档审查 Prompt 时键入 doc_id 前缀，服务端按租户过滤候选。用户选定后，resources/read 仍进行实时授权；某文件被撤销权限，缓存的候选也必须失效。

**失败模式与验证：**自动补全枚举私密对象、候选缓存跨用户、无限返回导致性能下降、误将补全结果当业务批准。用空候选、跨租户前缀、撤权和请求限流测试。

## 5. 关联知识与易混辨析

Completion 给输入参数建议；Elicitation 在处理过程中请求人补全信息；Tool Listing 返回可用方法目录；Sampling 是模型生成请求且已标记 deprecated。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么补全候选也要授权过滤？** 答：资源名称和 ID 就可能泄漏信息，不能只在最终读取阶段验证。
2. **问：Completion 是否取代调用 tools/call 的参数校验？** 答：不可以；候选建议不是用户同意、真实授权或业务有效性保证。

## 7. 中等难度考试题（含解析）

1. **题：共 8 个候选但当前用户只可见 5 个，应展示最多多少？** 解：最多 5 个，后续调用重新验证。
2. **题：候选 50 个但服务端设置每次最多 20 个，应返回几条？** 解：最多 20 条，其余按具体补全协议说明处理。
