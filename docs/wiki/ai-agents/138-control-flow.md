# Control Flow（控制流）

> AI Agents · 专题：工作流与编排模式 · 系统架构与执行依赖；技术语义依具体工具契约验证

## 1. 核心定义

**Control Flow（控制流）**：Control Flow（控制流）是规定程序或工作流中哪些动作在什么条件下以何种顺序执行的关系，包含顺序、条件、循环、异常路径、并发与终止。Agent 工作流中它负责管理节点的启动与停止，而不仅是把任务字符串从一个模型传给另一个模型。

**适用边界：**控制流与数据流相互关联但并非同义；一条数据依赖不能自动描述用户审批等控制门槛。控制流应能表达异常和取消，不能只画理想成功路径。

## 2. 形象理解

像交通信号和路线规则，决定车辆什么时候能直行、转弯、等待或停车；货物本身怎样流转属于另一层问题。

**类比的局限：**道路路线正确不保证每辆车获得通行权限，也不能自动保证货物内容准确。

## 3. 技术原理与核心内容

可用控制流图 CFG=(V,E) 和状态转移描述，节点含 action/predicate，边含 guard/transition。运行器评估当前可行边、检查执行预算与前置条件，处理循环上界、失败和安全终态。异步子任务要实现 join/cancel 语义；外部副作用需存储操作日志和可恢复状态。

## 4. 工程实践与设计权衡

**工程案例：**软件发布 Agent 的流程为构建→测试→安全检查→审批→灰度；当灰度指标恶化，控制流走回滚/停止而非继续扩大；日志数据仍沿另外的数据流进入评估器。

**失败模式与验证：**异常边缺失、无限循环、取消未传给子节点、审批被条件路由跳过、死锁导致流程不退出。进行路径覆盖、极限步数与状态机模型测试，不能只验证 happy path。

## 5. 关联知识与易混辨析

Control Flow 负责路径选择；Data Flow 负责值的生产与消费；State Graph 是含状态转移的图实现；DAG 无环，因此不能直接表达真正的回环，需另有循环机制。

## 6. 中等难度面试题（含参考答案）

1. **问：控制流图与依赖 DAG 的主要区别？** 答：CFG 可包含分支与循环，DAG 要求无环；任务依赖 DAG 更适合静态拓扑顺序，控制流可更动态。
2. **问：为什么要单独覆盖取消和异常边？** 答：否则真实工具故障或用户取消后可能继续执行有风险的后续步骤，或留下无人回收的任务。

## 7. 中等难度考试题（含解析）

1. **题：流程有 A→B→C 和 B→D 两条可能路径，若 B 的条件只能选其一，B 后可以同时执行 C 和 D 吗？** 解：按题设互斥条件分支不能同时执行两条路径；需要并发边才能并行。
2. **题：一个循环控制流每次执行 2 秒，最大执行 5 次，忽略额外开销，总循环时长上限？** 解：5×2=10 秒；仍需要单次工具超时以避免挂起。
