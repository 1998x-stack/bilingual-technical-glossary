# Coordinator Agent（协调者智能体）

> AI Agents · 专题：多智能体协作 · 多智能体角色和可复核的工程能力边界

## 1. 核心定义

**Coordinator Agent（协调者智能体）**：Coordinator Agent（协调者智能体）是在多智能体协作中负责消息传递、任务分配顺序、共享状态同步、进度跟踪与冲突解决的角色。它强调保持多个参与者协同和资源一致，不必亲自规划全部细节或拥有最终用户回复权。

**适用边界：**Coordinator 角色边界依系统设计而变；它可以是 LLM Agent，也可以是确定性调度/队列服务。协调能力不等于自动取得所有 Worker 的数据和写入权限，跨租户同步要强制隔离。

## 2. 形象理解

像会议协调员安排发言、收集行动项、解决日程冲突，保证合作过程顺畅，但不必替每个领域专家作最终专业判断。

**类比的局限：**会议被正确安排不代表每项行动完成，甚至不代表不同参与者的事实主张彼此一致。

## 3. 技术原理与核心内容

协调器持有 `task_registry,owners,dependencies,deadlines,correlation_ids`，维护任务生命周期 pending→assigned→running→returned/failed。根据 Worker 能力和负载分配任务，通过消息/事件系统保持结果关联、重试与心跳；对共享数据使用版本或 reducer 防止竞争。任务卡住时触发重新分配或停止，并保留历史副作用 ID 防止双重执行。

## 4. 工程实践与设计权衡

**工程案例：**仓库多 Agent 系统中，一个 Agent 查询库存、另一个计算运输、第三个校验订单。协调者确保所有结果对应同一订单和版本，处理某个 Agent 超时，不允许配送 Agent 在库存未确认前提交运输付款。

**失败模式与验证：**协调消息乱序、Worker 失联却持续等待、任务重复分派造成双写、全局状态被一条错误结果覆盖、Coordinator 变成单点故障。以故障注入、任务所有权和跨系统关联 trace 测试。

## 5. 关联知识与易混辨析

Coordinator Agent 偏重同步和资源分配；Manager Agent 通常保留最终面向用户的决策与答复；Supervisor Agent 强调监控/审核；Worker Agent 执行具体任务；不同实现可能重叠职责但术语焦点不同。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么分派工具任务要有稳定的 correlation_id 和 ownership？** 答：并发结果可能乱序返回，必须准确关联任务和责任主体，防止错配、重复派工及跨租户数据混用。
2. **问：协调者发现某个 Worker 超时，该怎样保证安全重新分配？** 答：先检查外部业务动作是否已提交，使用幂等/锁与任务版本，决定恢复或转交而非直接复制执行。

## 7. 中等难度考试题（含解析）

1. **题：协调者管理 4 个 Worker，收到 6 条回复但其中 2 条是重复的 task_id，假定剩下 4 个唯一任务都已返回，完成率？** 解：4/4=100% 的回执覆盖，但还必须验收每个任务的成功状态与整体目标。
2. **题：Agent A 和 B 同时更新版本号 9 的共享状态，A 成功写入版本 10，B 仍提交 version=9 应怎么办？** 解：拒绝过期更新并重读/合并，避免并发覆盖与状态错误。
