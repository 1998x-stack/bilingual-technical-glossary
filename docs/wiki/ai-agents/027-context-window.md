# Context Window（上下文窗口）

> AI Agents · 专题：模型能力与推理 · 通用概念；产品特性以文档版本和模型接口为准

## 1. 核心定义

**Context Window（上下文窗口）**：Context Window（上下文窗口）是模型一次推理能够纳入其处理范围的 token 容量。它涵盖相关输入消息、工具/格式定义、历史上下文以及模型所需的输出空间；具体输入输出计数与上限按模型/API 配置核对。

**适用边界：**长窗口并不意味着所有位置的信息都被可靠利用；超过窗口限制可能拒绝、截断或要求主动压缩，不同平台行为不同。

## 2. 形象理解

像办公桌可同时摊开的材料空间；桌子越大可摆更多材料，却不能保证每页都会被认真看过。

**类比的局限：**模型不是逐页人工检索器；长输入下的注意力、位置偏差和相关性仍影响质量。

## 3. 技术原理与核心内容

可用教学不等式 `T_input+T_generated≤W` 讨论总 token 空间；某些推理模型的内部推理 token 也占用输出及上下文预算。对于多轮 Agent，旧工具结果/消息会累计，应采用检索、摘要、关键状态外存与 token 预估，避免无意丢失约束。

## 4. 工程实践与设计权衡

**工程案例：**合同 Agent 需要处理 200 页附件时，先分段索引、提取章节证据、用可靠来源定位重读相关段落，而不是把全文重复塞入每轮模型请求。评估不同文档长度下的证据召回、答案正确率与成本。

**失败模式与验证：**直接删除旧消息可能丢失用户授权或尚未完成的工作；自动摘要也可能引入事实误差。必须把关键约束/任务状态与可丢弃的对话细节区分。

## 5. 关联知识与易混辨析

Context Window 是模型容量上限；Token Budget 是当前任务的可用配额策略；Working Memory 是系统设计中保留的短期相关信息，并不自动等于全部上下文。

## 6. 中等难度面试题（含参考答案）

1. **问：上下文快满时应保留哪些信息？** 答：优先保留系统约束、当前目标、未完成子任务、工具请求 ID、必要证据链接和异常状态；可压缩重复聊天并把原文放入可检索存储。
2. **问：为什么 128k token 窗口不等于能可靠回答任何 128k 输入的问题？** 答：因为信息定位/中间推理质量与长度有关，还受输出空间和模型实现影响。需要长文档评测及证据定位。

## 7. 中等难度考试题（含解析）

1. **题：假设窗口 W=8192 token，现有系统/用户/工具输入合计 6100 token，必须预留输出及推理 1600 token，剩余可放多少新输入？** 解：8192−6100−1600=492 token；这是题设简化的统一窗口模型，实际需要依 API 统计。
2. **题：文档索引显示某条款在第 125 页，但短上下文只保存第 1–20 页摘要。如何使答案可追溯？** 解：按索引重新检索第 125 页原文，保留页码与引用后再生成；不能凭摘要猜测缺失条款。
