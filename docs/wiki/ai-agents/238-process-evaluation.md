# Process Evaluation（过程评测）

> AI Agents · 专题：评测体系与常见基准 · 来源核验、场景适用与工程边界

## 1. 核心定义

**Process Evaluation（过程评测）**：Process Evaluation（过程评测）关注 Agent 如何完成任务：步骤是否合规、权限边界是否被遵守、证据如何收集、工具选择是否合理、失败是否按策略恢复。它特别适合发现‘最终结果正确但途径危险’的情况。

**适用边界：**过程评测并不要求所有成功系统使用同一条固定行动顺序；允许可替代路径，但必须严格执行安全不变量。过程分数也不能代替最终目标验证，合法操作仍可能因为业务失败而没有正确交付。

## 2. 形象理解

像食品卫生检查，不只看菜好不好吃，还查看生熟分离、温度记录和洗手流程是否合规。

**类比的局限：**卫生全部达标不代表菜一定好吃，结果与过程需要分开评测。

## 3. 技术原理与核心内容

构造 process rubric={allowed_actions,required_gates,forbidden_transitions,source_policy,retry_limits,privacy_constraints}，依据实际 trace 检查事件序列。规则型检查适合审批/工具权限、类型 schema 和重试次数；开放性解释可由专业人工 rubric 补充。对单个步骤使用 pass/fail/severity，跨任务报告不合规任务率以及高风险动作未授权次数；避免平均值掩盖严重越权。

## 4. 工程实践与设计权衡

**工程案例：**财务 Agent 最终计算总额正确，但曾未经授权读取另一租户订单或在审批前发起退款；Process Evaluation 判为安全失败，即使 Outcome 的数值准确。对于可恢复错误，允许经过规定重试后成功。

**失败模式与验证：**只统计运行成功、不记录中间工具、把模型解释当真实审批证据、过程规则过度僵化排斥合法替代方案。用越权、跳门控、重复写、合法绕行和 trace 丢失案例测试。

## 5. 关联知识与易混辨析

Process Evaluation 强调规则遵守；Trajectory Evaluation 是对完整执行路径的更广评分；Outcome Evaluation 面向最终结果；Tool-call Accuracy 只覆盖单个决策。

## 6. 中等难度面试题（含参考答案）

1. **问：同一任务结果正确，为什么过程仍可能不合格？** 答：存在隐私泄露、越权工具调用、未经批准写操作或无界重试等违规行为。
2. **问：如何避免把所有不同于参考路线的步骤判错？** 答：定义安全不变量和允许行动集合，准许语义等价的合法路径，而不是做逐字轨迹匹配。

## 7. 中等难度考试题（含解析）

1. **题：20 个任务中 3 个出现未授权操作，严重过程违规率？** 解：3/20=15%。
2. **题：任务共 10 次动作，9 次遵守流程、1 次越过审批，能算完整过程合规吗？** 解：不能，若审批是强制门控，则一个违反也使该次过程不合格。
