# Command-line Tool (CLI)（命令行工具 · CLI）

> AI Agents · 专题：工具使用与环境交互 · 具体工具行为、权限与版本以官方规范为准

## 1. 核心定义

**Command-line Tool (CLI)（命令行工具）**：Command-line Tool（CLI，命令行工具）是通过终端文本命令及参数与程序交互的接口，例如 git、curl 或编译器。Agent 可通过受控 shell 包装 CLI 执行任务，获取标准输出、标准错误和退出码。

**适用边界：**命令行形式并不代表比 API 更安全；shell 字符串拼接可能导致命令注入，运行目录、环境变量和文件系统权限也会改变结果。

## 2. 形象理解

像通过书面指令操作机器：写下命令和选项，机器返回文本结果。

**类比的局限：**指令中多一个转义或路径错误就可能影响完全不同的文件，误操作不一定可逆。

## 3. 技术原理与核心内容

建议使用参数数组调用进程（例如 Python subprocess.run([binary,arg1,...], shell=False)），对命令和参数做 allowlist/类型校验，设置 cwd、env、timeout、输出上限和最小权限。解析 exit_code、stdout、stderr，区分程序运行失败和业务结果不满足。危险命令进入确认/审批，不允许模型利用 ;、管道、重定向符绕过允许命令。

## 4. 工程实践与设计权衡

**工程案例：**代码审查 Agent 运行 git diff --check 与 pytest -q 获取确定性反馈；在只读工作区执行检测，将测试失败详情反馈给修订步骤。对 git push、删除分支等变更操作需要独立授权。

**失败模式与验证：**把用户输入拼接到 shell 命令、把 stderr 有输出当失败、忽略退出码、把模型建议的危险指令直接执行，都会造成误判或破坏。检查特殊字符、超时、文件路径边界和环境变量泄露。

## 5. 关联知识与易混辨析

CLI 是程序的文本交互接口；Code Execution 是执行程序的更广泛过程；API 可以是命令行工具所调用的底层网络接口；Tool Adapter 可把 CLI 包装成受控函数工具。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 `shell=False` 和参数数组通常更安全？** 答：避免 shell 解释器把输入中的分号、管道等元字符作为新命令解析；但还需验证参数语义和权限。
2. **问：命令 stdout 有文字、exit code 为 1，能当成功吗？** 答：通常不能；要按具体命令契约理解退出码，不能只看输出文字。

## 7. 中等难度考试题（含解析）

1. **题：串行运行编译 3s、单测 5s、静态检查 2s，忽略开销，总耗时多少？** 解：3+5+2=10 秒；若依赖允许，可对部分任务并行，但仍需考虑资源约束。
2. **题：用户输入文件名包含 `; rm -rf /`，为何不应拼进 shell 字符串？** 解：该内容可能被 shell 当成命令分隔和危险删除操作；应传独立参数并限制目标路径与操作权限。
