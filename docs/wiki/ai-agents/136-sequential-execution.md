# Sequential Execution（顺序执行）

> AI Agents · 专题：工作流与编排模式 · 系统架构与执行依赖；技术语义依具体工具契约验证

## 1. 核心定义

**Sequential Execution（顺序执行）**：Sequential Execution（顺序执行）是任务按确定顺序逐一运行的调度方式，后续步骤等待前面步骤完成或达到必要状态后再启动。它适合严格依赖、共享可变状态或要求简单审计的流程，但整体时延往往累加。

**适用边界：**顺序执行不表示每个阶段都使用 LLM；也不意味着每个操作可安全重复。某一前序步骤成功但反馈丢失时，必须先核对外部副作用，不能重放整个序列。

## 2. 形象理解

像办理护照先提交材料、再身份核验、再审核发证；不能先印证件再补查身份。

**类比的局限：**部分步骤可以安全并行，所有操作无条件串行会增加不必要等待；现实中还存在异步完成状态。

## 3. 技术原理与核心内容

对于任务 A→B→C，运行器维护 current_step 和 result_version，执行前检查前置条件，执行后持久化结果与后置条件，只有成功才释放下一步。串行时间可近似 `T_total=Σ T_i + T_wait`，失败需明确是停止、重试还是补偿。执行状态从 pending→running→succeeded/failed/unknown；unknown 不可当作成功流转。

## 4. 工程实践与设计权衡

**工程案例：**财务 Agent 先检查发票归属和金额，再申请审批，最后创建支付请求。审批未通过时拒绝写入；网络超时要查支付流水后才能决定能否再次调用。

**失败模式与验证：**长链累计延迟、上游错误级联、重复执行不可逆动作、忽略超时。用状态机回放、请求 ID 跟踪和每阶段契约测试保证链条正确。

## 5. 关联知识与易混辨析

Sequential Execution 描述时间调度；Prompt Chaining 是连续 LLM 调用；Chaining 是一般阶段数据衔接；Control Flow 描述流程允许的多种顺序和条件。

## 6. 中等难度面试题（含参考答案）

1. **问：什么情况下即使任务可以技术并发也应串行？** 答：存在业务审批、数据竞争或不可逆副作用依赖时，应按必要顺序执行以保障安全和可审计。
2. **问：序列执行失败后为什么不应该从头无条件重试？** 答：前几步可能已有实际写入，必须保留已确认状态并只恢复未完成部分。

## 7. 中等难度考试题（含解析）

1. **题：A、B、C 时延 1.5、2、2.5 秒，串行总时延？** 解：1.5+2+2.5=6 秒，忽略额外网络等待。
2. **题：A、B、C 都有写入副作用，B 返回 unknown，可否直接执行 C？** 解：不可；若 C 依赖 B 成功，必须先查 B 的权威状态并确认条件。
