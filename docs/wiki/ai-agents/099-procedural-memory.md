# Procedural Memory（程序性记忆）

> AI Agents · 专题：上下文、记忆与状态 · 概念与实际框架行为以来源和版本为准

## 1. 核心定义

**Procedural Memory（程序性记忆）**：Procedural Memory（程序性记忆）是 Agent 跨任务保留可复用的执行方式、操作规则、步骤模板和技能指导的一类记忆，回答‘如何完成某类任务’。它可能以工具操作手册、经过审核的 workflow、提示策略或技能代码存在。

**适用边界：**程序性记忆是可复用的知识或流程，不等于当前执行器已授权，也不能证明历史模板适用于新的工具版本。认知科学术语与具体 LLM 框架的实现并非严格对应。

## 2. 形象理解

像厨师掌握一道菜的步骤，能在不同日期按照材料和设备情况重复完成。

**类比的局限：**菜谱不会保证食材安全，也不会自动给予在新厨房使用危险设备的权限。

## 3. 技术原理与核心内容

在工程上可定义 procedure={skill_id,preconditions,tool_versions,steps,validation,rollback,owner,revision}。当任务触发时，先校验适用范围、当前资源权限和输入，再把模板细化为可执行的动作计划；每一步返回真实工具结果。模板升级后应运行契约测试和风险审查，包含付款/删除的步骤必须重新取得本次用户批准。

## 4. 工程实践与设计权衡

**工程案例：**数据库迁移 Agent 保存‘备份→迁移→回归测试→验证监控’流程。新的生产数据库版本不同，因此先检查参数、窗口和备份记录，再将经过审批的环境特定值填入模板；历史凭证不能混入执行上下文。

**失败模式与验证：**成功经历被错误泛化为任何场景可用、工具 schema 变更破坏兼容性、模型生成危险步骤未经复核直接存为流程。对版本变更、审批过期、恢复与测试失败建立回归用例。

## 5. 关联知识与易混辨析

Procedural Memory 是步骤和技能；Semantic Memory 是事实和概念；Episodic Memory 是具体经历。Policy 是状态到动作的映射，可利用程序性知识，但不等于一个固定操作模板。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么经一次成功运行的动作序列不宜自动推广为长期程序性记忆？** 答：单次成功可能依赖特殊环境与权限；需明确前置条件、反例测试、工具版本和人工审查，防止危险经验长期传播。
2. **问：用户只有只读权限，但模板包含写入，如何处理？** 答：执行器必须按本次真实授权禁止写入，不得因模板通过审核就放行，必要时停机或申请用户批准。

## 7. 中等难度考试题（含解析）

1. **题：流程备份耗时 2 分钟、迁移 8 分钟、测试 3 分钟，完全串行时共需多久？** 解：2+8+3=13 分钟；未计其他排队和失败重试。
2. **题：模板参数过去叫 userId，现在后端要求 account_id，直接使用旧模板有什么风险？** 解：会产生接口校验失败或更危险的语义错配，应进行版本化迁移与契约测试。
