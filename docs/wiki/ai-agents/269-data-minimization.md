# Data Minimization（数据最小化）

> AI Agents · 专题：安全防护与治理 · 防止不可信内容跨越执行授权与信任边界

## 1. 核心定义

**Data Minimization（数据最小化）**：Data Minimization（数据最小化）要求 Agent 在收集、检索、传输、存储和向其他工具/模型披露信息时，只使用完成特定合法目标所必需的数据。它是隐私和安全工程原则，能降低提示注入、日志泄露与跨服务数据复制造成的损害。

**适用边界：**最小化不等于一律删除所有数据，必要的审计、合法记录和用户可验证交付仍需按目的保留。它要求限制字段、条数、时间和接收者，不能因为上下文窗口很大就把完整用户数据库发送给第三方模型。

## 2. 形象理解

像医生诊治脚踝扭伤只需要相关病史和检查结果，不应把病人的全部银行交易记录交给无关诊室。

**类比的局限：**收集过少会导致诊断信息缺失，需建立对必要性、准确性和最短保留的业务解释。

## 3. 技术原理与核心内容

做 data inventory 与目的映射 `purpose → required_fields → permitted_recipients → retention`。发送给远程 Agent 之前采用字段 allowlist、PII redaction、脱敏 tokenization 和最小文件片段；对 Retrieval 限制 top-k、文档 section 和用户可访问范围。日志记录事件 ID/业务 ID 与摘要哈希，不默认保留整个 prompt/tool output。对多租户缓存设置 tenant namespace 和删除/撤权机制；同时检查模型 provider、MCP Server、A2A Remote Agent 的真实数据传输边界。

## 4. 工程实践与设计权衡

**工程案例：**报销 Agent 需要审核某张发票金额和日期，向 OCR 服务只发送该页已授权图像，不附带用户完整银行账户与往年所有交易；记录的审计只包含必要 invoice_id、状态和处理结果。

**失败模式与验证：**默认上传整份企业知识库、trace 无限制记录个人信息、远程 Agent 未按目的删除数据、错误脱敏导致重新识别、检索跨租户内容。用字段白名单、保留期、数据删除和无关字段注入测试。

## 5. 关联知识与易混辨析

Data Minimization 限制处理的数据量；Access Control 限制谁可读；Data Retention 决定保存期限；Purpose Limitation 约束用途；四者共同构成治理实践。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么仅设置模型 context 长度不等于数据最小化？** 答：上下文容量只是技术上限，数据最小化依据具体合法目的决定需要哪些字段。
2. **问：为什么 Agent 的日志也需要最小化？** 答：日志可能长期保存并被多方访问，完整工具结果和凭证会增加泄漏面，需脱敏与限定保留期。

## 7. 中等难度考试题（含解析）

1. **题：任务只需 5 个字段，但发送数据含 20 个字段，最小化后应保留多少？** 解：只保留有明确目的必要性的 5 个字段。
2. **题：日志保留期限 30 天，但第 31 天仍可查询没有合法延长期，符合最短必要保留吗？** 解：不符合，应按已定义保留政策删除或合法延长并记录理由。
