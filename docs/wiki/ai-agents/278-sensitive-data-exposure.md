# Sensitive Data Exposure（敏感信息暴露）

> AI Agents · 专题：智能体攻击与风险 · 执行权限与可信边界

## 1. 核心定义

**Sensitive Data Exposure（敏感信息暴露）**：个人身份、财务记录、秘密凭据、内部提示或其他敏感数据被不恰当地显示、存储、传递到模型上下文、日志、缓存或监控属性。即使数据没有离开组织，也可能在错误权限范围内暴露。

**适用条件与定义边界：**需要把威胁控制点、Agent 的真实执行权限、是否触发敏感工具以及可验证的业务后置状态一并列出。恶意指令不必然意味着攻击成功，模型说“已完成”也不能证明真实执行。工程审查必须将模型生成、工具请求与可信执行器的最后决策分开，不能从一个错误输出直接推断所有安全机制都被绕过。

## 2. 形象理解

**类比：**会议投影仪误放含薪资的表格，没被带走的文件也可能产生不应有的可见性。

**类比的局限：**实际系统存在多个授权主体、不同信任级别的输入、并发操作和可能失败的外部服务。类比只能展示一条错误路径，不能作为技术证明。要确认此类风险，需要追踪信息实际从哪里来、经过哪层转换、被哪些组件执行以及是否产生不可逆的外部影响。

## 3. 技术原理与核心内容

按数据分类在采集、传输、缓存、推理、记录、输出和删除各阶段实施最小化。执行前过滤不必要字段，结构化日志做字段级 allowlist，短期凭证不进入 Span 属性，历史副本有留存和清理策略。

**安全原理与执行不变量。**区分可信用户意图、Agent 模型建议、第三方资料与工具返回内容。模型的自述、自然语言策略、检索相似度以及 HTTP 200 均不能独立证明服务端授权和业务完成。每个写入请求需要可信执行器检查身份、动作、资源、租户和实际状态，危险操作应采用最小权限、具体参数审批与幂等键。攻击载荷可藏在 JSON、PDF、HTML、图片、上下文记忆或远程工具，因此不能依赖单一关键词检测。

**必要的工程接口：**工具能力注册、身份和租户绑定、参数规范化、业务状态查询、错误/超时与幂等恢复。对调用意图、执行接受和业务提交三个阶段分别建立证据，避免把前者当成后者。

## 4. 工程实践与设计权衡

**工程实例：**客服 Agent 的最终回答遮盖了身份证号，但 Trace 属性保存全号；需修复埋点、排查历史存储、限制观测平台访问。

**工程验证。**使用隔离环境、合成 canary 与没有真实支付/删除副作用的工具，按固定测试集记录输入载体、模型建议、工具请求、权限拒绝与最终权威业务状态。分别定义模型受影响率、被拦截率、误报率及真实越权率；仅凭回答“我拒绝”不能证明未造成副作用。持续测试超时、重试、会话恢复、跨租户、缓存、异步回调和人工审批参数变更。对运维成本、响应延迟与安全风险进行明确权衡，并保留可撤销和审计路径。

**失败模式：**当工具描述含糊、服务凭证权限过宽或缺乏对象级检查时，小模型错误也会被放大为危险动作。提高审批严格度会增加延迟、人工成本和误拦截，需要根据只读、可逆写入与不可逆写入分级调节。未知提交状态下应先查权威系统，不能将超时直接解释为失败再重试。

## 5. 关联知识与易混辨析

Data Exfiltration 指向外传输，Sensitive Data Exposure 范围更广；Prompt Leakage 特指提示词相关内容。

学习相邻术语时应分别回答风险对象、发生阶段、信任边界和验收证据。风险分类可以交叉但不意味着可互换：错误目标、工具误用、未授权动作和真实数据外传必须按不同机制建立测试；模型选择的理由不应被提升为后端执行权限。

## 6. 中等难度面试题（含参考答案）

1. **问：如何防止敏感字段意外进入结构化日志？** 答：定义可记录字段清单、脱敏规则、留存时间与访问 ACL，对动态属性做回归测试。
2. **问：为何全盘加密不能单独解决敏感暴露？** 答：已解密的运行时上下文、输出、外发工具和观测平台权限仍可造成暴露。

**深度追问：**说明怎样用对抗用例验证服务端约束、如何区分模型误判与工具实际越权、哪些关键参数需要再次确认，以及为何仅修改提示词不能作为完整修复。

## 7. 中等难度考试题（含解析）

1. **题：检查 800 条日志发现 12 条含不应记录的敏感字段，比例？** 解：12/800=1.5%；应额外按访问范围与敏感性分类。 计算须说明分子、分母和统计口径，文中数值只是教学假设，不能误称生产环境实测或正式安全基准。
2. **题：客服回复脱敏但 Trace 存完整秘密，能否判为通过安全验收？** 解：不能，应修复 Trace 采集路径并评估与清理历史数据。 评分点在于正确识别权限对象、调用阶段和权威后置状态，不允许以模型口头保证替代服务器 ACL 检查。
