# Loop Node（循环节点）

> AI Agents · 专题：工作流与编排模式 · 图编排、同步和权限边界；SDK 特性以对应版本文档为准

## 1. 核心定义

**Loop Node（循环节点）**：Loop Node（循环节点）是在工作流中根据退出条件反复执行某一组任务或返回前序节点的控制单元，常见于 Agent 的观察—行动—验证闭环、有限重试和迭代优化。它必须由真实状态和停止准则约束。

**适用边界：**循环节点不等于外部工具调用可安全重放；非幂等付款、消息发送等动作不能因循环逻辑返回便自动重做。循环条件可能受模型误判影响，必要时应由程序硬校验。

## 2. 形象理解

像实验室每轮测量后调整设备，再测量，达到指标或超过试验次数就结束。

**类比的局限：**实验设备可能产生不可逆化学变化，不能认为每次重新进入循环都从相同物理状态开始。

## 3. 技术原理与核心内容

流程 `while not verified_success and iteration<K and cost<B: observe; propose; validate; execute; update`。维持 iteration、last_result、pending_external_ids 与 deadline，避免单个工具卡死；对状态变量设计单调进度或失败去重，识别 no-progress loops。LangGraph 等图式框架可用条件边构建环路，并配置 recursion limit；逻辑停止原因须明确 success、failed 或 budget_exceeded。

## 4. 工程实践与设计权衡

**工程案例：**运维 Agent 检查一次配置变更是否解决服务报错，最多三次采样；若仍未恢复，进入报警并交给人工值班，而不是循环执行重启造成抖动。

**失败模式与验证：**循环没有实际 progress 条件、重复写操作、递归超过上下文预算、上一次模型结论被当真实修复证据。用最大次数、超时、取消和结果未知等故障注入测试。

## 5. 关联知识与易混辨析

Loop Node 是图上的重复控制单元；Backtracking 是内部搜索路径回退；Tool Retry 是特定调用失败后的有限重发；Evaluator–Optimizer 可利用循环节点实现多次修正。

## 6. 中等难度面试题（含参考答案）

1. **问：循环出口为什么不能只检查模型‘已经完成’文本？** 答：模型可能错误宣称成功；应根据权威业务验收或独立测试的结构化成功谓词决定出口。
2. **问：循环中写操作返回超时，下一轮能直接重发吗？** 答：不能；先查上次事务状态，后端支持幂等时才按同键同参数和预算重试。

## 7. 中等难度考试题（含解析）

1. **题：每轮需要 0.5 秒模型推断、1.0 秒工具调用，最多 4 轮且串行，总运行时长（忽略额外开销）？** 解：4×(0.5+1.0)=6 秒。
2. **题：退出条件 `iteration>=5`，计数从 0 起，每轮结束后加 1，执行多少轮后必须停止？** 解：最多执行 5 轮，达到 iteration=5 时不再进入第 6 轮。
