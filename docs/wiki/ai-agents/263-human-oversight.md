# Human Oversight（人类监督）

> AI Agents · 专题：安全防护与治理 · 明确安全边界、执行权限与可验证的用户决定

## 1. 核心定义

**Human Oversight（人类监督）**：Human Oversight（人类监督）是让有责任和权限的人持续了解、评估、纠正或停止 Agent 的目标选择、资源使用和高风险行为的治理安排。它既包含实时干预，也包含审计、申诉、政策更新、事故回顾和系统停用机制。

**适用边界：**有‘人工在群里’不意味着具备有效监督；监督者必须看到足够证据，具备明确决策权和真实技术控制（暂停、拒绝、撤权）。对自动化低风险任务也可采用抽样审计，但高后果动作可能要求同步审批。

## 2. 形象理解

像工业生产的监控室，值班员能看到关键报警、检查录像并触发紧急停止，而不是只收到‘系统一切正常’的模型摘要。

**类比的局限：**若仪表只显示模型自述而没有设备传感器，人工仍可能被错误信息误导。

## 3. 技术原理与核心内容

建立 OversightPlan={risk_tier,reviewer_role,approval_gates,telemetry,escalation,suspend_controls,audit_retention}。在任务创建时按影响分层设置强制 gate；运行中持续采集 tool-call、trace、业务操作 ID 与安全警报。需要审查时附最少必要上下文、来源、版本与失败证据；系统支持可验证的 stop/revoke/retry 决策，审稿和审批记录都应绑定主体、时间、资源 SHA 与 policy 版本。通过演练确认人工动作能真正停止有害行为，而非只有 UI 开关。

## 4. 工程实践与设计权衡

**工程案例：**法务 Agent 自动审阅公开合同条款，但在准备签署、删除客户合同或转发完整附件时必须暂停并由授权法务人员审查。事后抽样复核审计轨迹，发现系统误读法律版本时撤回相关自动化能力。

**失败模式与验证：**监督者无法看到真实工具执行、没有紧急停止、人工确认不绑定参数、事故报告缺 trace、以自动 Judge 代替专家。用告警误报/漏报、人工审批时延和故障注入演练。

## 5. 关联知识与易混辨析

Human Oversight 是持续治理总框架；HITL 是单次或多次介入模式；Human Review 检查产物；Human Approval 放行指定操作。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么人类监督不仅仅是审批按钮？** 答：还需持续可观测性、权限调整、纠错、申诉和停止机制，才能控制全生命周期风险。
2. **问：模型自述‘安全’是否足以支撑监督决策？** 答：不足，监督者应看到实际工具调用、真实业务状态和独立检查结果。

## 7. 中等难度考试题（含解析）

1. **题：20 项高风险动作需要监督审批，完成有效审批 15 项，未批准的最多能执行多少？** 解：未批准的最多 0 项，15 项也须通过执行时实际授权。
2. **题：安全报警误报 10 次、真实风险 5 次全被检出，能只报告召回率 100% 吗？** 解：不够，还须报告误报、精确率、负担和影响。
