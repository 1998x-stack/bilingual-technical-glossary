# Temperature（温度参数）

> AI Agents · 专题：模型能力与推理 · 通用概念；产品特性以文档版本和模型接口为准

## 1. 核心定义

**Temperature（温度参数）**：Temperature（温度参数）是从模型 logits 采样 token 时调节概率分布尖锐程度的参数。通常温度较低会更集中于高分候选，较高会使候选分布更平坦；实际允许范围和是否支持由具体模型/API 决定。

**适用边界：**温度只影响采样随机性，不是事实正确性、创造性或安全性的直接保证。部分推理模型不允许用户设置该参数。

## 2. 形象理解

像调节抽奖箱中热门号码的权重：低温更常抽中热门项，高温给冷门项更多机会。

**类比的局限：**并不意味着高温必定产生新颖好答案，低温也不意味着完全确定或永远正确。

## 3. 技术原理与核心内容

若 logits 为 `z_i`，非零温度 T 的采样概率 `p_i=exp(z_i/T)/Σ_j exp(z_j/T)`；T 趋近于 0 时概率趋向最高 logit；T=1 恢复原始 softmax 分布。实际实现还可能有 top_p、并行采样和确定性优化，不应对 T=0 作精确可复现承诺。

## 4. 工程实践与设计权衡

**工程案例：**代码生成或结构化报告可先试较低温度以减少输出变动；创意方案探索可测试较高温度，再用独立规则/测试筛选。对于不支持 temperature 的模型，应遵从 API 限制而非强行传参。

**失败模式与验证：**把低温当成幻觉抑制器是错误的：模型最可能的内容也可能不真实。温度升高时应更加依赖证据核验与结果验证，而非靠多次生成提高可信度。

## 5. 关联知识与易混辨析

Temperature 调整整体分布陡峭程度；Top-p 截断累计概率质量内的候选集合；二者是不同采样机制，生产调整时宜先控制单一变量。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 temperature=0 的回答仍可能有事实错误或不完全可复现？** 答：最高概率候选本身可错；数值精度、后端实现、版本及并发等也可能改变行为。事实应靠证据和测试核验。
2. **问：低温和 top_p=0.1 有何不同？** 答：低温会缩放概率差异；top_p 依概率质量选择候选子集并重新归一化。两者改变采样分布的方式不同，应分别实验。

## 7. 中等难度考试题（含解析）

1. **题：对两个 logits (2,1)，T=1 时第一个 token 概率近似多少？T=2 时呢？** 解：T=1：exp(2)/(exp(2)+exp(1))≈0.731；T=2：exp(1)/(exp(1)+exp(0.5))≈0.622。升温使分布趋平。
2. **题：客服 Agent 面对退款事实查询，应通过提高温度、降低温度还是调用权威账务 API 保证退款金额正确？** 解：权威 API 核验是核心；调温不能代替外部事实验证。
