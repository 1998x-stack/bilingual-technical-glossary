# Function Tool（函数工具）

> AI Agents · 专题：工具使用与环境交互 · 具体工具行为、权限与版本以官方规范为准

## 1. 核心定义

**Function Tool（函数工具）**：Function Tool（函数工具）是将外部能力以函数签名形式提供给模型的工具类型，通常具有名称、功能描述与结构化参数 schema。模型生成参数并请求调用，函数代码仍由受控宿主环境执行。

**适用边界：**模型能输出调用建议不代表真正具有 Python/JavaScript 函数执行权限。接口可能采用 JSON 参数、自由文本或托管工具约定，具体取决于提供商。

## 2. 形象理解

像给调度员一张带参数的服务菜单：填写要处理的订单号与操作类型，再由服务人员执行。

**类比的局限：**菜单描述不代表执行成功，更不能替代用户授权或业务校验。

## 3. 技术原理与核心内容

例如声明 get_order(order_id:string)；模型收到工具 schema 后生成函数调用 name 与 arguments，宿主检查参数、AuthZ 和状态，执行实际服务函数并返回 tool_result 供模型使用。工具可以由远程 RPC、数据库查询或本地函数封装，但必须统一错误、超时和日志策略。

## 4. 工程实践与设计权衡

**工程案例：**数据分析 Agent 提供 aggregate_sales(month,region) 工具，在可信数据库层计算聚合；模型不直接拼接原始 SQL。在租户隔离、日期范围和统计口径校验通过后返回数字，并保留查询时间和来源。

**失败模式与验证：**直接执行模型拼接的代码/SQL、把模型声明的成功当真、漏掉函数版本更改，会带来安全与可靠性问题。采用参数化 API、严格 schema、最小权限与完整单元测试防护。

## 5. 关联知识与易混辨析

Function Tool 是工具的函数式包装；Tool Call 是具体请求事件；API 是服务间接口规范，既可作为工具后端也可独立存在；Function Calling 是模型与函数工具交互机制。

## 6. 中等难度面试题（含参考答案）

1. **问：函数工具为什么要把数据库查询封装到服务器而非让 LLM 直接写 SQL？** 答：服务器更容易强制表/列白名单、租户范围、参数化查询和权限，模型只提出必要业务参数。
2. **问：Function Tool 与普通 Python 函数的关系？** 答：可由 Python 函数实现，但作为模型工具还需元数据、调用协议、执行器/结果回传和安全门控，不是任意本地函数都自动可调用。

## 7. 中等难度考试题（含解析）

1. **题：函数 schema 要求 month 为 1–12 的整数，模型给出 13，能执行吗？** 解：不能，超出合法月份范围；应拒绝或请求修正。
2. **题：一次函数工具调用返回传输成功但业务记录为空，能断言‘客户没有订单’吗？** 解：仅在查询范围、分页、权限和数据时效完整且权威时才能做相应结论，否则应说明观察范围及不确定性。
