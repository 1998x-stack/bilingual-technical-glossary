# Policy（策略）

> 适用领域：AI Agents · 专题：任务规划与决策 · 基础概念与具体 SDK 权限实现需分开判断

## 1. 核心定义

**Policy（策略）**：Policy（策略）是在给定状态或观测条件下选择动作的规则。在强化学习的 MDP 形式中，随机策略 `π(a|s)` 表示状态 s 下选择动作 a 的概率，确定性策略可写 `a=π(s)`。

**适用边界：**在 LLM Agent 工程中，policy 还可能泛指工具路由/控制规则，不一定是经过强化学习得到的参数化概率策略；要与访问控制 policy 区分语义。

## 2. 形象理解

像棋手的下棋原则：看当前棋局决定下哪一步，并可根据局面改变选择。

**类比的局限：**善于选择不等于有权执行动作；策略需服从可用操作、规则和资源约束。

## 3. 技术原理与核心内容

对随机策略，通常要求每个状态 `Σ_{a∈A(s)}π(a|s)=1` 且概率非负。策略可来自规则表、动态规划、RL 模型或 LLM 决策。执行前由 guardrail 过滤非法动作，必要时对剩余概率重新归一化。部署要关注策略变化和分布漂移。

## 4. 工程实践与设计权衡

**工程案例：**客服 Agent 在用户诉求不明确时选择追问、查询或转人工；而所有退款写操作都要经过固定授权门控。比较新旧策略时应统一任务样本、工具权限和成本预算。

**失败模式与验证：**模型概率分布偏好高风险动作、训练分布变化、或者在过滤后概率总和为零都可能导致异常。应支持无合法动作时安全停止。

## 5. 关联知识与易混辨析

Policy 是映射关系；Action Space 是映射的值域；Utility Function/Reward Signal 可能用于评估或学习策略，但策略本身不等同于目标或奖励。

## 6. 中等难度面试题（含参考答案）

1. **问：规则驱动 Agent 能否有 policy？** 答：可以。Policy 是状态到动作的映射，不要求必须通过神经网络或 RL 学得。
2. **问：若高概率动作被权限过滤，策略层应该怎么办？** 答：从合法动作中重新选择，并在候选集合为空时安全停机/升级人工，绝不越过权限执行原动作。

## 7. 中等难度考试题（含解析）

1. **题：某状态合法动作 a、b、c 的策略概率为 0.2、0.5、0.3；被禁止的 b 移除后对 a、c 归一化？** 解：余量 0.2+0.3=0.5，得到 `π'(a)=0.4`、`π'(c)=0.6`；这只是数学筛选，不代表业务动作自动安全。
2. **题：确定性策略在 s1 选 read，在 s2 选 stop，需要在每轮都调用 LLM 吗？** 解：不需要；规则或状态机就能实现映射，LLM 只是策略的一种实现形式。
