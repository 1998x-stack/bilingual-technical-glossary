# Skill Discovery（技能发现）

> AI Agents · 专题：开发实践与生态术语 · 可靠运维、能力封装与开发集成

## 1. 核心定义

**Skill Discovery（技能发现）**：Skill Discovery 是 Agent 或其宿主根据任务、技能元数据与可用环境找到候选技能的过程。发现只意味着可能匹配任务，不代表技能已加载、更不代表其脚本或工具已获得执行权限。

**定义边界：**这里的通用工程名称和个别厂商实现要区别对待。工具版本、规范字段、执行权限及可观测语义可能持续变化；不能从“描述存在”推断运行时已安装、用户已授权或动作已经成功。

## 2. 形象理解

**类比：**像图书管理员根据读者需求检索馆藏目录，先找到可能相关的工具书，再决定是否阅读。

**类比的局限：**真实 Agent 包含模型、工具、跨进程调度、业务权限和状态持久化，类比只能说明局部职能。外部文档可以提供资料却不能变成比用户目标更高优先级的行动指令，也不能直接推导脚本执行权限。

## 3. 技术原理与核心内容

发现流程通常是扫描经批准的技能目录→解析 SKILL.md 的 name/description→基于用户任务、匹配度和可用性过滤→选择需要加载的技能。要控制索引更新、冲突技能、恶意描述投毒和版本归属。Agent Skills 规范定义包格式，不规定所有宿主必须使用同一种发现 API 或排序算法。

**安全与执行边界。**技能包、SDK 与 ADK 都只能组织能力，不会自动赋予合法用户授权。外部文件或技能元数据可能含恶意说明，须在宿主执行器内落实签名/来源核验、最小权限、租户隔离、参数校验和真实业务后置状态。对不可逆操作使用幂等键，未知提交状态必须向权威系统查询。技能与开发依赖需要明确版本、来源和回滚策略。

**实施顺序：**先依据真实需求定义能力范围和成功判据，再选择工具包或技能的规范与版本，随后验证类型/schema、状态恢复与错误接口，最后以真实业务后置条件验收。工具调用本身不是最终成功条件。

## 4. 工程实践与设计权衡

**工程实例：**采购 Agent 需要检查供应商 PDF，宿主发现 PDF 解析 Skill；只有在技能源可信、版本兼容且任务确实需要时加载正文，PDF 本身不应命令加载高权限付款技能。

**工程验证。**使用受控任务集分别测试正常执行、缺失依赖、技能冲突、恶意元数据、过期接口、异常恢复、审批与跨租户访问。日志包含具体 task/trace ID 但不输出凭据。验收不仅检查模型报告的结论，还检查真实工具 API、权限策略与数据库状态。对运行手册进行模拟演练，保证失败路径能止损且能回退；引用依赖具体版本时应复核当前维护者资料。

**权衡：**标准化封装降低重复开发和维护成本，但也可能隐藏自动重试、动态脚本或不透明权限。应为升级设置契约测试、回归验证及回滚方式，明确审核人员和操作日志的保留范围；在技能加载时避免不必要的上下文开销。

## 5. 关联知识与易混辨析

Skill Discovery 是候选识别，Skill Invocation 是后续加载/使用阶段；Tool Discovery 识别可调用执行工具，两者信息结构与权限含义不同。

需要按“资产/描述”“发现/选择”“实际执行”“业务验证”四个阶段辨析，尤其不能把技能说明、工具 manifest 与已获授权的外部操作混作同一对象。对于供应链或提示词投毒，要把证据来源纳入测试。

## 6. 中等难度面试题（含参考答案）

1. **问：如何防止不可信技能描述操纵匹配排序？** 答：仅搜索已批准清单，审核来源和版本，限制描述影响权限决策，记录选中原因并回归测试冲突情况。
2. **问：为什么发现了一个技能不能直接执行它包含的脚本？** 答：发现阶段只有元数据匹配，不具备脚本执行授权；必须在宿主策略中检查权限、资源和审批。

面试中须解释可迁移原理和产品实现区别，并说明如何验证错误路径和危险权限，不能只答“使用某框架即可”。

## 7. 中等难度考试题（含解析）

1. **题：题设发现 40 个技能，过滤后 8 个可用，保留率？** 解：8/40=20%；不能用保留率代表技能质量。 题设数字只是教学假设，写明计算口径和单位。
2. **题：两个技能都称能处理合同，一个需访问所有客户数据，应该如何决策？** 解：优先满足任务范围且权限最小的可信技能，不要让自述的描述自动提升权限。 完整论证需要指出为什么另一个做法不满足授权、可靠性或版本约束。
