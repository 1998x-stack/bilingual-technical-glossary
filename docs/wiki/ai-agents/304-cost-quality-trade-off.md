# Cost–Quality Trade-off（成本—质量权衡）

> AI Agents · 专题：工程化、成本与可观测性 · 模型用量、成本预算与缓存治理

## 1. 核心定义

**Cost–Quality Trade-off（成本—质量权衡）**：在保证安全和业务约束前提下，选择模型、上下文规模、检索深度、评估/重试次数、缓存和工具组合，以在任务成功率、准确性、时延与资源费用之间取得可解释的平衡。

**定义边界：**有关 token、价格、配额和缓存的产品语义可能依模型与服务版本变化。本文只定义可以迁移的工程方法；练习数字均假设给定，不能误称任何供应商当前实际价格或基准数据。成本不是唯一目标，正确的任务结果、隐私和安全权限应具有清晰的最低门槛。

## 2. 形象理解

**类比：**像在不同交通方式中选择，既关心车费，也关心准时与安全。

**类比的局限：**不是“越便宜越好”；削减必要审批、安全验证或证据来源会牺牲无法接受的底线。 实际 Agent 有多种费用、资源状态和分布式后置结果，因此不能从类比推导精确计费或可靠性保证。

## 3. 技术原理与核心内容

对模型/工作流构建 Pareto 前沿：若方案 A 的成本更高且质量不优于 B，则 A 被支配。比较需保持同一评测集、任务难度与置信区间；常用目标为最小 C_success 或在质量≥Q_min、延迟≤L_max 下最小成本。小模型路由、缓存、检索、降级与重试改变成功率和尾延迟。

**成本模型与治理边界。**一个 Agent 任务会跨多次模型调用、检索、数据库、工具、人工审批和失败重试；应依调用 ID 归集用量，再按相应计价规则计算，不凭空使用特定厂商报价。要区分当前已结算与在途预留，模型回答成功不等于业务完成。缓存值、外部工具结果和旧记忆属于数据来源，不得因低成本或高相似度而突破现有授权与业务实时状态。

**执行闭环。**入口分配 task_id 和共享额度，执行器在每个子任务前检查预估资源需求，随后记录实际 usage 与工具费用；必要时主动拒绝或降级。所有业务写入仍要使用真实权限和幂等键，不能因为缓存或便宜模型的建议就直接行动。

## 4. 工程实践与设计权衡

**工程案例：**发票 Agent 的简单结构化抽取使用廉价模型，高风险争议账单切换更强模型与人工复核；低风险路径可优化费用，但不能降低账户权限校验。

**验证程序。**用固定任务集同时统计输入/输出用量、模型/工具调用数、重试次数、实际成功数、端到端 P95、成本与安全拦截；计算两组候选方案的成功摊销成本并标记计费口径。注入并发、超时、缓存过期、权限变更和费用报告滞后等边界用例，不使用真实客户数据。把质量阈值和安全边界作为必须满足的约束，不应以平均费用下降证明总体方案更优。

**失败与取舍：**便宜模型可能增加修复重试次数；高命中缓存若权限键错误会泄露数据；账单告警并不必然是执行层硬上限。预算控制应对不确定价格做保守预留，对失败任务记录消耗，在权限或关键事实变更时使旧结果失效。

## 5. 关联知识与易混辨析

Cost per Task 是均摊单价，Cost–Quality Trade-off 要同时考虑质量和约束；模型准确率上升不必然等于真实业务完成率上升。

应把调用级 token、任务级费用、预算策略、缓存有效性和业务完成率作为不同量分别建模。进行选型或成本报告时注明单位、统计期间、纳入的工具费用和失败样本，否则“每次调用价格下降”可能掩盖真正的任务总成本上升。

## 6. 中等难度面试题（含参考答案）

1. **问：怎样避免在成本优化中无意降低安全？** 答：把最小权限、数据保护和高风险审批作为硬约束，优化模型路由与缓存等可调整部分，并用回归评测验证。
2. **问：一个更贵的模型成功率更高，如何判断是否值得？** 答：以统一任务集计算成本/成功结果、质量阈值、尾延迟与风险，做 Pareto 比较和置信度评估。

回答应覆盖数据来源、并发资源控制、计量精度以及业务边界，说明如何用受控任务评测验证所提出的优化。

## 7. 中等难度考试题（含解析）

1. **题：A 方案 $0.04/次、成功率 80%；B $0.06/次、成功率 95%，各自成功摊销成本？** 解：A: $0.04/0.8=$0.05；B: $0.06/0.95≈$0.0632。 明确分母、币种或 token 数、所含费用范围，并验证数值合理性。
2. **题：若 A $0.05/次质量 90 分，B $0.06/次质量 88 分且其他条件相同，是否 B 被支配？** 解：是，A 成本更低且质量更高；但若有不同的安全/尾延迟约束，需重新比较。 要解释正确原因和常见误用，不能把成本优化与忽略业务授权混同。
