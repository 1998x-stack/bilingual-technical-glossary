# Cost Budget（成本预算）

> AI Agents · 专题：工程化、成本与可观测性 · 模型用量、成本预算与缓存治理

## 1. 核心定义

**Cost Budget（成本预算）**：为一个用户任务、工作流、租户或计费周期设定的可接受费用上限与执行控制方式。硬预算意味着可信执行器在启动工作前检查/预留额度，而预算告警不自动保证停止收费。

**定义边界：**有关 token、价格、配额和缓存的产品语义可能依模型与服务版本变化。本文只定义可以迁移的工程方法；练习数字均假设给定，不能误称任何供应商当前实际价格或基准数据。成本不是唯一目标，正确的任务结果、隐私和安全权限应具有清晰的最低门槛。

## 2. 形象理解

**类比：**像出差经费：预算表提醒花费接近上限，真正控制需要付款前核销额度。

**类比的局限：**第三方账单可能存在延迟，在途工作也可能继续计费，不能把账单页面通知等同硬中断。 实际 Agent 有多种费用、资源状态和分布式后置结果，因此不能从类比推导精确计费或可靠性保证。

## 3. 技术原理与核心内容

外层预算账本记录 reserved、spent、remaining，派生子任务必须共享父任务额度；启动并行分支前原子预留，不足就减少 fan-out 或降级。对未知价格工具保守估计，并定期对账。注意云供应商有 alerts-only 与符合条件的 spend caps 两种机制，支持范围和延迟不一。

**成本模型与治理边界。**一个 Agent 任务会跨多次模型调用、检索、数据库、工具、人工审批和失败重试；应依调用 ID 归集用量，再按相应计价规则计算，不凭空使用特定厂商报价。要区分当前已结算与在途预留，模型回答成功不等于业务完成。缓存值、外部工具结果和旧记忆属于数据来源，不得因低成本或高相似度而突破现有授权与业务实时状态。

**执行闭环。**入口分配 task_id 和共享额度，执行器在每个子任务前检查预估资源需求，随后记录实际 usage 与工具费用；必要时主动拒绝或降级。所有业务写入仍要使用真实权限和幂等键，不能因为缓存或便宜模型的建议就直接行动。

## 4. 工程实践与设计权衡

**工程案例：**研究 Agent 有 $2 预算，运行 5 个并行分析分支，若每个本地都读到 $2 余额会共同超支。需在调度器原子预留每分支最高费用，并将总余量返还/扣除。

**验证程序。**用固定任务集同时统计输入/输出用量、模型/工具调用数、重试次数、实际成功数、端到端 P95、成本与安全拦截；计算两组候选方案的成功摊销成本并标记计费口径。注入并发、超时、缓存过期、权限变更和费用报告滞后等边界用例，不使用真实客户数据。把质量阈值和安全边界作为必须满足的约束，不应以平均费用下降证明总体方案更优。

**失败与取舍：**便宜模型可能增加修复重试次数；高命中缓存若权限键错误会泄露数据；账单告警并不必然是执行层硬上限。预算控制应对不确定价格做保守预留，对失败任务记录消耗，在权限或关键事实变更时使旧结果失效。

## 5. 关联知识与易混辨析

Quota 可以按调用数或 tokens 限制，Cost Budget 以费用计；Billing Alert 是阈值通知，不是可依赖的系统级硬拒绝。

应把调用级 token、任务级费用、预算策略、缓存有效性和业务完成率作为不同量分别建模。进行选型或成本报告时注明单位、统计期间、纳入的工具费用和失败样本，否则“每次调用价格下降”可能掩盖真正的任务总成本上升。

## 6. 中等难度面试题（含参考答案）

1. **问：怎样实现层级 Agent 共享硬预算？** 答：父任务用集中/原子账本分配和预留额度，子任务回收未花费余额，超预算时拒绝或安全降级。
2. **问：为什么只设置云平台预算告警不能保证永远不超支？** 答：告警有延迟且可能只通知；部分厂商提供限定服务的 spend cap，仍需理解范围和在途请求。

回答应覆盖数据来源、并发资源控制、计量精度以及业务边界，说明如何用受控任务评测验证所提出的优化。

## 7. 中等难度考试题（含解析）

1. **题：预算 $10，已结算 $6.20，尚有在途预留 $1.30，可再预留多少？** 解：10−6.20−1.30=$2.50。 明确分母、币种或 token 数、所含费用范围，并验证数值合理性。
2. **题：5 个并发子任务分别预估 $3，父预算 $10，能全部启动吗？** 解：不能，全启动可能预留 $15；应限制至最多 3 个并发或调整策略与保守估值。 要解释正确原因和常见误用，不能把成本优化与忽略业务授权混同。
