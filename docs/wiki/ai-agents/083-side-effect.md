# Side Effect（副作用）

> AI Agents · 专题：工具使用与环境交互 · 适用范围：通用工程概念；具体服务协议以官方文档和版本为准

## 1. 核心定义

**Side Effect（副作用）**：Side Effect（副作用）是一次操作除返回数据外，对外部世界或持久状态产生的变化，例如写数据库、扣费、发送邮件、修改权限和创建工单。Agent 必须把副作用与只读观察分开管理。

**适用边界：**“有副作用”不意味着所有副作用都有害；安全风险取决于可逆性、授权、影响范围和重复执行语义。某些表面只读的 API 也可能记录访问日志，但通常不构成用户请求的主要业务状态变化。

## 2. 形象理解

查看银行余额是读取信息；执行转账改变账户资金分布，即使两个按钮都返回一条消息。

**类比的局限：**真实系统还会产生审计日志、通知和异步回调，不能仅凭接口名 read/write 完整判断效果。

## 3. 技术原理与核心内容

将动作分类为 read_only、reversible_write、irreversible_or_high_impact，并定义 precondition、authorization、idempotency、confirmation、postcondition。写入可结合事务、outbox、操作 ID 与补偿动作处理部分失败。若网络断开，状态可能为 unknown，必须从权威记录判断是否已实际提交；模型的“已完成”只是文本。

## 4. 工程实践与设计权衡

**工程案例：**招聘 Agent 可以自动检索候选人资料，但向候选人发送正式录用邮件属于高后果副作用，需审批且在发送后核对消息 ID，避免因超时重复通知。

**失败模式与验证：**把工具调用当纯函数、在搜索回溯时重复执行写操作、未经用户授权发送信息、出现部分提交后丢失记录。对单次和重复调用都做副作用审计及权限负向测试。

## 5. 关联知识与易混辨析

Side Effect 是外部状态变化；Idempotent Operation 表示重复后预期状态不再额外变化；Sensitive Action 指高风险操作。副作用可能是幂等或非幂等，也可能敏感或非敏感。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 Agent 的工具调用追踪必须记录副作用状态？** 答：模型计划可重新生成，但已发邮件/扣款不能随意恢复；执行台账可阻止重复写入并支持补偿和验收。
2. **问：HTTP GET 是否绝对不能产生任何副作用？** 答：规范上 GET 被定义为安全方法，指用户请求的主要意图不是状态改变；服务器仍可能记日志等副作用，违反规范的 GET 业务写入也确实存在。

## 7. 中等难度考试题（含解析）

1. **题：有一条只读查询耗时 1 秒、一条写入耗时 2 秒，写入超时后未经确认再执行一次，最多可能写入几次？** 解：如果两次请求都在服务器生效，可能产生 2 次写入；耗时信息不能证明首次未执行。
2. **题：给出读取订单状态与删除订单两种动作的风险差别。** 解：读取通常为只读观察，删除是业务状态变化，后者需要更强的归属权限、确认、审计及后置核验。
