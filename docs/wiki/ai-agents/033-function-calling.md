# Function Calling（函数调用）

> AI Agents · 专题：模型能力与推理 · 适用范围：通用智能体系统设计；具体实现以官方文档为准

## 1. 核心定义

**Function Calling（函数调用）**：Function Calling（函数调用）是一种让模型根据注册的工具签名提出函数名与结构化参数，再由宿主程序授权、执行、获取结果并回传给模型的交互机制。模型的输出只是调用意图，不是执行已完成的证明。

**适用边界：**调用可有多个或并行候选；字段 schema、严格模式与并发支持因接口而异。外部执行由应用控制。

## 2. 形象理解

像调度员填写维修单：维修工必须接受工单、确认权限与参数后才真正动工。

**类比的局限：**工单的合法格式既不能保证真实维修已经完成，也不能授予调度员额外权限。

## 3. 技术原理与核心内容

步骤为 `register tool schema → model(tool_choice) → tool_call(name,args,id) → validate/authorize → execute → tool_result(id) → model`。对只读工具可做安全重试；发短信/退款等写入需要幂等键、确认、日志与执行状态查询。工具结果是外部数据，不能升级为高优先级指令。

## 4. 工程实践与设计权衡

**工程案例：**日历 Agent 查空闲时间后生成 `create_event(start,end,attendees)`。执行器检查时区、冲突、邀请范围和用户确认，再调用服务端 API。最后必须检查日程 ID，而不是把模型文本“预约成功”当事实。

**失败模式与验证：**模型可能选择不存在的函数、输出字段不合法或请求并行的冲突写操作。输入校验、白名单、工具调用关联 ID 与依赖管理是生产必需环节。

## 5. 关联知识与易混辨析

Tool Call 是请求外部动作，Function Calling 是实现其模型/应用交互的协议；Structured Output 可以只返回结构对象而完全不调用工具。

## 6. 中等难度面试题（含参考答案）

1. **问：怎样防止模型删除无权限文件？** 答：执行器从可信身份确认权限，验证路径、文件归属与删除审批；提示写“谨慎删除”不足以阻断风险。
2. **问：写工具超时后能否直接重试？** 答：先用请求标识查询权威状态，或依赖服务端幂等机制；否则可能双写。

## 7. 中等难度考试题（含解析）

1. **题：schema 要求 `amount` 为整数，模型返回字符串 `"50"`，应执行退款吗？** 解：不得直接执行；类型不符合要求。拒绝参数或按明确的安全转换规则重新验证。
2. **题：查库存后才可下单，若模型同时给出两项调用可以并行吗？** 解：不能安全并行；创建订单取决于查询结果和验证，执行器应维护依赖顺序。
