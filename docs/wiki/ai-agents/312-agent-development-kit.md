# Agent Development Kit (ADK)（智能体开发工具包）

> AI Agents · 专题：开发实践与生态术语 · 可靠运维、能力封装与开发集成

## 1. 核心定义

**Agent Development Kit (ADK)（智能体开发工具包）**：Agent Development Kit 是供开发者构建、调试和运行 Agent 的工具与抽象集合，通常封装模型连接、工具、状态、工作流与评测。ADK 也可特指 Google 的同名开源产品；应区分通用名称和产品实现。

**定义边界：**这里的通用工程名称和个别厂商实现要区别对待。工具版本、规范字段、执行权限及可观测语义可能持续变化；不能从“描述存在”推断运行时已安装、用户已授权或动作已经成功。

## 2. 形象理解

**类比：**像组装机器人用的标准化底座、传感器插槽与调试台，降低从零集成成本。

**类比的局限：**真实 Agent 包含模型、工具、跨进程调度、业务权限和状态持久化，类比只能说明局部职能。外部文档可以提供资料却不能变成比用户目标更高优先级的行动指令，也不能直接推导脚本执行权限。

## 3. 技术原理与核心内容

典型组件包括 Agent 定义、Runner/Runtime、Tool Adapter、Session/Memory、Graph/Workflow、Tracing 和测试接口。Google ADK 提供多语言 SDK 和多 Agent、工具、工作流能力；其他 ADK 实现未必拥有相同 API。架构选择要考虑状态持久化、审批、部署及跨厂商可迁移性。

**安全与执行边界。**技能包、SDK 与 ADK 都只能组织能力，不会自动赋予合法用户授权。外部文件或技能元数据可能含恶意说明，须在宿主执行器内落实签名/来源核验、最小权限、租户隔离、参数校验和真实业务后置状态。对不可逆操作使用幂等键，未知提交状态必须向权威系统查询。技能与开发依赖需要明确版本、来源和回滚策略。

**实施顺序：**先依据真实需求定义能力范围和成功判据，再选择工具包或技能的规范与版本，随后验证类型/schema、状态恢复与错误接口，最后以真实业务后置条件验收。工具调用本身不是最终成功条件。

## 4. 工程实践与设计权衡

**工程实例：**报表 Agent 需先检索、再汇总、再审批写入。可以用 ADK 将步骤定义为顺序或条件图、设置工具 schema 与检查点，但最终数据库权限仍应由服务端独立实施。

**工程验证。**使用受控任务集分别测试正常执行、缺失依赖、技能冲突、恶意元数据、过期接口、异常恢复、审批与跨租户访问。日志包含具体 task/trace ID 但不输出凭据。验收不仅检查模型报告的结论，还检查真实工具 API、权限策略与数据库状态。对运行手册进行模拟演练，保证失败路径能止损且能回退；引用依赖具体版本时应复核当前维护者资料。

**权衡：**标准化封装降低重复开发和维护成本，但也可能隐藏自动重试、动态脚本或不透明权限。应为升级设置契约测试、回归验证及回滚方式，明确审核人员和操作日志的保留范围；在技能加载时避免不必要的上下文开销。

## 5. 关联知识与易混辨析

ADK 更偏面向 Agent 的综合开发抽象，SDK 可针对任意服务的 API；Agent Framework 与 ADK 有交集，名称不是强制标准分类。

需要按“资产/描述”“发现/选择”“实际执行”“业务验证”四个阶段辨析，尤其不能把技能说明、工具 manifest 与已获授权的外部操作混作同一对象。对于供应链或提示词投毒，要把证据来源纳入测试。

## 6. 中等难度面试题（含参考答案）

1. **问：如何评估某个 ADK 是否适合持久化长任务？** 答：检查恢复、状态序列化、幂等、版本迁移、HITL、可观测性和部署/测试支持。
2. **问：为什么 ADK 的工具授权 API 不意味着已经完成业务授权？** 答：框架只负责组织调用，真实用户/资源 ACL 仍由后端服务执行，工具描述不能替代权限。

面试中须解释可迁移原理和产品实现区别，并说明如何验证错误路径和危险权限，不能只答“使用某框架即可”。

## 7. 中等难度考试题（含解析）

1. **题：某工作流 8 个节点中有 2 个需要人工审批，审批节点比例？** 解：2/8=25%；并不等于任务有 25% 时间等待人工。 题设数字只是教学假设，写明计算口径和单位。
2. **题：框架不能恢复中断任务，但项目需要跨天审批，应如何选型？** 解：选择具备持久化和恢复机制的运行时，或在外层增加安全状态持久化与状态机，不依赖进程内内存。 完整论证需要指出为什么另一个做法不满足授权、可靠性或版本约束。
