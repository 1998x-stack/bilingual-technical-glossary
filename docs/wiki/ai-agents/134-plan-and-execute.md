# Plan-and-Execute（计划后执行）

> AI Agents · 专题：工作流与编排模式 · 应用架构、状态恢复与工程权衡

## 1. 核心定义

**Plan-and-Execute（计划后执行）**：Plan-and-Execute（计划后执行）是先形成步骤、依赖和验收条件的计划，再依计划逐步调用工具或子 Agent 的工作流组织方法。相较每步都临时决定，计划先行有利于可解释性和预算控制，但环境变化时仍须校验与重规划。

**适用边界：**初始计划只是基于现有信息的候选路线，不自动证明每一步可执行。Plan-and-Solve Prompting 是一篇研究中的提示策略，生产中的 Plan-and-Execute 系统还需真实工具状态、权限与恢复机制。

## 2. 形象理解

像施工前制定材料清单、施工顺序和验收清单，施工时根据现场条件逐步落实，必要时变更设计。

**类比的局限：**图纸不会自动阻止天气变化或工程材料不足；已经施工的部分不能像纸面步骤那样随意擦除。

## 3. 技术原理与核心内容

构造 plan P=[(action_i,precondition_i,postcondition_i,dependencies_i)]，先做可行性检查，再按拓扑依赖调度。每步完成后用权威环境状态验证 postcondition，失败后标记已完成节点与未知外部副作用，再计算剩余可行计划。使用 deadline、cost_budget 和审批条件防止越界。

## 4. 工程实践与设计权衡

**工程案例：**库存盘点 Agent 先列出‘读取库存、对账、列差异、提交调整审批’，只有前几项确认且用户授权后才允许写入库存调整。盘点过程若仓库实时锁单变化，应重查状态而非直接照旧计划修改。

**失败模式与验证：**模型生成不存在的工具、计划未列资源约束、环境变化未重规划、已执行付款被重复运行、计划太大导致上下文溢出。测试前置条件失败、版本变化、部分提交和预算终止。

## 5. 关联知识与易混辨析

Plan-and-Execute 是先计划后执行的控制方式；Reactive Execution 每轮基于即时观察行动；Planning 是形成计划的理论过程；Orchestration 管理实际执行与状态恢复。

## 6. 中等难度面试题（含参考答案）

1. **问：如何判断初始计划已过时？** 答：执行时前置条件不满足、资源/工具变化或目标约束改变；以权威状态为准，保留已执行事实并重规划后缀。
2. **问：先制定计划是否一定慢于实时反应？** 答：不一定；计划有开销，却可能减少无效工具调用和重复搜索，需按任务复杂度和风险衡量总时间。

## 7. 中等难度考试题（含解析）

1. **题：计划 A→B→C，耗时 2、4、3 分钟且严格依赖，总执行时间？** 解：2+4+3=9 分钟，不含初次规划时间。
2. **题：A 已成功写入订单，B 失败，新计划包含重新执行 A 是否一定正确？** 解：不正确。必须固定 A 的外部状态并查订单 ID，避免重复创建。
