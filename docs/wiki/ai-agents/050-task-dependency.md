# Task Dependency（任务依赖）

> 适用领域：AI Agents · 专题：任务规划与决策 · 相关理论与具体产品能力应依据所引来源和版本区分

## 1. 核心定义

**Task Dependency（任务依赖）**：Task Dependency（任务依赖）描述任务之间为了保证正确性必须遵守的先后顺序、数据可用性或共享资源限制。典型依赖为“任务 B 必须等待任务 A 产生合格输出”，也可能包含同一独占资源不能同时使用的约束。

**适用边界：**DAG 只能直接表示无环的前置依赖；循环迭代、互斥资源与事务约束需要额外的调度语义，不应误把有向环当作合法静态拓扑序。

## 2. 形象理解

像修房子必须先打地基再砌墙，但两个不同房间的粉刷在资源充足时可以同时做。

**类比的局限：**图上没有边不代表现实中完全独立：两项工作可能争抢同一设备或写同一文件。

## 3. 技术原理与核心内容

对任务图 `G=(V,E)`，边 `u→v` 表示 v 依赖 u。无环时可通过 Kahn 算法按入度为零的节点启动并行批次；关键路径时长为 DAG 上最长依赖路径（假设任务固定耗时、无资源限制）。资源互斥另由锁、限流或互斥约束控制。

## 4. 工程实践与设计权衡

**工程案例：**软件交付中源代码检查通过后才能部署到测试环境；监控指标和日志分析可在部署后并行，但生产发布必须等待完整验收。自动编排器按依赖释放任务，并在失败时阻断下游。

**失败模式与验证：**隐式依赖遗漏会导致过早触发支付/发布；循环依赖导致死锁；依赖过强导致无谓串行。建立静态环检测、运行时状态检查和关键路径指标。

## 5. 关联知识与易混辨析

Task Dependency 是任务之间的关系；Task Priority 决定已就绪任务谁先获得资源；Control Flow 实现真正的执行次序与错误转移。

## 6. 中等难度面试题（含参考答案）

1. **问：调度器发现所有任务都有未满足依赖且无运行中任务，首先检查什么？** 答：检查是否有有向环、失败节点阻塞或依赖状态丢失；运行拓扑环检测，不应无限等待。
2. **问：两个没有直接依赖的任务一定能并行吗？** 答：不一定，还需检查共享 GPU、文件写入、外部 API 限流和事务隔离等资源/安全约束。

## 7. 中等难度考试题（含解析）

1. **题：DAG 中 A=2s 后可并行 B=5s、C=3s，D=4s 依赖 B/C；忽略资源限制的关键路径？** 解：A→B→D，总时长 2+5+4=11s；经 C 的路径 2+3+4=9s。
2. **题：两任务互相依赖：A→B 与 B→A。是否存在拓扑排序？** 解：不存在，这是有向环。应重新设计依赖、合并成循环状态机，或拆除不必要约束。
