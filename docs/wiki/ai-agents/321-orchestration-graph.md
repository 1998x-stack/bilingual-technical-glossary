# Orchestration Graph（编排图）

> AI Agents · 专题：开发实践与生态术语 · 编排、输入构造与运行配置

## 1. 核心定义

**Orchestration Graph（编排图）**：编排图是把智能体工作流表示为节点、边和共享/传递状态的有向图模型，用以定义执行顺序、条件分支、并行汇合、循环和终止条件。具体框架可支持动态图、持久化检查点和人工介入，但图本身不是业务成功证明。

**适用范围：**通用概念与具体框架的 API 有区别。特别是 LangGraph 的 Graph API、Python 变量接口和具体 Prompt Template 运行库各自拥有版本与实现约束；不能把某个示例的调度行为当作所有 Agent 的默认能力。

## 2. 形象理解

**类比：**像地铁线路图：站点是行动步骤，轨道和换乘规则决定下一站可去哪里。

**类比的局限：**类比中的顺序和约束不代表真实网络、任务调度与业务权限。Agent 可能跨服务并行、因重试重复运行或在调用后才发现状态未知，所以仍需真实状态模型及明确终止条件。

## 3. 技术原理与核心内容

在 LangGraph 的 StateGraph 中，开发者声明 state schema、`add_node`、`add_edge`、`add_conditional_edges`，并使用 START/END 构造流程。节点读取状态并返回部分状态更新，reducer 控制多个分支对同一字段的合并。需要明确循环退出条件、最大步数、checkpoint 与副作用的重放语义。静态边与条件边混用可能导致两条路径都执行。

**安全与状态前提。**Agent 的模型推断、工具 API 调用和最终业务提交是三个不同事件。无论图如何路由、模板如何格式化，所有高影响写入均需要可信执行器的授权、输入校验、幂等处理和权威后置状态复核；外部文档和工具输出必须保持低信任，不能把引导文字升级成用户权限。真实生产配置与秘密不可出现在知识库、Prompt 或原始日志里。

**设计视角。**首先定义输入数据与状态 schema、允许的后继路径、可观察事件和完成条件，再将复用模块封装为可独立测试的步骤。对动态依赖使用预算和截止时间，对不可信数据明确边界，对参数版本变更设回归用例。

## 4. 工程实践与设计权衡

**工程实例：**资料分析 Agent 的图为 START→检索→文档评估→(证据不足?再次检索:起草)→审稿→END，审稿失败回到起草。设最多 3 次检索，禁止无上限循环；支付工具不得在恢复时重复执行。

**测试与可观测性。**为同一个可重复任务建立基线，记录任务/跨度 ID、版本、分支选择、输入数据来源、成功验收条件与完成时延。在隔离环境注入超时、缺字段、并行写同一状态、循环次数超限、取消/恢复和恶意检索内容，检查错误分支与副作用控制。运行时不只判断模型自报“成功”，还要核实工具结果、业务数据库/账本与权限审计。

**工程权衡。**抽象化可以提高复用与可读性，却可能隐藏框架默认的并发/重试及额外 token 成本；限制过严会牺牲灵活性，限制过宽则放大提示注入和重复副作用风险。重要策略需要日志可追踪、配置可复核、失败可回退。

## 5. 关联知识与易混辨析

Orchestration Graph 表示执行控制流与状态；DAG 不允许有向环，Agent 工作流常有迭代环；单纯 Chain 主要线性步骤，不等于可路由工作流。Node 负责计算，Edge 负责转移和依赖。

跨术语评审应分别回答：这是执行节点、控制关系、生成输入的模板，还是进程配置？它对用户成功率、权限边界和数据来源有什么影响？名称相似并不意味着相同的运行时保证。

## 6. 中等难度面试题（含参考答案）

1. **问：含循环与并行的 Agent 编排为什么不能只用线性调用列表？** 答：线性列表难表达动态路由、检查点、恢复与并发汇合；图可明确控制流和约束，仍需处理副作用重放。
2. **问：怎样保证并发分支更新同一个 state key 时合并正确？** 答：在 state schema 指定 reducer 或单写者策略，校验更新是否交换/结合，必要时同步并避免覆盖。

优秀回答应该说明真实系统的约束、边界故障以及如何通过测试验证，而非只复述单个 API 名称。

## 7. 中等难度考试题（含解析）

1. **题：图 A→B、A→C，B/C 可并行且耗时 3s/5s，A 用 2s，末端汇合 D 用 1s，理想总时长？** 解：2+max(3,5)+1=8 秒，假定分支并行且没有调度开销。 **注意：**数值和前提仅来自题设，不是生产实测。
2. **题：一个图在每次失败后无条件回到同一节点，缺少上限有什么问题？** 解：可能陷入无限循环、耗尽 token/费用和工具配额；需要退出条件、预算和步数限制。 **注意：**明确执行路径或参数范围，不能把未执行的分支、额外权限或隐含转换计入结果。
