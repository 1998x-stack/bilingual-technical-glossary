# Constrained Decoding（约束解码）

> AI Agents · 专题：模型能力与推理 · 适用范围：通用智能体系统设计；具体实现以官方文档为准

## 1. 核心定义

**Constrained Decoding（约束解码）**：Constrained Decoding（约束解码）指在模型生成每个 token 时，根据语法或结构状态限制可继续生成的 token，让完成的输出满足可编译的格式约束。限制可以来自正则语法、JSON schema 或自动机，具体实现取决于推理引擎。

**适用边界：**约束的主要目标是格式正确而非事实真实；复杂语义依赖不一定能编译成解码约束。

## 2. 形象理解

像棋局规则限制能走哪些格子，禁止非法走法。

**类比的局限：**合法落子仍可能导致输棋；格式合法不保证答案有效。

## 3. 技术原理与核心内容

原始 token 概率为 p_i，允许集合 A 由前缀和语法状态决定。解码时对 i∈A 重新归一化 `p'_i=p_i/Σ(j∈A)p_j`，其余 token 概率设为零；到接受态后才能结束。实现须考虑一个 token 可能跨越多个字符，schema 子集支持与语义校验也须独立处理。

## 4. 工程实践与设计权衡

**工程案例：**工单系统要求返回具有固定键的 JSON。约束解码能减少括号、字段名或类型错误；却无法检测 `amount=800` 实际应为 80。应在生成前预编译 schema，完成后由业务规则与来源对照验证。

**失败模式与验证：**无法满足的 schema 或无法兼容的语法可能导致 API 错误或生成中止。错误引用仍可能填在 `source_url:string` 里，因此需要外部链接/证据验证。

## 5. 关联知识与易混辨析

后处理 JSON.parse 不改变已经采样的 token；约束解码在生成过程中禁止不合法序列；结构化输出是端到端格式目标。

## 6. 中等难度面试题（含参考答案）

1. **问：相比生成后 `JSON.parse`，约束解码有什么收益？** 答：生成过程中排除非法 token，可提高形式遵循率；仍要分别检查内容真实性。
2. **问：为什么引擎不能直接支持所有 JSON Schema 逻辑条件？** 答：部分关键词涉及跨字段、动态外部状态或复杂语义，无法在有限语法状态中高效限制下一 token；需后置校验。

## 7. 中等难度考试题（含解析）

1. **题：A/B/C 原始概率 0.5/0.3/0.2，语法只允许 B/C，重归一化后概率？** 解：总允许质量为 0.5；B=0.3/0.5=0.6，C=0.2/0.5=0.4。
2. **题：JSON 有效，但给出不存在的 DOI。约束解码能发现吗？** 解：不能。论文真实性由外部检索、引用检查或人工审查判断。
