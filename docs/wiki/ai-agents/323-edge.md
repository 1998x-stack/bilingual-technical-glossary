# Edge（边）

> AI Agents · 专题：开发实践与生态术语 · 编排、输入构造与运行配置

## 1. 核心定义

**Edge（边）**：边是编排图中连接节点、表示调度依赖或状态条件转移的关系。边可以是固定的后继关系，也可以通过条件路由选择下个节点或多个并行后继；选择语义取决于具体执行框架。

**适用范围：**通用概念与具体框架的 API 有区别。特别是 LangGraph 的 Graph API、Python 变量接口和具体 Prompt Template 运行库各自拥有版本与实现约束；不能把某个示例的调度行为当作所有 Agent 的默认能力。

## 2. 形象理解

**类比：**像机场转机路径：登上哪一班后续航班取决于固定航线与转机条件，不能凭上一站的说法默认已到终点。

**类比的局限：**类比中的顺序和约束不代表真实网络、任务调度与业务权限。Agent 可能跨服务并行、因重试重复运行或在调用后才发现状态未知，所以仍需真实状态模型及明确终止条件。

## 3. 技术原理与核心内容

在 LangGraph 中，`add_edge('a','b')` 声明固定后继；`add_conditional_edges('a',route)` 根据当前 state 路由，可返回一个或多个节点或 END。`add_edge(['b','c'],'d')` 可等待 b/c 都完成后再执行 d；多个普通出边也可能触发并行分支。不要在同一节点上随意混用固定边与动态路由，否则可能运行双路径。

**安全与状态前提。**Agent 的模型推断、工具 API 调用和最终业务提交是三个不同事件。无论图如何路由、模板如何格式化，所有高影响写入均需要可信执行器的授权、输入校验、幂等处理和权威后置状态复核；外部文档和工具输出必须保持低信任，不能把引导文字升级成用户权限。真实生产配置与秘密不可出现在知识库、Prompt 或原始日志里。

**设计视角。**首先定义输入数据与状态 schema、允许的后继路径、可观察事件和完成条件，再将复用模块封装为可独立测试的步骤。对动态依赖使用预算和截止时间，对不可信数据明确边界，对参数版本变更设回归用例。

## 4. 工程实践与设计权衡

**工程实例：**报销 Agent 通过校验节点后，满足额度的申请走自动审批边，超额申请必须走人工审批边。如果错误地同时添加固定边直接通向付款，可能绕过审批。

**测试与可观测性。**为同一个可重复任务建立基线，记录任务/跨度 ID、版本、分支选择、输入数据来源、成功验收条件与完成时延。在隔离环境注入超时、缺字段、并行写同一状态、循环次数超限、取消/恢复和恶意检索内容，检查错误分支与副作用控制。运行时不只判断模型自报“成功”，还要核实工具结果、业务数据库/账本与权限审计。

**工程权衡。**抽象化可以提高复用与可读性，却可能隐藏框架默认的并发/重试及额外 token 成本；限制过严会牺牲灵活性，限制过宽则放大提示注入和重复副作用风险。重要策略需要日志可追踪、配置可复核、失败可回退。

## 5. 关联知识与易混辨析

Edge 控制移动与依赖，Node 处理输入和更新；Conditional Edge 是状态驱动的转移，Static Edge 是固定转移。边并不携带业务授权，也不能保证 downstream 一定成功。

跨术语评审应分别回答：这是执行节点、控制关系、生成输入的模板，还是进程配置？它对用户成功率、权限边界和数据来源有什么影响？名称相似并不意味着相同的运行时保证。

## 6. 中等难度面试题（含参考答案）

1. **问：怎样防止审批图出现“自动付款”旁路？** 答：审查所有通往写入节点的路径，限制固定边和条件边混用，付款节点仍进行服务端授权。
2. **问：若两个并行分支必须完成才能汇合，图中边要表达什么？** 答：需要 AND-join/明确等待依赖；同时防止一个分支永不结束导致死等，设置超时和失败路径。

优秀回答应该说明真实系统的约束、边界故障以及如何通过测试验证，而非只复述单个 API 名称。

## 7. 中等难度考试题（含解析）

1. **题：条件边在一次执行中只选 A 或 B，A 用 2s、B 用 4s，若 A 被选本次分支用时多少？** 解：2 秒，不应把未执行的 B 用时算进去。 **注意：**数值和前提仅来自题设，不是生产实测。
2. **题：A 同时发出到 B、C 的并行边且 B/C 分别 3s/7s，理想分支结束需多久？** 解：max(3,7)=7 秒，假设并行且无额外汇合开销。 **注意：**明确执行路径或参数范围，不能把未执行的分支、额外权限或隐含转换计入结果。
