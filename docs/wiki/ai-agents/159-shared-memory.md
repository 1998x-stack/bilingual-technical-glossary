# Shared Memory（共享记忆）

> AI Agents · 专题：多智能体协作 · 多 Agent 协作模式与信任边界；SDK API 以版本文档为准

## 1. 核心定义

**Shared Memory（共享记忆）**：Shared Memory（共享记忆）是多个 Agent 在授权范围内共同读取、更新或引用的信息存储，用来交换任务进度、事实和中间结果，减少重复检索和上下文丢失。共享范围可以是同一任务、项目或租户，不等于全球公开存储。

**适用边界：**共享记忆中的记录不自动可信、最新或属于所有 Agent；并发写入需一致性策略，用户撤销和跨租户访问必须传播到缓存与索引。它不同于大模型内部参数记忆。

## 2. 形象理解

像团队共同维护的版本化项目 Wiki 与任务看板，成员依自己的权限访问内容，修改要留下来源和时间。

**类比的局限：**多人可见不代表内容经审核；两个成员同时编辑同一页也可能发生最后写入覆盖。

## 3. 技术原理与核心内容

采用 Store namespace=(tenant,project,task), key=memory_id, value={content,source,version,ttl,acl}。写入需 owner 验证、乐观并发/CAS，读取先做 ACL 和时效过滤；敏感记录用引用而非原文广泛广播。共享长期存储与短期 thread checkpoint 分离，写入索引后确保撤回/删除同步。关键业务事务状态仍以权威外部系统为准。

## 4. 工程实践与设计权衡

**工程案例：**研发 Agent 和测试 Agent 共享 API 的版本与 PR SHA，测试在特定 commit 上运行；若开发 Agent 推进到新 SHA，旧测试结果不得用于新版本的部署 gate。协调器发布版本变更事件，并要求重新测试。

**失败模式与验证：**越权共享、同名键串租户、并发状态覆盖、错误事实被所有 Agent 反复复述、索引延迟让已删除偏好继续被看到。做权限负例、竞态更新、版本适配和撤回后不可读测试。

## 5. 关联知识与易混辨析

Shared Memory 是共同存储的机制；Blackboard 是以公共任务事实/假设协调多个知识源的架构模式；Message Bus 以事件流传输消息；Conversation History 是交互事件而非全部共享事实。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么共享记忆记录需要 owner/tenant 与版本？** 答：控制可见性和并发更新，避免把他人记录或旧版本知识误用于当前任务。
2. **问：共享记忆能否作为用户付款已成功的唯一证据？** 答：不能。它可能是过时摘要，应查询支付系统权威交易状态与对应业务 ID。

## 7. 中等难度考试题（含解析）

1. **题：3 个 Agent 对同一 key 都以 version=5 更新，只允许 CAS 成功一次，那么成功更新的最大次数？** 解：同一版本条件最多 1 次，其余必须重新读取并协调；不意味着业务写入最多一次。
2. **题：版本 12 的共享测试记录与当前代码版本 13 不一致，还能直接据此部署吗？** 解：不能，测试证据关联不同 artifact 版本，需要针对版本 13 重跑或验证适用性。
