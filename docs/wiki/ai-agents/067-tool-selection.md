# Tool Selection（工具选择）

> AI Agents · 专题：工具使用与环境交互 · 通用工程概念；具体行为以平台、协议与版本为准

## 1. 核心定义

**Tool Selection（工具选择）**：Tool Selection（工具选择）指 Agent 根据当前目标、可用工具描述、执行前置条件、风险与成本决定采用哪一种能力。它关注‘使用哪个工具’，选择结果仍需要由执行层强制权限检查。

**适用边界：**模型根据名称或描述做语义匹配不保证可靠；同样与退款有关的工具可能一个只读、一个创建新交易，风险完全不同。

## 2. 形象理解

维修人员先判断该用测量仪还是拆卸工具，而不是看哪个工具名字最像故障现象。

**类比的局限：**即使选中正确工具，也可能在错误时间或用错误参数操作。

## 3. 技术原理与核心内容

从注册/发现的工具集合 T 出发，先按当前用户身份、任务前置条件和资源约束筛为 T_valid。模型在候选内依据需求描述选择工具，随后执行器重新做工具名白名单与 schema 校验。对于几百种工具，可先按能力与说明搜索 top-k 个候选来减少上下文，但后端仍需再次授权。

## 4. 工程实践与设计权衡

**工程案例：**客服问‘这笔订单退款了吗’，选择只读 get_refund_status 而非 create_refund。评测题集纳入同义名称、错误参数、跨账户调用和高风险动作，统计工具选择准确率与高后果误选率。

**失败模式与验证：**名称相似而副作用不同是最常见的错误来源；无视工具实际健康状态会反复错调，能力列表过长还可能淹没关键工具定义。要使用独立路由/权限门控并监测误调用。

## 5. 关联知识与易混辨析

Tool Selection 负责在候选能力间做决定；Tool Routing 负责把已批准的调用送给正确执行器；Tool Discovery 负责查询当前有哪些能力可用。

## 6. 中等难度面试题（含参考答案）

1. **问：系统应该如何区别 check_refund 与 issue_refund？** 答：除了语义描述，还应记录 risk_level/read_only 和执行权限；只读查询应优先，写入需要明确任务目标与审批。
2. **问：工具从 10 种增至 300 种，怎样控制选择错误？** 答：使用任务检索或分层分类减少候选数量，评估相关 top-k 召回，执行端保持严格权限与参数校验。

## 7. 中等难度考试题（含解析）

1. **题：100 个工具选择决策中 87 次正确，选择准确率是多少？** 解：87/100=87%，但仍要评估错选写工具等高风险错误。
2. **题：用户只问是否已发送邮件，系统有 status_email 和 send_email。应该首先选哪个？** 解：status_email，只读查证；不能在尚未核对时触发第二次发送。
