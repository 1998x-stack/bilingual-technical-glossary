# Reasoning and Acting (ReAct)（推理与行动协同 · ReAct）

> AI Agents · 专题：模型能力与推理 · 适用范围：通用智能体系统设计；具体实现以官方文档为准

## 1. 核心定义

**Reasoning and Acting (ReAct)（推理与行动协同）**：Reasoning and Acting（ReAct，推理与行动协同）是将决策/推断与外部工具行动交替运行的方法。Agent 根据当前观察选择工具，工具提供新证据，再据此决定下一步，直至满足终止条件。

**适用边界：**ReAct 概念不要求商业 API 暴露私有的完整内部推理；实际系统可记录简明决策摘要和外部动作轨迹。

## 2. 形象理解

像维修工先推测原因、测量设备、根据仪表结果再选下一项测试。

**类比的局限：**如果测量仪表有误或权限受限，反馈可能误导决策，不能保证诊断正确。

## 3. 技术原理与核心内容

可写为 `goal → choose action → execute → observe → update state → repeat or stop`。原始 ReAct 研究让语言推断和操作交替，并通过外部知识/环境反馈辅助推理。生产运行器负责校验工具参数、处理不可信 observation、最大轮数、超时和高风险审批。

## 4. 工程实践与设计权衡

**工程案例：**网站故障排查 Agent 先看 5xx 指标，再查日志、部署记录和回滚证据；对生产回滚需审批且以服务状态核验成功。不得将日志中的恶意命令当作高优先级系统指令。

**失败模式与验证：**没有新增信息时可能循环检索；工具失败可能被模型解释为“数据不存在”。使用 trace_id 关联每一轮 tool_call、返回状态与最终结论，设定失败预算。

## 5. 关联知识与易混辨析

CoT 不一定触碰外部环境；ReAct 强调观察驱动的行动；Plan-and-Execute 倾向先计划，再执行和必要时重规划。

## 6. 中等难度面试题（含参考答案）

1. **问：ReAct 比纯 CoT 更适合哪些任务？** 答：需要实时业务状态、外部检索或反复调试的任务；通过新观察修正行动，而不是仅在既有上下文里推断。
2. **问：怎样防止网页文字发号施令？** 答：作为低信任工具数据处理，不提升为系统指令；敏感动作的执行层采用权限与审计。

## 7. 中等难度考试题（含解析）

1. **题：查日志 0.5 s，两次模型决策各 0.7 s，第二次查工具 0.8 s，串行总时间？** 解：0.5+2×0.7+0.8=2.7 s，忽略其他排队和网络开销。
2. **题：模型决定查询日志但在结果返回前写出“数据库已损坏”，该结论可靠么？** 解：不可靠；应等待观察结果并从足够证据做出诊断，否则只是假设。
