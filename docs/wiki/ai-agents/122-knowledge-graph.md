# Knowledge Graph (KG)（知识图谱 · KG）

> AI Agents · 专题：检索与知识增强 · 此篇区分通用计算机科学术语与具体 Agent 实现版本

## 1. 核心定义

**Knowledge Graph (KG)（知识图谱）**：Knowledge Graph（KG，知识图谱）是把实体、属性和实体间关系组织为图结构的知识表示，节点通常对应对象或值，边描述具名关系。它能支持结构化关系查询、多跳路径与事实整合，但图中的事实仍需要来源、版本和权限控制。

**适用边界：**KG 不是一个专属 AI Agent 协议，也不要求所有实现采用 RDF。RDF 使用主体—谓词—客体三元组；属性图则常用带标签节点、关系边及属性。两者数据模型与查询语言并不完全相同。

## 2. 形象理解

像城市交通关系地图：地铁站是节点、线路是边，通过路径可找到换乘关系；但地图还需注明更新时间和限行信息。

**类比的局限：**图上有连接不意味着该连接在今天仍有效；‘曾任职’与‘当前任职’不能混成同一种边。

## 3. 技术原理与核心内容

构建可使用 `(subject,predicate,object,source,validity,owner)`；实体解析先解决同名与别名，再将边写入图并建立索引。SPARQL 可对 RDF 图进行模式匹配，例如 `?company :supplies ?part`，多跳可连接多个 triple pattern。结构化查询结果需要与外部原始文档的 provenance 关联，不能仅依据图模型的漂亮可视化断言来源可信。

## 4. 工程实践与设计权衡

**工程案例：**研发 Agent 查询‘哪些微服务调用了包含支付数据的数据库’，按服务→依赖→数据库路径连接并用部署元信息验证版本。应检查图的更新频率，防止旧拓扑导致错误的权限变更建议。

**失败模式与验证：**实体对齐错误造成错误边、时间属性丢失导致历史关系被当当前事实、图权限穿透跨租户实体、知识更新后没有同步。通过实体精度、边真值支持率、路径引用和授权约束测试。

## 5. 关联知识与易混辨析

Knowledge Graph 是结构化知识表示；Vector Database 以相似性为核心；Hybrid RAG 可把图路径与文本块结合；Multi-hop Retrieval 是推理/检索过程，既可用图也可用普通文档。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么给关系边加 source 与 valid_from/valid_to？** 答：否则无法解释关系从哪里来、是否在当前日期适用，也难以处理冲突与审计。
2. **问：RDF 三元组与属性图的差别是什么？** 答：RDF 以具名主体/谓词/客体声明事实；属性图以节点和边承载属性，查询与建模惯例不同，不可直接假定完全兼容。

## 7. 中等难度考试题（含解析）

1. **题：KG 中 A→B、B→C、C→D，A 到 D 的最短有向路径包含多少条边？** 解：3 条边，经过 4 个节点；假设不存在其他更短边。
2. **题：两个不同客户都有名叫‘Alex’的节点，可因名称相同直接合并吗？** 解：不能；必须根据稳定实体 ID、租户授权与支持证据做实体消歧。
