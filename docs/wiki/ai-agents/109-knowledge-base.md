# Knowledge Base (KB)（知识库 · KB）

> AI Agents · 专题：检索与知识增强 · 适用范围：知识管理与检索工程；具体 API 以版本文档为准

## 1. 核心定义

**Knowledge Base (KB)（知识库）**：Knowledge Base（KB，知识库）是组织领域文档、事实、关系或规则以支持检索和复用的信息系统。知识库可以由原始文件、关系数据库、文档检索索引、知识图谱及元数据构成，并不一定等于一个向量数据库。

**适用边界：**内容被纳入知识库不表示已通过专业审校，也不意味着所有用户可见；不同文件版本和访问主体需要明确的来源、时间和权限控制。

## 2. 形象理解

像有完整目录、书架编号和借阅权限的专业图书馆，而不是把各种 PDF 随意丢到一个文件夹里。

**类比的局限：**有馆藏目录不保证书籍是最新版或适用于当前读者，借阅权限也不能靠目录搜索结果绕过。

## 3. 技术原理与核心内容

基本记录 `{doc_id,source_uri,owner,version,effective_from,acl,content_hash,ingestion_status}`，关联检索 chunk、向量索引和关键词索引。更新文档时做版本替换或并存；删除文件需同步其索引与缓存。知识检索前先做 tenant/ACL 过滤，结果保留原始页码与章节，可定位引用。对技术定义可保留原始标准和官方文档，避免未经审核摘要覆盖正文。

## 4. 工程实践与设计权衡

**工程案例：**企业研发 KB 同时索引项目设计文档、API 规范和故障复盘，支持按部门权限、仓库版本和修改时间筛选。员工问最新接口参数，优先返回对应正式版本的 API schema，不直接借用过期会议纪要。

**失败模式与验证：**索引重建遗漏某些文件、已删除文档在向量库仍可检索、跨租户文件泄漏、版本冲突和文档摄取时隐式脚本执行。建立内容哈希对账、来源覆盖率、授权拒绝及更新延迟监控。

## 5. 关联知识与易混辨析

Knowledge Base 是信息组织与管理系统；Vector Database 是可能的索引/检索基础设施；Document Ingestion 是把来源导入 KB 的处理管线；RAG 是消费检索证据的生成应用。

## 6. 中等难度面试题（含参考答案）

1. **问：知识库为什么不能简单等同于向量数据库？** 答：知识库还需要原始资料、版本、文档结构、权限、审计和更新治理；向量数据库主要负责相似性索引与检索。
2. **问：文件已经从主库删除，索引还返回它时应该怎么办？** 答：先通过删除黑名单/ACL 阻断召回，再清理向量及关键词索引并验收全部入口。

## 7. 中等难度考试题（含解析）

1. **题：KB 有 1000 篇文档，其中 100 篇新版本替换旧版本，假设版本替换不并存，最终文档数？** 解：仍是 1000 篇；变更的是版本，而不是额外新增 100 篇。
2. **题：某团队只有 35 份文档权限，检索底层返回了 50 份，其中 20 份无权限，可交给模型多少份？** 解：最多 30 份（50−20），还须做其他适用性过滤；绝不能暴露那 20 份。
