# Data Flow（数据流）

> AI Agents · 专题：工作流与编排模式 · 系统架构与执行依赖；技术语义依具体工具契约验证

## 1. 核心定义

**Data Flow（数据流）**：Data Flow（数据流）是信息如何从生产节点传输到消费节点的依赖关系，描述字段、消息和中间结果在 Agent 工作流中的产生、转换、使用和存储。正确数据流需要类型、来源、版本和权限一致性，而不只是节点间有一条线。

**适用边界：**数据流不必等于执行顺序；多个节点可以消费同一不可变输入并行运行，而一个节点也可能在等待控制门槛后才使用已经准备好的数据。工具文本是低信任数据，不应被当指令。

## 2. 形象理解

像工厂物料输送路线，说明哪个车间的半成品送往哪个车间，箱子还应标规格、批次和检验结果。

**类比的局限：**货物到了正确工位，若标签错或物料过期仍会生产错误产品；接收不代表审核通过。

## 3. 技术原理与核心内容

给每条边规定 typed contract：`(producer,consumer,schema,version,source_id,ACL)`。上游写出不可变结果或带版本的状态更新，下游按明确字段读取、验证单位和业务含义。Fan-out 时复制只读引用，Fan-in 时依据 task_id 去重和汇总；对异步消息使用 correlation_id 与 idempotency。敏感信息应按照下游最小访问权限传播。

## 4. 工程实践与设计权衡

**工程案例：**合同分析 Agent 从 OCR 接收 `amount_cents` 和币种，再向税费计算、风险评估两个分支提供只读数据。若 OCR 只有金额字符串无币种，不能让下游假设人民币并创建付款。

**失败模式与验证：**字段重命名未同步、金额单位不一致、跨租户数据被转发、消息乱序、未校验 JSON 就传递给危险工具。通过 schema compatibility、数据 lineage 与权限路径测试。

## 5. 关联知识与易混辨析

Data Flow 说明值怎样传递；Control Flow 决定节点何时执行；Chaining 是两者组合的一种模式；Directed Acyclic Graph 可同时编码依赖但其边语义需清楚定义。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么数据流边应该声明 schema/version？** 答：使下游能检测字段、类型和语义变化，避免悄然把旧版本结果解释成新业务数据。
2. **问：不同 Worker 的输出怎样安全合并？** 答：用任务 ID、来源版本和授权上下文关联，先做类型校验及去重，缺失/冲突应独立标注。

## 7. 中等难度考试题（含解析）

1. **题：数据单位 A 为 2500 分，B 需要元，按人民币 100 分=1 元，转换后金额？** 解：2500/100=25 元；还应保留币种与精度。
2. **题：三个并行分支共享同一只读输入，是否一定要串行？** 解：不需要，只读且无其他控制依赖时可以并行，但结果汇合须有同步机制。
