# AI Agent（人工智能智能体）

> AI Agents · 专题：基础概念与角色 · 适用范围：通用智能体系统设计；具体 SDK 与平台版本以对应文档为准

## 1. 核心定义

**AI Agent（人工智能智能体）**：智能体是依据目标和观测，在授权边界内选择并执行动作、再用环境反馈调整后续步骤的系统。基于 LLM 的 Agent 通常由模型、工具、指令、状态与执行循环组成。

**适用边界：**仅能生成文字的聊天模型未必构成具有外部行动能力的 Agent；自主并不等于不受约束。

## 2. 形象理解

像有目标、会查资料并能实际办事的助理：接单后查看已有信息，执行步骤，核对结果。

**类比的局限：**助理类比不意味着模型拥有人的意图、法律权限或可靠的自我验证能力。

## 3. 技术原理与核心内容

典型执行链为用户目标 → 读取状态/指令 → 模型选择回答或工具调用 → 工具执行 → 记录 observation → 继续决策或终止。控制器而不是自然语言输出本身负责执行、预算与权限。每轮应检查最大步数、超时、安全策略和成功条件。

## 4. 工程实践与设计权衡

报销核验：只读查订单与规则；发起退款属于有副作用动作，需要金额边界、用户确认和审计记录。测试应覆盖无订单、工具超时、重复调用和权限拒绝，而不只评估答案文笔。

## 5. 关联知识与易混辨析

Agent 与 Workflow：前者的下一步可由模型依据观测动态决定；后者的控制路径可完全预先编排。两者可以组合，不能按是否使用 LLM 简单区分。

## 6. 中等难度面试题（含参考答案）

1. **问：如何判断客服应用是否真正需要 Agent？** 答：列出需要动态决策与外部操作的场景；若只是分类、检索或固定表单流，确定性工作流更可控。用任务成功率、人工接管率、执行成本作对比。
2. **问：工具连续失败时应如何设计？** 答：按可重试性区分超时与业务拒绝，幂等请求有限重试；有副作用动作先查询执行状态，超预算就停止并交接，不让模型无限猜测。

## 7. 中等难度考试题（含解析）

1. **题：某系统最多执行 5 次模型决策，每次模型耗时 0.8 s，最多 3 次工具调用各耗时 0.6 s，忽略网络开销，最坏总时间多少？** 解：5×0.8+3×0.6=5.8 s；这是题设上界，不代表实际时延，工具并行或超时会改变结果。
2. **题：系统只调用模型总结检索结果，和系统动态调用订单查询/退款工具，哪个更符合行动型 Agent？** 解：后者：它依据状态选择并执行有外部效果的动作；前者可只是 RAG 应用。判断依据是控制与行动机制而非产品命名。
