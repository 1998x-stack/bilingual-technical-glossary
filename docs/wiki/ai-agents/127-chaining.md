# Chaining（链式处理）

> AI Agents · 专题：工作流与编排模式 · 区分编排模式、执行权限和模型行为边界

## 1. 核心定义

**Chaining（链式处理）**：Chaining（链式处理）是把多个计算、模型或工具处理阶段按依赖关系连接，使一个阶段的输出成为后续阶段的输入。链中的每一步可以是确定性代码、LLM 调用或工具执行，不必都由模型完成。

**适用边界：**链式处理不保证严格线性，也可能是多分支有向图；若使用严格串行，就需要考虑累计延迟与错误传播。把上游输出作为下游输入时仍须校验类型、来源和权限。

## 2. 形象理解

像翻译出版流水线：先抽取原文、再翻译、再校对、最终排版，后续步骤依赖前面的结果。

**类比的局限：**第一步误读原文时，再精美的排版也无法恢复事实；流程链必须有可校验的中间接口。

## 3. 技术原理与核心内容

定义阶段 `y_i=f_i(y_(i-1), context_i)`，每一层建立输入/输出 schema 与失败状态。对可重试的纯计算阶段可局部重算；有外部副作用的写阶段必须保存操作 ID 和幂等约定。若上游输出与下游约束不匹配，采用结构化错误而非让模型猜测字段；可插入 gate 检查或人工复核。

## 4. 工程实践与设计权衡

**工程案例：**安全公告处理 Agent 先抓取官方 CVE、解析受影响版本、调用资产清单匹配，再创建待审批工单。若版本解析失败，应阻断工单创建而不是把不确定范围当确认漏洞。

**失败模式与验证：**前置错误级联放大、类型不兼容造成静默截断、将工具返回的低信任文本当系统指令、串行链延迟过长。用阶段契约、数据 lineage 和多种失败输入做回归。

## 5. 关联知识与易混辨析

Chaining 是阶段相接的通用组合；Prompt Chaining 特指多次模型提示调用；Sequential Execution 强调时间顺序；Data Flow 表示数据依赖，未必需要相同的顺序控制。

## 6. 中等难度面试题（含参考答案）

1. **问：如何提高多步链式处理的可调试性？** 答：给每阶段独立 schema、trace_id、输入版本和状态，并能定位首次失败的步骤，而不是只看最终输出。
2. **问：链中哪些步骤适合并行，哪些不能？** 答：仅当依赖和副作用不冲突时可并行；下游依赖上游输出的阶段必须等待数据满足前置条件。

## 7. 中等难度考试题（含解析）

1. **题：四步纯串行链耗时 1、2、3、4 秒，总时长？** 解：10 秒，且无法简单按最大耗时计算。
2. **题：第二步输出字段是 price_usd，第三步只接受 price_cny 且无转换，能直接传吗？** 解：不能；需显式汇率来源和单位转换，否则是 schema/语义错配。
