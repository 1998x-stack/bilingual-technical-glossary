# Browser Automation（浏览器自动化）

> AI Agents · 专题：工具使用与环境交互 · 具体工具行为、权限与版本以官方规范为准

## 1. 核心定义

**Browser Automation（浏览器自动化）**：Browser Automation（浏览器自动化）是通过编程驱动真实或无头浏览器，完成导航、DOM 定位、点击、输入、截图、网络等待和网页表单交互的技术。它可用于网站测试和 Agent 操作，但网页并不天然可信。

**适用边界：**网页 UI 会变化、请求异步且会有登录状态/权限限制；浏览器自动化不保证点击后业务事务已提交，敏感操作仍需要用户许可和后端验证。

## 2. 形象理解

像机械手按真实网页界面填写表单，而不是直接向数据库写入记录。

**类比的局限：**机械手可能点错相似按钮；看到‘提交成功’的弹窗也不一定意味着服务器已经持久化数据。

## 3. 技术原理与核心内容

Playwright 等框架通过 locator 查找元素，执行点击前会检查可见、稳定、可交互等条件；推荐基于 role/label/test-id 的语义定位而非脆弱的绝对 XPath。交互流程包含等待导航/响应、截图、结果确认和异常处理。Agent 应隔离浏览器会话和 Cookie，对新站点和高风险动作设置审批。

## 4. 工程实践与设计权衡

**工程案例：**企业内部报销 Agent 自动打开表单、填写金额并在提交前请求用户确认；提交后从权威系统检查报销 ID，而非仅用按钮是否被点击或 DOM 是否出现提示作为完成证据。

**失败模式与验证：**UI 布局变化导致误点、竞态条件导致重复提交、网页中的恶意操作指令让 Agent 偏离任务、Cookie 泄露都会造成问题。使用浏览器级回归测试、重试边界、权限隔离与审计录像或截图。

## 5. 关联知识与易混辨析

Browser Automation 操作浏览器 DOM 和网页交互；Computer Use 更通用地操作图形桌面或应用；API 调用通常更稳定和结构化，但未必覆盖 UI 独有流程。

## 6. 中等难度面试题（含参考答案）

1. **问：为何定位按钮要优先使用语义 locator 而非屏幕绝对坐标？** 答：语义定位对布局变化通常更稳健，可配合唯一性和可操作性检查；坐标容易在分辨率变化后点错。
2. **问：网页显示‘操作成功’就能把数据库任务标为成功吗？** 答：不能完全依赖网页文案，应核对事务 ID 和权威业务状态，尤其有延迟/重复提交风险时。

## 7. 中等难度考试题（含解析）

1. **题：浏览器依序完成 3 次页面操作，各 0.6、0.8、1.1 s，最终业务核验 0.5 s，忽略额外等待，总耗时？** 解：0.6+0.8+1.1+0.5=3.0 s；实际网页异步/网络延迟会增大耗时。
2. **题：按钮点击后页面没有变化，但请求可能已提交。可以重复点击多少次来保证成功？** 解：不能靠重复次数保证。先查权威事务或页面状态，避免无保护的重复写操作。
