# Tool Schema（工具模式）

> AI Agents · 专题：工具使用与环境交互 · 通用工程概念；具体行为以平台、协议与版本为准

## 1. 核心定义

**Tool Schema（工具模式）**：Tool Schema（工具模式）是描述某项工具如何被调用的机器可读契约，包括工具名、功能说明、参数字段、必填规则、类型、枚举及部分平台支持的输出结构。常使用 JSON Schema 或兼容子集。

**适用边界：**schema 检查形式而不提供身份授权；所有平台都支持哪些 JSON Schema 关键词需具体核对。一个合法字符串仍可能指向别人账户或危险路径。

## 2. 形象理解

像设备插头的技术规格：说明电压与引脚，但不代表任何人都被允许通电操作。

**类比的局限：**插头匹配不保证接的设备正确或操作安全，仍需权限和实际环境检查。

## 3. 技术原理与核心内容

典型工具描述包含 name、description、inputSchema。输入可要求 order_id 为 string、currency 属于特定 enum，限制附加字段。模型根据描述提出参数，宿主再通过 schema_validate 和业务校验。修改参数类型或新增必填字段应做版本化或兼容性适配，并建立生产使用者的合约测试。

## 4. 工程实践与设计权衡

**工程案例：**价格查询工具规定 base_currency 与 quote_currency 使用受支持币种，amount 必须是正数。接入系统还需对汇率日期和数据权限做核对；schema 合规不等于当日汇率真实。

**失败模式与验证：**描述模糊造成工具误选，过宽 schema 允许危险内容，版本更新使旧调用突然无法解析。用合法/非法输入、边界值、未知字段、恶意输入与服务端校验回归测试。

## 5. 关联知识与易混辨析

Tool Schema 是静态字段契约；Argument Validation 在一次调用中验证实际输入；Tool Registry 保存多项工具定义，必要时支持版本和能力搜索。

## 6. 中等难度面试题（含参考答案）

1. **问：通过 JSON Schema 后是否可以直接进行付款？** 答：不可以，还需确认用户身份、账户归属、当前余额、授权上限、业务审批与去重。
2. **问：新增必填字段会给老客户端带来什么？** 答：可能导致旧参数无法通过 schema，应做版本兼容、迁移和负向合约测试。

## 7. 中等难度考试题（含解析）

1. **题：amount 类型为整数且 minimum=1，输入 0、5、字符串形式的 5，哪项通过严格校验？** 解：只有整数 5 通过，0 越界，字符串值类型错误。
2. **题：模型给出格式合法但属于其他用户的 order_id，能执行查询吗？** 解：不能。服务端 AuthZ 必须阻断跨主体访问，schema 不验证对象归属。
