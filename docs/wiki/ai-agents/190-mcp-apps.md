# MCP Apps（MCP 应用）

> AI Agents · 专题：MCP：模型上下文协议 · MCP 2026-07-28 及兼容边界；示例数字为教学题设

## 1. 核心定义

**MCP Apps（MCP 应用）**：MCP Apps（MCP 应用）是一种让 MCP Server 通过工具关联的 UI 资源向 Host 提供可交互界面的扩展方案。它使模型的工具结果可以伴随可视组件出现在对话中，而不要求 Host 把第三方 HTML 直接赋予页面全权限。

**适用边界：**MCP Apps 不是 MCP 核心 Tool 的必需行为；需要 Host 支持扩展，Server 声明相应 `ui://` 资源，并在受限环境内渲染。UI 界面展示与真实业务授权、用户同意/交易确认不能画等号。

## 2. 形象理解

像聊天里嵌入一个受保护的小型仪表盘，用户能查看数据并触发受控操作，但它仍受主程序权限约束。

**类比的局限：**界面看起来像官方表单并不能证明它可信，沙箱不能替代对业务接口的身份授权。

## 3. 技术原理与核心内容

工具元数据可声明指向 `ui://` 资源的界面入口，Host 读取 HTML UI 后在 sandboxed iframe 中加载；双向消息通道传输工具结果和经授权的 UI 行为，相关工具调用仍由 Host 中介。UI 应采用 CSP、来源校验、数据最小化与权限门控，禁止通过 iframe 的脚本直接获得全站 cookie 或未授权外部网络。

## 4. 工程实践与设计权衡

**工程案例：**采购 Agent 在对话中展示供应商报价对比表，用户选择方案后 UI 请求 Host 调用受控审批工具。Host 校验用户、订单金额和当前版本；单击图表或 UI 内虚构的‘通过’标签不应直接触发支付。

**失败模式与验证：**第三方 iframe 脚本越界、消息来源校验遗漏、工具输出注入 HTML、用户以为 UI 是官方认证页面、错误缓存敏感数据。用 CSP、postMessage 来源检查、同源隔离与无权限路径测试。

## 5. 关联知识与易混辨析

MCP Apps 提供扩展 UI；MCP Prompt 是可复用文字/消息模板；MCP Resource 可承载 UI HTML，但普通资源并不自动成为 App；Web 前端插件与 MCP Apps 的协议作用范围不同。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 MCP Apps 要借助 sandboxed iframe？** 答：为了限制第三方 UI 脚本的权限和来源影响，降低对 Host 页面和用户数据的攻击面。
2. **问：一个 App 的按钮显示‘付款成功’，可以作为业务记录吗？** 答：不能，必须由受控支付接口返回权威事务状态并做授权审计。

## 7. 中等难度考试题（含解析）

1. **题：3 个可视组件各自每秒刷新 2 次，持续 10 秒，共多少次刷新？** 解：3×2×10=60 次，假设每次都执行。
2. **题：Server 工具可返回 5 个数据字段，但 UI 只需要 2 个，该传多少？** 解：应遵循最小化原则只传必需的 2 个，另行按任务需要控制。
