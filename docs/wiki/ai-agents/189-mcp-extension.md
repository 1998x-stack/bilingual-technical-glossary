# MCP Extension（MCP 扩展）

> AI Agents · 专题：MCP：模型上下文协议 · MCP 2026-07-28 及兼容边界；示例数字为教学题设

## 1. 核心定义

**MCP Extension（MCP 扩展）**：MCP Extension（MCP 扩展）是在核心 JSON-RPC 工具、资源、提示协议之外，提供专用或可选能力的机制，例如任务扩展与 UI 应用。2026-07-28 将扩展治理和能力协商正式纳入协议规范，避免把特定 SDK 实验功能当核心强制接口。

**适用边界：**扩展应双方明确支持并协商启用；旧客户端或服务器没有声明就不能假设可用。某扩展可能有自己的版本和权限要求，扩展名称相同也不意味着所有实现行为相同。

## 2. 形象理解

像电脑操作系统和设备均支持某个插件接口后才能加载插件，插件并不获得所有管理员权限。

**类比的局限：**插件能被加载不代表其实现安全或授权范围合理，仍需独立审核代码与能力边界。

## 3. 技术原理与核心内容

新版每个请求 `_meta` 内含客户端能力声明，服务端在 `server/discover` 回复中声明能力；扩展可基于 capabilities.extensions 做显式协商。Host 按扩展标识与版本选择处理器，不支持时返回可解释错误/降级。Tasks 扩展可用于可查询的长时工作单元，MCP Apps 扩展提供 UI 资源与双向通信；扩展数据应遵循最低权限和完整协议校验。

## 4. 工程实践与设计权衡

**工程案例：**Agent 想使用 Tasks 扩展建立长时间文档转换，如果 Server 未声明该扩展，就改用普通调用和后端 operation_id 跟踪，不应直接发送 `tasks/get`。需要交互式审批 UI 时仅加载已信任的 Apps 资源，隔离 iframe。

**失败模式与验证：**客户端以为支持而调用未声明方法、扩展与核心错误状态混淆、扩展资源跨租户暴露、插件版本不兼容。使用能力矩阵、版本回退、无扩展环境和权限负例测试。

## 5. 关联知识与易混辨析

MCP Extension 扩充协议能力；MCP App 是扩展的一类具体 UI 机制；Tool 是核心能力；MCP Registry/Connector 目录是发现分发机制，不能用来替代协商与授权。

## 6. 中等难度面试题（含参考答案）

1. **问：能否未协商就假定 Server 支持 Tasks？** 答：不能，应根据 capabilities 扩展声明并进行兼容检查。
2. **问：MCP Extension 存在是否自动意味着插件具有本机文件权限？** 答：不意味着，必须由 Host/Server 及运行环境的 ACL 独立授权。

## 7. 中等难度考试题（含解析）

1. **题：客户端支持扩展 X、Y，服务端只支持 Y、Z，共同可用扩展集合？** 解：交集只有 Y。
2. **题：对不支持的扩展强行调用可能出现什么？** 解：应返回不支持能力或方法的明确错误，不能静默执行其他功能。
