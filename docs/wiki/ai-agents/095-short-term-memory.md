# Short-term Memory（短期记忆）

> AI Agents · 专题：上下文、记忆与状态 · 通用会话与记忆工程；具体框架行为以对应文档为准

## 1. 核心定义

**Short-term Memory（短期记忆）**：Short-term Memory（短期记忆）是 Agent 在当前会话、线程或近期任务范围内保留的可复用信息，典型包括最近消息、临时偏好、未完成子任务和工具结果摘要。在许多框架中它通过 thread/session state 与 checkpoint 实现。

**适用边界：**短期不必等于全部原始聊天历史，也不自动保证跨会话持续；是否保留取决于存储、生命周期、过期策略和数据授权。与工作记忆常有重叠，但侧重近期时间/会话范围。

## 2. 形象理解

像会议期间的白板，保存当前讨论的决定和下一步任务；会议结束后白板可能被清理。

**类比的局限：**白板上写过的结论可能需要更新；不同会议室也不能默认共享敏感白板内容。

## 3. 技术原理与核心内容

常见架构是 `thread_id → checkpoint/messages/state`。每轮把当前输入、工具反馈和任务进度写入有版本的会话状态；调用模型时读取近期消息或压缩摘要。对过长历史选择保留最新轮次、关键约束、证据引用，且使用户数据能按策略删除。分布式运行需保证并发写入一致性与同一 thread 隔离。

## 4. 工程实践与设计权衡

**工程案例：**客服 Agent 在当前会话中记住订单号和已问过的两项验证问题，避免重复追问；当用户开启另一个无关联会话时，不能未经授权自动暴露前一会话的敏感订单信息。

**失败模式与验证：**将线程 ID 当鉴权凭证、突然裁剪掉未确认动作、多个并发消息顺序错乱、摘要把用户偏好误写成全局永久事实。使用 TTL、并发冲突和跨会话隔离的回归测试。

## 5. 关联知识与易混辨析

Short-term Memory 通常属于近期会话或线程范围；Long-term Memory 可跨线程复用；Working Memory 是当前步骤所需的活跃集合；Session State 是结构化控制状态。

## 6. 中等难度面试题（含参考答案）

1. **问：LangGraph 中短期记忆与 checkpoint 的联系是什么？** 答：线程级状态可被 checkpointer 保存，后续在同一线程恢复；但仍需按实际实现和授权管理并发、存储与历史压缩。
2. **问：为何同一个 thread_id 不等于用户已授权访问之前全部消息？** 答：线程标识不是身份认证。必须从可信登录身份验证资源归属、访问范围和数据留存策略。

## 7. 中等难度考试题（含解析）

1. **题：一个会话最近 8 轮消息共 3200 token，压缩后 1200 token，减少比例？** 解：(3200−1200)/3200=62.5%；仍需验证关键事实是否保真。
2. **题：一条临时数据按 TTL=30 分钟保存，距最后更新时间 45 分钟且未续期，是否可继续依赖？** 解：不应。按题设已过期，需要重新查询或由有效的持久存储恢复。
