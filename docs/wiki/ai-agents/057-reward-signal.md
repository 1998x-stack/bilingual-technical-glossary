# Reward Signal（奖励信号）

> 适用领域：AI Agents · 专题：任务规划与决策 · 基础概念与具体 SDK 权限实现需分开判断

## 1. 核心定义

**Reward Signal（奖励信号）**：Reward Signal（奖励信号）是在智能体与环境交互时用于评价行为结果的数值反馈。强化学习中常记为 `R_(t+1)`，表示执行 `A_t` 后环境给出的即时奖励；策略学习通常以累计折扣回报而非单步奖励为目标。

**适用边界：**在非 RL 的 LLM Agent 中，业务评分/用户反馈也可能被俗称 reward，但它不一定代表在线强化学习或可证明最优的训练信号。

## 2. 形象理解

像运动员每次训练收到分数，但长期进步不能只追求单次分数最高。

**类比的局限：**如果评分体系设计有漏洞，刷分的行为未必真正解决问题。

## 3. 技术原理与核心内容

常用有限/无限时域折扣回报 `G_t=Σ_(k=0)^∞ γ^k R_(t+k+1)`，其中 γ∈[0,1)；折扣衡量未来奖励权重。Reward 与 Policy/Value 通过学习或规划相关联，但必须防止奖励投机（reward hacking），例如只优化“点击量”损害真实用户体验。

## 4. 工程实践与设计权衡

**工程案例：**工单 Agent 以最终问题解决和用户确认作为主要反馈，而不是以“发送回复次数”计分；监控异常重复调用、取消率和错误关闭工单率。真实奖励设计还要考虑延迟反馈及不可观测性。

**失败模式与验证：**奖励稀疏、反馈延迟、代理指标失真和错误归因可能让策略走捷径。使用结果审计、对抗样本和多指标验收降低投机；避免把奖励模型分数当事实。

## 5. 关联知识与易混辨析

Reward Signal 是一步或一段行动后得到的学习/评价反馈；Utility Function 是结果偏好映射；Goal 是用户真正要达到的可验证业务结果。

## 6. 中等难度面试题（含参考答案）

1. **问：为何把“客服回复越快奖励越高”可能产生有害策略？** 答：Agent 可能跳过核实而快速关闭工单，优化可计量代理指标却牺牲真实解决率；应加入质量和实际完成的约束。
2. **问：RL 奖励与业务成功判据需要怎么关联？** 答：明确奖励如何支持终极目标，同时对越权、错误处理设强制安全门控与结果验证，不把奖励分数视为授权。

## 7. 中等难度考试题（含解析）

1. **题：连续两步奖励分别 4 和 10，折扣 γ=0.5，题设仅两步，起点回报是多少？** 解：`G=4+0.5×10=9`。若采用无限时域还须考虑后续奖励，本题假设后续为 0。
2. **题：Agent 可以发送 10 条无用回复各获 +1 奖励，却未解决问题。什么设计缺陷？** 解：奖励与实际成功目标错位，产生 reward hacking；应加入验证后的最终解决指标并防止重复刷分。
