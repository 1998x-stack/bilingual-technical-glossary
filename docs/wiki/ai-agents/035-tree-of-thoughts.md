# Tree of Thoughts (ToT)（思维树 · ToT）

> AI Agents · 专题：模型能力与推理 · 适用范围：通用智能体系统设计；具体实现以官方文档为准

## 1. 核心定义

**Tree of Thoughts (ToT)（思维树）**：Tree of Thoughts（ToT，思维树）把中间思路作为可扩展节点，利用生成、评估、剪枝及回溯来探索多条候选求解路径；它是推理时搜索策略，不是模型的参数拓扑结构。

**适用边界：**每个分支的“好坏”由评估器估计，可能有误；额外搜索成本与模型调用次数需要预算限制。

## 2. 形象理解

像解迷宫时在每个路口记录几个候选方向，死路则退回尝试其他路线。

**类比的局限：**错误的地图或估价会使搜索早早丢弃真正的可行路径。

## 3. 技术原理与核心内容

把状态 s 定义为已选择的思路前缀，扩展函数 G(s) 给出 b 个后继，评价 V(s') 为候选打分。可按 BFS、DFS 或 beam search 限制层宽 k；无剪枝、分支数 b、深度 d 的节点数为 `1+b+...+b^d`。硬约束由确定性规则判定，语言评估只负责柔性排序。

## 4. 工程实践与设计权衡

**工程案例：**自动排班 Agent 用搜索提出候选班表，先校验劳动时间/冲突规则，剪除非法节点，再按成本和人员偏好排序；只有达成全部约束才输出排班结果。

**失败模式与验证：**搜索会放大延迟与 token 消耗；若评估器和生成器共享偏误，剪枝可能反而降低成功率。以固定节点/调用预算和相同测试集比较 CoT、ToT 与约束规划算法。

## 5. 关联知识与易混辨析

CoT 是单条路径；ToT 明确搜索、回溯不同中间状态；Self-Consistency 多为独立完整样本投票。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 ToT 不一定优于 CoT？** 答：问题简单或已有高效确定性算法时，树搜索的分支和评价开销可能超过收益；应用难度筛选与预算上限。
2. **问：如何降低错误剪枝？** 答：使用独立可验证的硬约束和可追溯评分、保留部分多样化候选，必要时回溯，避免全靠模型自评。

## 7. 中等难度考试题（含解析）

1. **题：b=3、d=3、根深度 0，不剪枝共多少节点？** 解：1+3+9+27=40；只有叶节点为 27，不能混淆。
2. **题：第一层 3 个候选仅保留 2 个，下一层每个扩展 3 个，下一层新节点数？** 解：2×3=6 个；可再次剪枝。
