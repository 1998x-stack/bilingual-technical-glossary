# Evaluator–Optimizer（评估者—优化者模式）

> AI Agents · 专题：工作流与编排模式 · 应用架构、状态恢复与工程权衡

## 1. 核心定义

**Evaluator–Optimizer（评估者—优化者模式）**：Evaluator–Optimizer（评估者—优化者模式）是一个模型或算法先产生候选结果，另一个评估器依据明确标准给出质量反馈，优化器据此迭代修订，直至通过验收或触发停止条件的工作流模式。它擅长可指出具体改进方向的生成任务。

**适用边界：**评估器不必是 LLM，代码测试或人工评审常更可靠。缺乏客观标准时，两个模型可能共享偏见并进入无限‘自我满意’循环；必须限制迭代与成本。

## 2. 形象理解

像作者写文章、编辑指出事实和结构问题、作者修订，直到达到可检查的出版标准。

**类比的局限：**编辑也会犯错，反复改稿不代表证据更真实；必须有外部事实核验和停止规则。

## 3. 技术原理与核心内容

令候选 y_k、评估反馈 e_k=E(y_k,criteria)，修订 y_(k+1)=O(y_k,e_k)。迭代时记录 rubric、客观检查结果和变更 diff，满足 `pass(e_k)` 时退出；若连续无提升、超出 max_rounds 或费用上限，则输出未通过状态。将安全策略和高风险写操作由确定性执行器强制控制，不能把自我评估当授权。

## 4. 工程实践与设计权衡

**工程案例：**营销合规文案 Agent 生成广告，评估器对禁用词、事实来源与字数分别给出结构化反馈，优化器修订后复查；若引用没有官方依据，即使审美评分很高也不能自动发布。

**失败模式与验证：**评估器幻觉、评价标准变化、过拟合 LLM 打分、循环不终止、越优化越远离用户约束。评估可用真实标注集/独立规则比较多轮准确率、延迟和事实支持率。

## 5. 关联知识与易混辨析

Evaluator–Optimizer 是生成-评估-反馈循环；Prompt Chaining 是相互依赖的多次调用，不一定包含优化闭环；Reflection 偏重自我分析，可能作为反馈输入但不替代外部评估。

## 6. 中等难度面试题（含参考答案）

1. **问：什么条件下该模式比单次生成更值得采用？** 答：有清晰可操作的评价标准，反馈可改善下一轮且预计收益超过额外 token/延迟成本。
2. **问：为什么不能用同一个模型的高分自评证明合同合法？** 答：模型可能与生成器共享错误；法律合规需适用条款、版本与权威证据，必要时由专业人员审查。

## 7. 中等难度考试题（含解析）

1. **题：最多允许 4 轮优化，每轮生成 0.8s、评估 0.4s，四轮均执行的总模型调用耗时？** 解：4×(0.8+0.4)=4.8 秒，不含检索开销。
2. **题：评分依次 70、76、75、77，是否单调改善？** 解：否，第 3 轮下降 1 分；应根据 rubric 和业务门槛，而不是仅以最后分数最高判定成功。
