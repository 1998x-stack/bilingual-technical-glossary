# Span（跨度）

> AI Agents · 专题：工程化、成本与可观测性 · OpenTelemetry / W3C 追踪语义

## 1. 核心定义

**Span（跨度）**：一个有起止时间、Span Context、名称、状态、Attributes、Events 等字段的操作记录，是 Trace 的常用基本单元。它可以代表一次 LLM 生成、向量检索或工具调用，但不能等同于真实业务数据库事务。

**适用范围和定义边界：**此词条属于服务可观测性与执行诊断概念，具体 SDK 的字段名、采样策略和导出格式可能因实现和版本而异；不得把某个厂商的扩展属性说成通用标准。还应区分观测数据、推测的根因与经权威业务系统确认的结果：一条追踪只能表明被记录的操作，不保证所有操作都被完整采集。

## 2. 形象理解

**类比：**工厂工序卡记录某道工序的开始时间、完成时间、工作状态和备注。

**类比的局限：**真实的并行、异步恢复、丢包和采样会使追踪结构比类比复杂。一个操作的记录不等于实际事务已经持久化，系统也可能因为记录不完整而漏掉部分路径。理解概念时应回到原始上下文、时间戳、因果关系和业务后置状态。

## 3. 技术原理与核心内容

Span 包括 trace_id、独立 span_id、可选 parent ID；属性描述维度，Events 表示某个瞬时点，Status 表示观测的操作状态。持续执行建 Span，按钮确认、重试发生时点可以记录 Event。

**观测模型与指标语义。**用 task ID、trace_id 与 span_id 连接执行上下文，区分模型提供的建议、工具返回的状态与业务系统实际提交。日志解释离散事件，指标聚合请求量、延迟分位数、错误和费用，Trace/Span 重建单次任务路径。三者相互补充，不能用某个 HTTP 成功值代替业务成功。多个分支可以并行、异步恢复并发生重试，因而单纯累计 Span 时长不等于端到端时延，必须通过真实时间线或关键路径判断。

**数据路径：**请求进入 Agent Runtime 后，应产生可关联的任务标识；模型生成、检索、工具适配器和下游 API 分别记录相应操作。跨网络边界时需要显式或自动传播上下文，对异步扇出/扇入按真实关系建立 links；针对失败/重试要区分每一次 attempt 与逻辑操作的结果。

## 4. 工程实践与设计权衡

**工程案例：**Agent 工具调用 Span 保存工具类别、时延、状态码与安全脱敏后的重试次数；不记录原始 token 或敏感输入。多次 retry 可以作为一个父操作下的 attempt 子 Span。

**工程验证与取舍。**在可控环境注入 429、超时、下游服务慢请求、工具重试、队列恢复、丢失追踪上下文和业务已成功但客户端报错等案例。首先确认能否从一个 task ID 查到所有必要操作，其次核查实际业务后置状态，然后检查抽样及分位数是否会遗漏少量严重故障。Trace 可能丢包或采样，不能代替审计账本。保护 API Key 和个人信息，禁止把完整 prompt/凭据放入 Span 属性或跨域 baggage；同时控制高基数维度、日志留存与存储费用。

**失败模式：**跨度没有结束时间、错误建立 parent 关系、把外部 header 当认证材料、日志泄漏秘密、样本覆盖不足、高基数指标维度过多，均会损害结果可靠性。应根据排障价值选择适当抽样策略、结构化字段和成本预算，而不是无上限保存所有原始模型对话。

## 5. 关联知识与易混辨析

Trace 是所有关联操作的集合；Span 是单个区间；Span Event 是区间中的时间点而非必然单独的持续过程。

关键辨析点是：这是“执行行为”“观测动作”还是“存储的轨迹实体”？它与 Monitoring、Logging、Metrics、Correlation ID 和业务 Audit Trail 的职责均不同。若追踪缺失，不可直接据此断言某个工具从未执行；应先核对服务端日志及权威业务记录。

## 6. 中等难度面试题（含参考答案）

1. **问：重试应记录在同一个 Span 中还是拆成多个？** 答：可用总操作 Span 加每次 attempt 子 Span，既能分析总耗时，也能看各次失败和退避。
2. **问：Span 的 Status=OK 能否证明付款已入账？** 答：不能，可能仅表示客户端 HTTP 调用结束，真实业务状态需向付款系统核实。

**面试考查重点：**说明具体 Span/Trace 关系、指标分母、网络传播与隐私风险，能在并发、重试、异步和失败状态中确定真正的端到端问题，而不只背诵术语。

## 7. 中等难度考试题（含解析）

1. **题：Span 从 14:00:00.100 到 14:00:00.450，耗时多少毫秒？** 解：450−100=350ms，题设均在同一秒。 必须说明单位、采样假设和是否为墙钟延迟；所有数值是教学题设，非实际部署实测。
2. **题：用户瞬时点击和模型持续推理分别适合什么观测表示？** 解：点击适合 Span Event，模型推理适合有起止时间的 Span，并与任务 Trace 关联。 评分点是因果结构、时间语义和跨服务边界的正确建模，同时说明如何通过真实系统状态验证。
