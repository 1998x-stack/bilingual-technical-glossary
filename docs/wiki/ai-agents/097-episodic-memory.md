# Episodic Memory（情景记忆）

> AI Agents · 专题：上下文、记忆与状态 · 概念与实际框架行为以来源和版本为准

## 1. 核心定义

**Episodic Memory（情景记忆）**：Episodic Memory（情景记忆）是记录具体经历、任务事件、先前行动、环境观察及其实际结果的记忆类型。它帮助 Agent 借鉴曾经完成或失败的任务，但不构成将历史策略原样套到新环境的许可。

**适用边界：**情景记忆重点在事件背景和后果，而非无时效的抽象事实；成功标记必须由外部验收而不是模型文字证明。具体实现可为事件日志、trace 或案例摘要。

## 2. 形象理解

像运维工程师记得上次凌晨网络故障的症状、排查路线、变更和最终修复证据。

**类比的局限：**今日故障可能只与上次表面相似，历史原因不能直接当成当前根因。

## 3. 技术原理与核心内容

事件记录可组织为 episode_id、task、environment_version、actions、observations、outcome、source、timestamp 和 lesson。由真实工具 trace 与测试结果提炼，再按相似任务、环境版本和可信度检索。Reflexion 等研究会使用语言反馈指导下一次尝试，但这种记忆通常不更新基础模型权重。

## 4. 工程实践与设计权衡

**工程案例：**软件 Agent 保存一次依赖升级失败的版本组合、报错和补丁；未来遇到同类编译错误时可先检索此案例，再检查当前版本和跑独立回归测试，而非盲贴旧代码。

**失败模式与验证：**把未经测试的‘已修复’总结存为成功案例、情境不匹配、日志包含密钥或个人信息，都会扩大风险。需去敏、保留原始证据引用、标明版本和过期条件。

## 5. 关联知识与易混辨析

Episodic Memory 保存特定事件；Semantic Memory 保存抽象知识与事实；Procedural Memory 保存策略与操作方法。事件可转化为知识或流程，但必须额外验证。

## 6. 中等难度面试题（含参考答案）

1. **问：情景记忆与原始 Conversation History 有什么区别？** 答：对话历史按时间记录消息；情景记忆聚焦事件目标、动作、环境、反馈和可验收结果，可含结构化 trace 与经验标签。
2. **问：为什么过去一次修复成功不能证明当前同样步骤正确？** 答：工具版本、业务权限、输入与环境可能不同；必须对当前前置条件与测试结果再验证。

## 7. 中等难度考试题（含解析）

1. **题：系统检索 8 条历史案例，其中 6 条与当前故障相关，precision@8？** 解：6/8=75%，不能由此计算 recall，因为没有全部相关案例的数量。
2. **题：模型称修复成功但单测失败，可否存为成功情景？** 解：不可，实际结果是失败；应记录错误观察与未达到的验收条件。
