# Action Space（行动空间）

> 适用领域：AI Agents · 专题：任务规划与决策 · 基础概念与具体 SDK 权限实现需分开判断

## 1. 核心定义

**Action Space（行动空间）**：Action Space（行动空间）是智能体在某种抽象层次上能够选择的全部动作集合，实际在状态 s 中可执行的合法动作通常是其子集 `A(s)`。Agent 的动作可能是自然语言回应、调用工具或向另一智能体委派任务。

**适用边界：**理论动作空间可能是离散、连续或参数化的；实际工具权限、参数 schema 和环境状态会缩小可执行范围。

## 2. 形象理解

像驾驶车辆有转向、刹车、加速等动作，但红灯时不能合法选择前进。

**类比的局限：**动作种类多不等于决策好，也不意味着交通信号可被忽略。

## 3. 技术原理与核心内容

在 MDP 中策略可写 `π(a|s)`，其中 a∈A(s)。工具型 Agent 的动作还可能含参数，如 `send_email(recipient,text)`；如果参数域巨大，直接枚举不可行，应先选工具再做参数约束校验。Execution mask 排除无权限或前置条件不满足的候选；模型生成的自然语言不能绕过 mask。

## 4. 工程实践与设计权衡

**工程案例：**运维 Agent 注册 `get_metrics`、`tail_logs`、`restart_service` 三类工具，但在只读会话中 `A(s)` 只能含前两类；生产重启需要单独审批与角色身份。

**失败模式与验证：**将所有工具都暴露给模型会扩大攻击面、增加无效选择并可能造成错误写操作。评估工具选择准确率和“禁止动作被强制阻断”的覆盖，而非只统计模型是否能列出动作名称。

## 5. 关联知识与易混辨析

Action Space 是候选操作集合；State Space 是可能的环境状态集合；Policy 是从状态/观察到合法动作的决策规则。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么复杂参数化工具不能当成有限几个菜单动作？** 答：一个工具参数可以组合出大量目标和影响范围，需要类型/范围/权限校验及分层动作生成，不能只核对函数名。
2. **问：最小权限怎样改变 Agent 的行动空间？** 答：根据身份与任务状态动态过滤可执行动作，而不只在提示词写“不要调用危险工具”；授权失败产生可追踪拒绝状态。

## 7. 中等难度考试题（含解析）

1. **题：原有 6 个离散动作，其中两个因权限被禁用，另一个前置条件未满足，当前合法动作数？** 解：假设三类禁止互不重叠，合法动作数 6−2−1=3；如果有重叠需按集合去重。
2. **题：4 个动作中有 1 个写操作需审批、目前未审批。策略给该动作最高概率，可以执行吗？** 解：不可以，先应用合法动作过滤；策略只能在合法集合中选取或转为审批流程。
