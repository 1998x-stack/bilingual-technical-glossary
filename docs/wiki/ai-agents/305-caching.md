# Caching（缓存）

> AI Agents · 专题：工程化、成本与可观测性 · 模型用量、成本预算与缓存治理

## 1. 核心定义

**Caching（缓存）**：把先前计算或检索结果暂存在更快位置以复用，从而降低 Agent 的延迟、工具调用量与费用。缓存的有效性依赖键、租户/权限边界、时效、版本、失效策略和可接受的一致性。

**定义边界：**有关 token、价格、配额和缓存的产品语义可能依模型与服务版本变化。本文只定义可以迁移的工程方法；练习数字均假设给定，不能误称任何供应商当前实际价格或基准数据。成本不是唯一目标，正确的任务结果、隐私和安全权限应具有清晰的最低门槛。

## 2. 形象理解

**类比：**像在工作台备一份常用工具清单，取用更快但过期时需换新。

**类比的局限：**缓存不能被当成最新事实，也不自动继承新权限；过期合同或付款状态尤其危险。 实际 Agent 有多种费用、资源状态和分布式后置结果，因此不能从类比推导精确计费或可靠性保证。

## 3. 技术原理与核心内容

Cache-aside 模式先按键查缓存，miss 后查权威源并回填；键应含 tenant_id、授权范围、模型/Prompt 版本、规范化输入及必要数据版本。TTL 和显式失效控制陈旧性；并发过期可能产生 cache stampede，需要 single-flight/锁或预热。对不可逆副作用绝不能复用旧“执行成功”当本次授权。

**成本模型与治理边界。**一个 Agent 任务会跨多次模型调用、检索、数据库、工具、人工审批和失败重试；应依调用 ID 归集用量，再按相应计价规则计算，不凭空使用特定厂商报价。要区分当前已结算与在途预留，模型回答成功不等于业务完成。缓存值、外部工具结果和旧记忆属于数据来源，不得因低成本或高相似度而突破现有授权与业务实时状态。

**执行闭环。**入口分配 task_id 和共享额度，执行器在每个子任务前检查预估资源需求，随后记录实际 usage 与工具费用；必要时主动拒绝或降级。所有业务写入仍要使用真实权限和幂等键，不能因为缓存或便宜模型的建议就直接行动。

## 4. 工程实践与设计权衡

**工程案例：**企业知识 Agent 缓存公开手册检索可以显著减轻负担，但不能复用其他租户的私有文档或缓存上周的账户余额作为当前付款依据。

**验证程序。**用固定任务集同时统计输入/输出用量、模型/工具调用数、重试次数、实际成功数、端到端 P95、成本与安全拦截；计算两组候选方案的成功摊销成本并标记计费口径。注入并发、超时、缓存过期、权限变更和费用报告滞后等边界用例，不使用真实客户数据。把质量阈值和安全边界作为必须满足的约束，不应以平均费用下降证明总体方案更优。

**失败与取舍：**便宜模型可能增加修复重试次数；高命中缓存若权限键错误会泄露数据；账单告警并不必然是执行层硬上限。预算控制应对不确定价格做保守预留，对失败任务记录消耗，在权限或关键事实变更时使旧结果失效。

## 5. 关联知识与易混辨析

Caching 复用已有结果；Memory 通常长期存储跨任务知识或状态，生命周期语义不同。Prompt Cache 也不等于业务结果缓存；Rate Limiting 仍需要保护峰值。

应把调用级 token、任务级费用、预算策略、缓存有效性和业务完成率作为不同量分别建模。进行选型或成本报告时注明单位、统计期间、纳入的工具费用和失败样本，否则“每次调用价格下降”可能掩盖真正的任务总成本上升。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么缓存键必须包含权限上下文或租户？** 答：避免跨用户/租户拿到不应读的数据；权限变动时必须使旧缓存失效或重新授权。
2. **问：怎样处理热门检索键在 TTL 到期瞬间触发大量并发 miss？** 答：用单航班请求合并、随机 TTL 抖动、预刷新或限并发，避免 stampede 冲垮后端。

回答应覆盖数据来源、并发资源控制、计量精度以及业务边界，说明如何用受控任务评测验证所提出的优化。

## 7. 中等难度考试题（含解析）

1. **题：1,000 次读取中 850 次 cache hit，命中率和 miss 次数？** 解：命中率 850/1000=85%，miss=150 次。 明确分母、币种或 token 数、所含费用范围，并验证数值合理性。
2. **题：命中耗时 10ms、miss 耗时 210ms，命中率 80%，平均耗时（忽略额外开销）？** 解：平均=0.8×10+0.2×210=50ms；还应实测 P95 与陈旧性。 要解释正确原因和常见误用，不能把成本优化与忽略业务授权混同。
