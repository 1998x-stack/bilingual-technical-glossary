# Feature Hashing（特征哈希）

> 领域：机器学习 · 专题：数据预处理与特征工程 · 数理原理、适用条件与生产风险

## 1. 核心定义

特征哈希使用确定性哈希函数将高基数离散特征映射到固定维数的桶，而无须在训练中存储完整的类别到列索引字典。它有利于海量类别和流式处理，但不同特征可能碰撞，且难以直接解释反向映射。

## 2. 形象理解

把很多商品代码按规则分配到固定数量的储物柜，柜子数量不变，但不同商品可能共用一个柜子。

**类比的局限：**碰撞会混淆信息；固定维数不是无损压缩，hash 不会自动保持所有语义相似度。

## 3. 技术原理与核心内容

特征索引 j=h(token) mod d，计数或取值累加到第 j 桶；部分实现使用额外符号哈希减少偏差。HashingVectorizer 不需要 fit 词表，适于在线文档流，但不可对随机 Python hash 的盐及版本作未经固定的依赖。桶数 d 越小碰撞概率越高，需控制编码和分词预处理一致性。

## 4. 工程实践与设计权衡

广告 ID、设备 ID 等百万级稀疏特征采用 2^k 桶进行特征哈希，避免词表更新造成线上列错位；应以验证集比较不同桶数下的性能、碰撞率和内存。

## 5. 关联知识与易混辨析

FeatureHashing 固定维、无词表、不可逆；OneHotEncoder 保留明确类别列并可解释但词表维度增长；TargetEncoder 利用标签统计，具有独立泄漏风险。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么不建议只依赖哈希桶索引解释某个重要特征？** 答：一个桶可能由多个原特征共享，权重不再唯一对应一个类别；需要额外采样追踪或词表/日志才能解释。

2. **问：桶数从 2^10 提到 2^18 有何权衡？** 答：更大桶数通常减少碰撞但增大稀疏特征空间与模型参数成本；不保证每个任务一定改善指标。

## 7. 中等难度考试题（含解析）

1. **题：哈希桶数 d=8，两 token 哈希整数分别 13 与 21，映到哪些桶？** 解：13 mod 8=5，21 mod 8=5，同桶碰撞。

2. **题：固定桶数 1024，若 dense float32 每个样本存全部桶值，不计开销占多少字节？** 解：1024×4=4096 字节，约 4 KiB；稀疏实现可避免存储大量零。
