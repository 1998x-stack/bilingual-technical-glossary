# Mixed Precision Training（混合精度训练）

> 学科：AI Infrastructure · 专题：分布式训练 · 相关框架实现请核对所引用版本

## 1. 核心定义

混合精度训练（Mixed Precision Training）为不同算子选择不同的浮点格式，如 FP32、FP16、BF16，在保持可接受数值稳定性的同时利用低精度 Tensor Core 等硬件吞吐与显存优势。它并非把整个模型、所有梯度和优化器状态一律转换为 FP16。

## 2. 形象理解

做大规模搬运时用轻量箱子运输（低精度），做最终结算时仍使用精确账簿（较高精度）。如果结算的数据本身已经因精度不足被截断，再大的账簿也无法找回全部信息；低精度带来的误差仍须监测。

## 3. 技术原理与核心内容

自动混合精度通过 `autocast` 为适合的运算挑选 dtype，典型矩阵乘法使用 BF16/FP16，而某些归约、规范化或优化器累积可保留 FP32。BF16 的指数范围接近 FP32 但尾数位较少；FP16 精度有效位较多而动态范围更窄，因此 FP16 训练时常配合 **loss scaling** 减少小梯度下溢。梯度以何精度存储、Adam 状态是否 FP32、master weights 是否存在均依框架和配置而定。算术吞吐的理论优势不等于完整 step 的加速。

## 4. 工程实践与设计权衡

优先确认 GPU/加速器支持的 BF16/FP16 kernel、矩阵形状与硬件代际。在 PyTorch 训练时可围绕前向和损失计算使用 `autocast`，由支持的 dtype 决定是否使用 `GradScaler`；不要在没有梯度诊断的情况下把所有层强制 `.half()`。记录 loss 是否溢出、scale 动态变化、optimizer skipped step、全局梯度 norm、困惑度/准确率与 step 时间，尤其关注 softmax、归一化和小幅度梯度。

## 5. 易混概念与边界

**量化**往往指更低位宽的权重/激活表示（如 INT8/INT4）并可能有额外 scale/zero point；混合精度浮点训练不是简单的训练后量化。**BF16** 不等同于更精确的 FP16：指数更宽但有效尾数位更少。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么 BF16 在训练中常比 FP16 更少需要 loss scaling？** 答：BF16 保留与 FP32 同数量级的指数位，能表示更广的梯度数量级；FP16 容易在非常小梯度附近下溢。仍应看具体算子、累加精度与模型数值，不能声称 BF16 训练一定稳定。

2. **问：混合精度训练的验证指标该怎么选择？** 答：除了 TFLOPS，比较吞吐、端到端 step、峰值显存、梯度溢出/下溢、收敛与最终验证集指标；对特定算子做 FP32 基线和误差边界测试。

## 7. 中等难度考试题（含解析）

1. **题：一个 100M 元素激活，忽略额外对齐，FP32 与 BF16 分别占多少十进制 MB？** 解：FP32 `100,000,000×4=400,000,000 B=**400 MB**`；BF16 `×2=**200 MB**`。这是单个 tensor，不代表训练显存必减半。

2. **题：设模型一层的 FP32 乘加输出为 1.25，BF16 模型输出为 1.23，按 FP32 为参考，绝对与相对误差是多少？** 解：绝对误差 `|1.25−1.23|=**0.02**`；相对误差 `0.02/1.25=**1.6%**`。仅为单值误差演算，不能以此判定训练是否收敛。
