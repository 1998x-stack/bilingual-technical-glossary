# Register File（寄存器文件）

> AI Infra Wiki · Batch 01 · 术语 012/142 · 来源：[AI Infra 原始术语](../../data/ai-infrastructure.tsv)

## 1. 核心定义

**Register File**（**寄存器文件**）：处理器中用于存储高速临时变量的寄存器集合。

**适用边界：** 寄存器是 SM 内的高速存储资源，编译器为线程私有值分配寄存器。解释该术语时应指明具体架构、设备代际或测量口径，不能将理论指标直接等同工程表现。

## 2. 形象理解

寄存器像每名工人手边的小工具格，存取快却非常有限；工具拿得太多，会挤占同一车间能同时工作的人员数量。

## 3. 技术原理与核心内容

寄存器是 SM 内的高速存储资源，编译器为线程私有值分配寄存器。每线程需求乘以驻留线程数并考虑硬件分配粒度，会影响 occupancy；超出可用寄存器预算时可能溢出到更慢的 local memory。

## 4. 工程实践与设计权衡

使用编译器寄存器统计和 profiler 识别寄存器压力；避免盲目设置过小 `maxrregcount` 导致 spill。变量写成局部不保证它驻留寄存器，最终以编译结果为准。

## 5. 易混概念与边界

寄存器与 shared memory 都是片上资源，但前者主要是线程私有、由编译器管理，后者供 block 内协作访问。

## 6. 中等难度面试题（含参考答案）

1. **问：为什么减少寄存器使用可能反而变慢？** 答：强制限额可能使活跃数据溢出到 local memory，额外访存超过 occupancy 改善收益。
2. **问：如何区分寄存器瓶颈与内存带宽瓶颈？** 答：结合寄存器/溢出统计、占用率及实测带宽，观察调参前后的真实 kernel 时间。

## 7. 中等难度考试题（含解析）

1. **题：每 SM 有 65,536 个寄存器，每线程用 32 个，忽略其他限制，理论最多支持多少线程？** 解：65,536/32=2,048 线程。
2. **题：若改为每线程 64 个寄存器，上述理论数如何变化？** 解：降至 1,024；实际驻留还受其它资源和分配粒度限制。
