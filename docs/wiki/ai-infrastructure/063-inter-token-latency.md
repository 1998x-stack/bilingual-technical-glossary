# Inter-Token Latency（词元间延迟 · ITL）

> 学科：AI Infrastructure · 专题：推理与服务 · 所有性能指标必须注明计量口径与软件版本

## 1. 核心定义

词元间延迟（ITL）是连续流式输出事件之间的墙钟间隔，用于描述生成过程是否流畅与尾部卡顿。vLLM 的 benchmark 统计相邻**输出事件**，而非保证每事件恰好只有一个 token；使用推测解码或输出缓冲时，须注明 chunk 粒度。

## 2. 形象理解

像字幕每次出现字符间的停顿，平均每 20 ms 更新却偶尔停顿 300 ms，用户仍会觉得卡顿。因此 ITL 的高分位比仅有均值更能反映交互流畅性。

## 3. 技术原理与核心内容

给定流式输出事件到达时间 `t1...tm`，可产生 `m−1` 个差值 `ITL_i=t_(i+1)−t_i`。在一个事件只包含一个 token 的前提下，同一请求的 ITL 算术均值等于 TPOT；一旦打包输出或跨请求加权聚合，二者通常不同。第一个事件前的延迟属于 TTFT，不能算作 ITL。

## 4. 工程实践与设计权衡

生产监测按模型版本、请求长度、GPU 负载、并发级别追踪 ITL P50/P99 和最大间隔。将突刺与 KV swap/preemption、长 prefill 插队、网络 SSE flush、GPU 时序相对齐；单个长尾事件不一定证明 GPU decode 核异常。

## 5. 易混概念与边界

与 TPOT（每请求平均）不同，ITL 是相邻事件的**观测序列**；对于不流式返回、只有一个事件的请求，ITL 缺少样本。不能将未定义值记为零并纳入平均。

## 6. 中等难度面试题（含参考答案）

1. **问：ITL P99 高而 aggregate TPS 仍高，先怀疑什么？** 答：少量请求长时间被调度抢占或网络流式缓冲，大多数请求仍输出很多 token；应按 request ID 比对调度时间线和 SSE 事件。

2. **问：每事件包含 4 个 tokens 时能把事件间隔直接除以 4 当成真实 ITL 吗？** 答：不能简单等价。一次验证/缓冲可能导致多 token 同时输出；需定义是输出事件间隔，还是 token 平均有效耗时。

## 7. 中等难度考试题（含解析）

1. **题：事件发生于 50、72、110、125 ms，求 ITL 样本和均值。** 解：差值 **22、38、15 ms**，平均 `(22+38+15)/3=**25 ms**`，首事件的 50 ms 不计。

2. **题：一个请求只有一个流式事件，能求出多少 ITL 样本？** 解：`m−1=0`，没有可观测相邻间隔；ITL 应为**无样本/未定义**，不是零。
